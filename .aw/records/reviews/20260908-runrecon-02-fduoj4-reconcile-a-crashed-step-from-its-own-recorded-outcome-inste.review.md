THE ONE FINDING THAT WOULD HAVE BROKEN THE BUILD IS PR-701, and it is worth stating plainly because it

PRECEDENCE, DO NOT WRITE A SECOND ONE", naming the four precedence rules accurately. But the function's
FINAL line is `return ("partial" if exit_code == 0 else "failed-safely"), outcome`, so calling it from the
interrupted path returns `partial` or `failed-safely` in exactly the four cases E-05 requires to keep
returning `interrupted`. An executor following E-02 literally would have watched E-05 fail and had two
choices: relax E-05, shipping a regression that flips crashed steps to `failed-safely`, or discover the
contradiction mid-execution. Two further blockers sit behind it: the function REQUIRES an `exit_code` that
a crashed process never produced, and its review and orchestrate branches never read the outcome file at
all. E-02 is rewritten to extract the four-line precedence core as a helper returning a value or `None`,
which preserves the one-definition goal the original instruction was protecting while being safe on both
callers, and this also RESOLVES OQ-02 from measurement instead of leaving it to the executor.
