WHAT THIS ROUND CHANGED ABOUT THE PLAN'S SHAPE. Nothing about the move strategy, and one thing about
where the move's PROOF lives. PR-501 is the substance: this plan correctly identified that a guard is
what protects the move, then named the guard whose assertion does not protect it, and the codebase had
already written a comment explaining why that guard cannot host a re-homed name. Getting this wrong
would have produced the most deceptive possible outcome, a plan that passes its own validation with
every moved name guarded only against a divergence it cannot detect. The second theme is that three
questions this plan left open were already answered next door: child 01's review measured the
pass-through count to zero and settled the `_read_*` destination, and following that settled answer
would have walked the executor out of this plan's fence, which is the one consequence neither plan had
drawn. The rest is measurement hygiene of the kind now recurring across this Set: a count stale in one
day, a baseline wrong in both halves, an off-by-one in a guard's contents, and a size field that
misreports a 7-leaf plan as a threshold exception.
