was verified by reading the code: the guard the backlog item asks someone to invent already exists in
`retire_orchestrator` (`:2258-2271`), already carries the diagnostic message explaining the capture,
already names `driver_actor` as the remedy, and is already pinned by three tests. Lifting reviewed code
instead of writing new code is the right instinct and it survives review intact. The primary defect
reproduces exactly as described: `_HISTORY_ATTRIB_RE` does not match the parenthesized line,
`_HISTORY_LINE_RE` does and yields `executed`, and that fallthrough is what makes
`_newest_executed_history` return `("", "")`. The `key=value` convention really is established and
documented on both drivers (`oc_runipd.py:862-883`, `agy_runipd.py:896-903`). The decision to fix the
INPUT rather than reorder the two-phase transaction is correct and its deferral reasoning is honest.
The `_GENERIC_ACTORS` caution is right and was verified: both generic strings are still captured
exactly and still rejected under the widened pattern. The interim slash-form guidance is verified to
parse. The refusal-message-as-documentation requirement is a good instinct and now has a concrete
obligation attached (the three stale prose copies). And the plan correctly declined to rewrite the
existing corpus, which the corpus measurement vindicates: widening the readers makes all 328 affected
lines parse without editing a single tracked file.

RIGHT-SIZING AND THE ONE ADVISORY. `aw ipd lint` raises `IPD-Z602` on E-07 (three clauses, possible
multi-concern). Assessed semantically and deliberately NOT split: E-07's deliverable is ONE guard at
ONE function, and its second clause (disposing of the dead call site that the guard would refuse) is
not an independent deliverable but the guard's own blast radius, which cannot honestly be closed in a
different pass. The plan is now 8 E-items across 3 groups, under both count thresholds, and each item
maps to one file region and one test surface. E-08 names two patterns and is the one item a reviewer
could argue for splitting; it is kept whole because the two are the SAME one-line change measured the
SAME way, and separating them would duplicate the corpus-wide no-regression proof that is the only
expensive part.

WHAT THIS ROUND CHANGED ABOUT THE PLAN'S SHAPE. The plan arrived as a tidy three-group fix for a loud
nuisance and leaves as a fix for a silent gate failure with the nuisance attached. Two items were
ADDED (E-07, E-08) and they now carry the plan's value; the ordering advice in the gate says so
explicitly, so an executor who runs short of room stops in the right place. One prescribed
implementation was REVERSED on measurement (greedy to lazy), which is the finding I would most want a
re-reviewer to check, because the plan's own named hazard is the case that discriminates them. One
enumeration was CORRECTED in both directions and gained a caller it had missed. One stated baseline and
its named known-failure were both false and are now measured, which for a plan whose executor is told
to judge a module on the delta is worth its own finding. The rest is arithmetic hygiene: three figures
were stale, one effect was overstated by grandfathering, and one unparseable population is out of reach
