This review ran in an isolated, non-interactive review lane with no human channel. After revision, `--phase review-finalize` reports only the expected `IPD-Q501` on the new blocking OQ-03.

- `build_report(suite_passed=True, run_subprocess_gates=True)` on this tree failed `['ipd_lint', 'capability_freshness', 'residual_risk']`. That matches the plan's standing-gate model.
- On a minimal managed-style tree, the following gates FAIL: `docs_checks` ("docs tree missing"), `workflow_disposition` ("could not run: FileNotFoundError"), `capability_freshness` ("capability matrix missing"), and `changelog_versioning`. `gate_leak_scan` on a bare temp dir returned "leak scan exit 2". `engine.collect_source_members` ships `.aw/system/workflows/release-review/08-final-ship-review.md` to managed repositories (PR-002).
- The F-01 grep also matches `.aw/system/workflows/benchmark/tools/bench_env.py` (an unrelated `build_report`) and `agent_workflows/command_surface.py` (the command declaration). The claim "only release_readiness.py and cli.py" is wrong as a grep result, but the underlying property holds: no release-review file, `RELEASING.md`, CI workflow, or hook consumes the report (PR-003).
- `tests/test_agent_surface_conformance.py -k readiness`: 2 passed.
- No em or en dashes in the four target docs.
- Security lens: the plan strengthens a release-authority gate and forges no attestation, because `--residual-risk-signer` is used only after human approval. PR-004 closes a fail-open path the plan itself introduced.

## Round 2

Re-review on 2026-10-15, run non-interactively with no question tool, after the maintainer RESOLVED OQ-03 with option (b) and filed backlog `v1re2z`. The plan was committed and unchanged at `111f08acf`, so no snapshot was taken. `aw ipd lint --phase author --agent` was clean before revision. The `- Item-Dependencies:` edge was set through `aw ipd dependencies set` and auto-committed as `1e0b3ae9f`. `aw ipd lint --phase review-finalize --agent` is clean after revision.

Re-verified at review HEAD:
- `v1re2z` is `open` with `Work-Kind: bug`, `Blocks-Release: next`, and NO plan. `git grep -ln v1re2z -- .aw/records/plans/` matched only this plan.
- `release_readiness.GateResult` carries only `passed: bool`, and `ReleaseReadinessReport.failing_gates` is `[g.name for g in self.gates if not g.passed]`. No not-applicable state exists yet, so this plan cannot name the signal it will read. It has to bind at execution time, which E-01(e) now does.
- `runner_shared.edge_satisfied` requires the EXACT status for a `state:` edge on an execute turn and relaxes only on a review turn. So `state:backlog:done:v1re2z` holds execution until `v1re2z` is `done`, which in turn requires its carrier plan to be executed (AGENTS.md close-legitimacy rule).
- `RELEASING.md` is NOT among `engine.collect_source_members(Path('.aw/system/workflows'))`, but `release-review/08`, `09`, and `templates/final-response.md` are. The maintainer ruled that anything meant only for this repo must not be installed elsewhere. The shipped workflow docs therefore must not carry a this-repo-only carve-out, and E-04(5) now says so.
- The `Blocking / pending items` banner line exists at `templates/final-response.md` (`RELEASE REVIEW DECISION` block). `DecisionGate` has `prompt` and `metadata` fields (`run_gates.DecisionGate`), so the Section 9 display is reachable through the gate the `input_handler` receives.
- Security lens: treating not-applicable as never-a-pass, and a not-applicable `full_suite`/`residual_risk` as hard, keeps the release gate fail-closed for attestation inputs. Absent files are the accepted risk, and they are surfaced to the approver.
