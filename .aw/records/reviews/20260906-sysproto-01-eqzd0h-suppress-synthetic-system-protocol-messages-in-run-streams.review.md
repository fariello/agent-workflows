## Round 1

Reviewed at HEAD `4cbee5fa`. Structural preflight `aw ipd lint --phase author` conformed before semantic
review; `--phase review-finalize` conformed after the revisions.

METHOD, because it produced every finding. This plan makes empirical claims about a string in a data
stream (how many variants exist, where they appear, in which event shapes, on which host), so instead of
reading its prose I measured the corpus it is about: 426 session logs under
`.aw/records/runs/*/sessions/*.jsonl`, 101,836 lines, 4,058 placeholder-bearing `text` events across 294
files. I also read the code the plan proposes to edit, at HEAD rather than as the plan describes it.

WHAT THE PLAN GOT RIGHT, stated first because it is why this is a revisions verdict and not a replan. Its
central count is CORRECT and I confirmed rather than assumed it: the regex it specifies matches exactly 20
distinct variants, and the broad `Empty\b[^\]]*` body (rather than a literal) is the right matcher because
the 19 rare variants are single-occurrence corruptions of the dominant one. Its module placement is right
(shared helper in `render_stream.py`, imported by the agy renderer). Its `return None` suppression
mechanism is the one the renderer already uses. OQ-01's strip-and-show resolution is correct and the
measurement supports it.

THREE CLAIMS WERE FALSE, and each would have produced a specific visible defect.

The worst is PR-001, and it is worth stating why it is worse than an ordinary staleness bug. E-01
prescribed the exact output expression `pal("• ", "cyan") + _one_line(text, 400)`. That expression was
DELETED four commits before this review (`4308015c`, 2026-09-07) and replaced with the aligned
`format_event_prefix("think", ...)` prefix. An executor following the plan literally would have reverted
just-shipped work while believing it was implementing a filter, and the plan gave it no reason to doubt the
line. Two tests catch it, so the damage would have surfaced as "two unrelated tests broke", which invites
an agent to edit the tests.

PR-004 is the mirror image: E-02 instructed edits to `render_agy_event` branches that do not exist. That
function reads no `message` or `text` field anywhere in its 145 lines, and its `agent_response` branch
already returns `None`. So the instruction was unimplementable as written, and the natural way to "comply"
would be to INVENT a branch for an event shape this host has never been observed to emit, for a token
measured at zero occurrences there.

PR-006 is the honesty finding: "suite remains green" is false at HEAD (`1 failed, 5613 passed`), so an
executor would have had to either report a failure it did not cause or quietly accept a broken criterion.

Two measurements reshaped the DESIGN rather than merely correcting prose. First (PR-002), the placeholder
sits at position 0 in 4,058 of 4,059 occurrences, so the unanchored iterative strip the plan specified
bought nothing while risking a real false positive: the token is a string agents legitimately QUOTE when
discussing this feature, and a mid-text strip would silently delete it from genuine narration. For a filter
whose purpose is removing noise, quietly corrupting signal is the one unacceptable failure. Second
(PR-003), `tools/ipdrunner/test_runagy.py` pins `render_agy_event` through the `runagy.py` re-export shim
but is NOT collected by a bare `python3 -m pytest`, so the plan's own validation would have reported green
over a broken agy renderer.
