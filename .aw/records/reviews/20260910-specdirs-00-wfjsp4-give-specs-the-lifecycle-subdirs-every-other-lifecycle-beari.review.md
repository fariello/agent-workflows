THE SET'S THESIS IS SOUND AND I RE-VERIFIED IT rather than trusting the authored measurements. Specs really
are the only lifecycle-bearing records type that does not partition on status: measured across all ten trees,
`plans` 5 subdirs, `backlog` 5, `prompts` 6, `research` 5, `comms` 2, and `specs`, `reviews`, `roadmaps`,
`walkthroughs`, `releases` all 0, with every flat type flat because it has no lifecycle. The reader defect is
real and I re-proved it in a throwaway repo: a spec in `.aw/records/specs/approved/` yields
`aw specs check: all specs conform` while `specs._spec_files` returns ZERO and
`check_engine._iter_type_files` returns ONE. The `glob`/`rglob` root cause is at `specs.py:89` versus
`check_engine.py:517`. The Order 01 -> Order 02 dependency is a genuine correctness edge, not a preference.

WHAT REVIEW CHANGED. Two findings are BLOCKING and left OPEN, because each is a decision the maintainer must
make: one is a scope call on their own accepted trade, the other asks permission to amend an APPROVED spec.
Five were fixed in place, and four of those five are measurement errors that would each have sent an executor
down a wrong path: the Set's own central criterion is unobservable on the two surfaces an executor would
reach, a prescribed cross-check would have failed for a reason unrelated to this Set, the suite baseline is
wrong in both its count and its named failing test, and the spec inventory is stale. E-items grew 3 -> 4,
V-items 3 -> 4, cross-IPD checks 6 -> 8.

THE ROOT CAUSE THE TWO BLOCKERS SHARE is worth naming because it explains why one plan missed both: the Set
was scoped as a READ-SIDE problem plus a move. It correctly found that readers can hide a spec, and it
correctly sequenced the fix first. It did not ask the symmetric question on the WRITE side (who can place a
spec, and do they all know where) or on the CONTRACT side (does an approved spec assert the shape this
changes). Both answers turned out to be "no", and both are the kind of gap that only shows up if you go
looking for the mirror image of the bug you already found.
