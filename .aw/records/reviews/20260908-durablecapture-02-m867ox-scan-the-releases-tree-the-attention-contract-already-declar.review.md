`.agents/releases` added to `SCAN_ROOTS`, the E-04 cross-list guard is GREEN while `attention.scan`

this repository materializes no `.agents/releases`. The plan had left the choice between spellings as a
non-blocking cosmetic OQ ("an unused root costs a directory probe per scan and nothing else"), so an
executor could legitimately have added only the `.agents/` spelling, seen the guard go green, and
shipped nothing. That turned OQ-02 into a correctness question and forced a third E-05 mutation to
PROVE the gap rather than assert it.

is impossible because `TRACKED_TREES` is DERIVED from `TREE_POLICY` (PR-004); E-04's predicate is
under-specified and its most obvious form (`_classify_tree` alone) FAILS IMMEDIATELY on `.agents/docs`,
the scanned ancestor of specs and research (PR-005); and releases is the only tracked tree with no
map-totality test, which is the guard the plan's "check all three values" instruction should have been
(PR-006).

BOTH OPEN QUESTIONS WERE RESOLVED FROM REPOSITORY EVIDENCE RATHER THAN ESCALATED, and the reviews half
resolved decisively: a review record has NO `- Status:` field at all (zero of 132 `.review.md` files),

8.6 states the tracked-or-excluded RULE rather than a closed roster, so adding an exclusion SATISFIES
the spec; Section 8.1 already requires a tracked tree be scanned, so E-01 brings code into compliance
with a spec that already says the right thing. No amendment, and the spec file is deliberately kept out
of `- Scope-Paths:`.

No BLOCKER. Ten findings, all FIXED, none deferred, no open question remaining. The plan is now
substantially longer than it was, and that is the point: it went from a two-line change with an
