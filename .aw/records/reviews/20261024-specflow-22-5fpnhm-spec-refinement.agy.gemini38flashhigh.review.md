### Scope and Verification Summary

1. **Gating Finding Schema Contradiction and Table Misalignment with `review_findings.py` (F-105)**: Identified that Section 4.3 FR-07 defined a critique finding schema with non-existent fields (`Category`, `Requirement Reference`, `Suggested Remedy`, `Disposition`) and non-normative severities (`critical`, `major`, `minor`, `cosmetic`), directly contradicting the repository's typed review data layer in `agent_workflows/review_findings.py`. If review records were emitted adhering to FR-07, `review_findings.parse_review_text` would fail with parse diagnostics `REV-P001` (column count mismatch against `FINDING_COLUMNS`), `REV-P002` (unknown severity against closed `SEVERITIES`), and `REV-P003` (unknown decision against closed `DECISIONS`). Furthermore, in Section 6.1 ERD, entity `ITERATION_FINDING` erroneously mirrored these non-standard fields instead of matching `review_findings.py`. Aligned Section 4.3 FR-07, FR-09, FR-11, Section 6.1 ERD, and the persistence table with `FINDING_COLUMNS` (`ID`, `Severity`, `Scope`, `Area`, `Evidence`, `Finding`, `Remediation Risk`, `Decision`, `Resolution`), mapping gating severities strictly to `high` and `blocker` with `Decision != fixed`, and advisory severities to `low` and `medium`.
2. **State Diagram 7.3 Unconditional Bypass of Capped-with-Findings Halted State Contradicting FR-11 and Section 13.3 (F-106)**: Discovered that State Diagram 7.3 showed `CappedCandidate` unconditionally transitioning to `Synthesizing` (for N > 1) or `Finalizing` (for N = 1), and `CappedSynthesis` unconditionally transitioning to `Finalizing`. This contradicted Section 4.3 FR-11 and Section 13.3 Worked Transcript (`cp73m9`), which mandate that reaching refine-cap or synth-refine-cap with unresolved blocker/high findings halts execution with exit code 1 in state `capped_with_findings`. Added explicit state `CappedHalted` to Diagram 7.3 along with resumption branches to `Dispatching` (via `aw specs flow resume` with increased caps/budget), `Synthesizing` (via `aw specs flow merge`), and `Finalizing` (via `aw specs flow finalize --allow-unresolved-findings`).
3. **CLI Options Asymmetry: Missing Title/Slug on `reconcile` and Selector Gaps on `status` (F-107)**: In Table 3.4, `aw research flow reconcile` omitted `--title <str>` and `--slug <slug>`, preventing users from naming reconciled output artifacts when synthesizing from standalone reports. Additionally, `aw specs flow status` and `aw research flow status` omitted `<setid>` selector support (resolving latest run for set), creating asymmetry with `resume`, `finalize`, and `cancel`. Furthermore, `aw research flow finalize` lacked `--allow-unresolved-findings`. Updated Table 3.4 to include `--title`/`--slug` on `reconcile`, `<setid>` selector support on `status`, and `--allow-unresolved-findings` on `research flow finalize`.
4. **Flowchart 7.1 and 7.2 Decision Symmetry, Cap Branching, and Terminal Lifecycle Routing (F-108)**: Flowchart 7.1 node O unconditionally directed final specs to `to-review/`, contradicting Section 1.5, Section 4.6 FR-20, and maintainer ruling DL-17, where single-model runs, solo runs, and capped runs with findings finalize to `draft/` with status `draft`. In Flowchart 7.2 (Research Flow Diagram), single-model candidate refinement (`RR_solo`) and multi-model candidate refinement (`RR_multi`) lacked critique/revision loops and convergence/cap decision diamonds, breaking symmetry with Flowchart 7.1 and obscuring Stage 2 bounded loops. Updated Flowchart 7.1 terminal node O and added explicit critique/revision feedback loops and convergence/cap decision diamonds to Flowchart 7.2.
5. **Inaccurate D177 Pre-Cutover Severity Statement in Section 6.2 Item 4 (F-109)**: In Section 6.2 Item 4, the spec stated: "`check.name-nonconformant` will report warnings on D177 filenames outside research". In `agent_workflows/check_engine.py:138`, `RULE_REGISTRY["check.name-nonconformant"]` is registered with severity `"error"`, not `"warning"`. Mislabeling error diagnostics as warnings misleads operators regarding CI gate behavior. Corrected Section 6.2 Item 4 to accurately cite `error` severity and clarify that Phase 1 implementation of D177 eliminates these errors.
6. **Missing Canonical Token `gpt61` in Section 11 Phase 1 Model Token Vocabulary (F-110)**: Section 11 Phase 1 specified adding alias `gpt-6.1 = "gpt61"` to `[normalizations]` in `research-models.toml`, but omitted `gpt61` from the list of canonical tokens to add to `models` (`opus55`, `opus55high`, `gpt61sol`, `gpt61solmedium`). In `research_contract.py: normalize_model()`, normalizing to a token not in `models` causes `recognized=False`. Added `gpt61` to the canonical tokens registered under `models` in Section 11.
7. **Section 6.3 Review Front Matter Schema Scope Range and Markdown Findings Header Specification (F-111)**: Section 6.3 Review Critique Record schema lacked the required `## Round <N>` and `### Findings` headers and the 9-column Markdown findings table. Line 693 also referenced an outdated test range (`AT-01..AT-44`). Updated Section 6.3 Review Critique Record schema to include `## Round 1`, `### Findings`, conforming 9-column table, and updated `Audited-Scope: [FR-01..FR-36, AT-01..AT-52, Decisions 01..13]`.
8. **Acceptance Test Matrix Coverage Expansion (F-112)**: Added acceptance tests `AT-49` (`review_findings.py` parser verification on emitted reviews), `AT-50` (`<setid>` selector resolution on `status`), `AT-51` (`--title` and `--slug` options on `reconcile`), and `AT-52` (refinement cap halting in `capped_with_findings` state without premature synthesis dispatch), expanding audited scope to `AT-01..AT-52`.
