THE DOMINANT FINDING IS ONE THE PLAN COULD NOT SEE BY READING, ONLY BY RUNNING. The guard detects
`ast.parse` and `ast.walk`, and it must CALL both to do its own job. Implemented exactly as E-01
specified, it is RED ON ARRIVAL AGAINST ITSELF. I demonstrated this rather than reasoning it: the
detector this plan specifies, run over a guard body written as this plan specifies, reported two
self-violations (`ast.parse` and `ast.walk` in its own scan function) while reporting zero over the
rest of the post-Order-01 tree. The plan's own gate forbids both available remedies (do not weaken
the guard, do not add an unjustified allowlist entry), so an executor following it literally reaches
a state with no authorized way forward. Fixed by requiring a structural self-exclusion by resolved
`Path(__file__)` identity, deliberately NOT an E-02 allowlist entry, with the reasoning recorded: an
allowlist entry claims a file holds a sanctioned pin whose need may expire, whereas the guard's own
machinery is permanent, and E-02's self-cleaning rule would keep demanding forever that the guard
still contain a flagged call.

A SECOND MECHANICAL DEFECT OF THE SAME KIND: E-02's self-cleaning assertion would have been
structurally vacuous. It asks whether each allowlisted file STILL CONTAINS a flagged call, but a
detector that consults the allowlist internally answers "no" for exactly the files the allowlist
covers, so the check would pass forever including after the file it names was emptied of pins. Fixed
by requiring the detector be a pure function over `(relative_path, source_text)` that both the tree
scan and the self-cleaning check call, the former allowlist-filtered and the latter not, which is the
seam `tests/test_carrier_scan_single_item_contract.py` already ships
(`scan_source_for_contract_violations` beside its package walk). V-02 now demands the non-vacuity be
shown by pasting the flagged calls found in the real entry (7 at review measurement).

justified attribute-form matching by saying the sanctioned exception "contains those names as DATA
