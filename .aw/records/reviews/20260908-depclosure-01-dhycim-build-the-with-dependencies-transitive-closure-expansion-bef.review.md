WHAT THIS ROUND CHANGED ABOUT THE PLAN'S SHAPE. Nothing about the design: the closure belongs in the
shared module, at that seam, for this one flag. The pattern in the revisions is that this plan traced
the flag's INPUT path meticulously and did not trace its OUTPUT path. It knew precisely where to insert
and what to parse, and it did not ask what the expanded selection would then flow into: not what the
gate is actually handed (a loop that swallows the very targets the gate exists to catch), not what
`action_for` returns for a target the closure would newly admit (`execute`, for a plan that is already
finished), and not what the queue builder does with an id6 the manifest lacks (an unguarded `KeyError`,
after the run directory exists). Three of the four review findings are that same omission at three
depths. The second, smaller theme is that a plan citing a fast-moving file must re-measure the file it
cites, and that spot-checking the wrong host is worse than not checking: the oc citations were nearly
all still exact, which would have wrongly reassured anyone who sampled them.
