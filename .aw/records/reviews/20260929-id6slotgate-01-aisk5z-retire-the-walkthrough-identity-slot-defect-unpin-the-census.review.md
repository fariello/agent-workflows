EVERY ONE OF THE PLAN'S SIX AUTHORING FACTS WAS RE-DERIVED RATHER THAN RE-READ, and all six hold at review
HEAD. Fact 1: the census over `.aw/records/walkthroughs/` shows `slot=01ad6r id=01ad6r target=zpbx7o`,
`slot=cceh3w id=cceh3w target=y5od1h`, and `slot=v0nmuv id=v0nmuv target=4fodkt`, so the three plan id6s the
backlog item names are held as `- Target-Id:` references and not as identities. Fact 2: `aw find y5od1h`
returns the plan plus its own review record and no walkthrough. Fact 3: `check_collisions(root)` and
`check_collisions(root, include_retired=True)` both return `Counter()`. Fact 4 reproduced exactly, by adding
one fully conformant walkthrough: `AssertionError: 25 != 24 : Census must find exactly 24 walkthroughs`,
`1 failed, 3 passed`. Fact 5 reproduced exactly, by deleting the `cceh3w` file's `- Id:` bullet at an
unchanged census size: `"...cceh3w...: slot id6='cceh3w', declared in metadata region=None"`. Fact 6: 24
total, 13 clustered, 11 slotless, and the slotless set equals `LEGACY_WALKTHROUGHS` exactly (set difference
empty in both directions). Both mutations were reverted and `git status --short` was clean afterwards. So the
plan's inversion of its backlog item is correct: the remediation shipped, and the residue is the guard.

WHAT REVIEW FOUND THAT AUTHORING DID NOT falls into two groups, and the second is the substantive one.
FIRST, two `error`-severity rules were firing on this plan and the plan did not know. `check.scope-path-target-stale`
reported BOTH declared backlog paths, because the runner moved both items from `open/` to `graduated/` when
this plan was authored (commits `0f777712` at 11:56:36 and `4eec8292`, 35 seconds after the plan commit
`eaaf92c0` at 11:56:01), so the plan was authored against paths its own graduation invalidated. And
`check.ipd-uncarried-obligation` reported five deferred rows naming no durable carrier, at `error` severity,
while the SIBLING plan `dta75n` in the same Set carries `Carrier-Declined`/`Carrier-Evidence`/`Carrier` on
every one of its rows. Both are fixed; both rules are now silent on this plan (PR-001, PR-002).

SECOND, AND THIS IS THE FINDING THAT MATTERS, THE PLAN'S PRESCRIBED FIX WAS PARTLY DEAD CODE AND ITS
REPLACEMENT GUARD WAS VACUOUS. E-02 instructed the executor to "derive the legacy exemption" from
`check_engine._identity_slot_token`. Measured, that derivation is a NO-OP: the loop already carries
`if not token: continue`, so running the loop with the `LEGACY_WALKTHROUGHS` literal, with a
`_identity_slot_token` pre-filter, and with NO exemption at all returns the identical
`(examined=12, failures=[])`. Adding the pre-filter would have shipped dead code whose harmlessness a later
reader must re-derive (PR-003).

That matters because it means the ONLY new protection E-02 offered was its anti-vacuity floor, and the floor
as specified ("at least one clustered walkthrough was actually examined") is measurably too weak: the
eligible population is 12, so it passes while examining 1 of 12. Strengthening it to an equality was the
obvious repair and IT IS ALSO VACUOUS if the expected side comes from the same normalizer, which I found by
writing my own first fix and then trying to break it. Simulating two normalizer regressions (one recognizing
only `202609*` names, one recognizing none) kept `examined == expected` TRUE at `12/12`, then `9/9`, then
`0/0`, because the regression moves both sides together. Recomputing the expectation from an INDEPENDENT
legacy-name-shape rule keeps `12 == 12` at rest and fails both regressions at `9 != 12` and `0 != 12`. That
is now E-07, with the independence requirement stated as the load-bearing property and the collapse-it-to-
remove-duplication temptation named as the thing that would silently re-vacuate it (PR-004).

THE PLAN'S OWN STANDARD IS WHAT CAUGHT THIS. It says "a green run proves nothing on its own, because the
failure mode being fixed is a test that passes while asserting the wrong thing", and then specified a new
assertion nobody had watched fail. E-09 now mutates the discriminator and requires the pasted failure, and
V-09 states explicitly that a PASS there is a FAILED validation because it proves the vacuous shape.

ONE FURTHER CORRECTNESS NOTE ON WHAT THE GUARD IS FOR, since it justifies keeping the test at all rather
than deferring to `aw check`: the test catches a class the checker does not. A walkthrough with a UNIQUE
slot id6 and no declared `- Id:` satisfies `_check_identity_slots` rule (b) as sole holder, so
`check_collisions` returns `Counter()` on it, while the test's loop fails it. Measured in a scratch repo. So
the two surfaces are not redundant and narrowing the test toward the checker would lose coverage.
