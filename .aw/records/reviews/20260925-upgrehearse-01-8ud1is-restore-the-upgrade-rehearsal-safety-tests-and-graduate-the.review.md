## Round 1

All claims verified at HEAD `b6155ed0`. The target plan was committed and unchanged, so the pre-review
snapshot was correctly skipped per Step 1. Structural preflight `aw ipd lint --phase author --agent`
reported `conforming` (exit 0) BEFORE review and again at `--phase review-finalize` afterwards.

ALL THREE OF THE PLAN'S FINDINGS HOLD, and its central sequencing instinct is right. F-1: the test file
was deleted in `19313eed`. F-2: the safety tests pass against today's tool, exactly 13 of them. F-3:
`aw upgrade-test` does not exist (`invalid choice`). Restoring coverage before moving code is the right
order, and review found it is load-bearing in a way the plan did not state: the restored tests
CONSTRAIN two of the plan's own later items, so restoring first is what makes those constraints visible
before the code moves rather than after.

I RESTORED THE DELETED FILE AND RAN IT rather than reasoning about it, and that decided most of this
review. `37 passed in 2.52s`; `-k SafetyInvariant` gives `13 passed, 24 deselected`. So the whole file
passes against today's tool, not merely the safety subset the plan proposed to keep, and all four
helpers it imports from `tests/support.py` still exist.

THE DOMINANT FINDING IS PR-603, and it is the combination rather than either half. E-01 proposed
dropping `CliTests` as pinning "incidental behavior", while E-03 proposed rewriting the output
contract. Reading the discarded class: `test_the_json_flag_is_honored_on_either_side_of_the_subcommand`
pins a MEASURED regression in which a subparser applying its own `--json` default LAST clobbered the
value the top-level flag had already set, so `--json list` parsed to False and silently emitted human
output to a caller that asked for machine output. Its five-row table varies the flag's SIDE and the
SUBCOMMAND deliberately, because the flag is inherited from a shared parent and the bug was therefore
reintroducible one subcommand at a time; the negative row pins `default=None` with `store_const`
because that is the MECHANISM, and a well-meant change to `default=False` reintroduces the clobber. So
the plan would have deleted the only guard on its own riskiest change, in the same commit that makes
it. `InspectionTests` is the same story in miniature: it pins the version/layout precedence every
rehearsal report's claims rest on, including that a dual-layout repo must report the version it
upgraded TO rather than FROM. These are behavior tests in temp directories, not structural pins, so the
standing rule against structure-pinning tests does not reach them.

THE SECOND MATERIAL FINDING IS PR-604, where the plan contains an internal contradiction. E-04 called
for defaulting the sandbox root "to a directory under the system temp dir". A SAFETY test that E-01
restores, `test_default_sandbox_root_is_computed_not_hardcoded`, asserts both
`computed.name == SANDBOX_ROOT_NAME` and `computed.parent.name == "tmp"`; a bare
`tempfile.gettempdir()/aw-upgrade-tests` fails the second. Worse, the `tmp/` nesting is a SAFETY
MECHANISM rather than an accident: `default_sandbox_root`'s own docstring records that a sandbox placed
directly under a discovery search root would be found as a managed repo and could be swept into a later
`aw install all`, which is invariant 3, and the extra level exists because the immediate-children scan
cannot reach it. So E-04 as worded would have broken a test E-01 restores and weakened an invariant
this plan exists to protect.

PR-605 corrects the justification for that same item. E-04's stated goal was "no maintainer-specific
path in the default" and its validation asked for a sanitizer run. Measured: `aw sanitize --agent` is
CLEAN at HEAD, `default_sandbox_root` is already COMPUTED with an `AW_UPGRADE_TEST_ROOT` override, and
its docstring already says a literal "is exactly what the leak-sanitizer rejects". There is no tracked
leak and no hardcoded path to remove. The genuine defect is narrower and is the one the SOURCE ITEM
states: with no configured search root the function falls back to `Path.home()`, so a fresh
non-maintainer gets sandboxes in their home directory. The item survives with that concern and a
recorded decision (OQ-02, resolved to change only the fallback), which satisfies the source item while
keeping both restored assertions true and preserving the invariant-3 nesting.

PR-606 is an unsatisfiable acceptance criterion. E-03 expected `find_undeclared_leaves` to "stay
empty"; measured, it returns FIVE entries today (`oc profile add|default|list|remove|show`). An
executor would either report a false pass or chase five leaves this plan does not own: they belong to
pending plan `0yrtne` (Set `cmdsurf`), which declares them and restores the whole-CLI declaration test.
The repository already sets the precedent for the correct shape, in `tests/test_prompts_new.py`, whose
comment says the suite-wide test "is RED at baseline for other verbs" and whose assertion is scoped to
its own leaf.

PR-607 removes a false safety assumption rather than a false statement. The plan leans on leaf
declarations being enforced; both `tests/test_command_surface_declarations.py` and
`tests/test_cli_conformance_matrix.py` were deleted in `19313eed`, the same commit that removed the
upgrade-test file, and the CI step that names them is VACUOUS. I ran its exact command: all three
listed files are absent, pytest collects nothing, exit 0. So an undeclared leaf added today fails
nothing at all. I recorded this rather than fixing it (out of scope, and `0yrtne` owns the whole-CLI
test) and moved V-05 to check the leaf set directly instead of trusting CI.

PR-608 is a concrete break the move would have caused. The restored tests reach internals through
`load_module("aw_upgrade_test", TOOL)` and call many private helpers off that module object, so a shim
that only delegates `main` breaks them. The shipped precedent the source item names does the right
thing and the plan should say so explicitly: `tools/pwatch.py` is 35 lines over a 1051-line package
module and RE-EXPORTS every non-dunder attribute. I also found the one test that genuinely needs an
edit rather than a verbatim restore: `test_default_sandbox_root_is_computed_not_hardcoded` does
`Path(TOOL).read_text()` and asserts a literal is absent, which after the move reads the SHIM and
becomes vacuous. It must be repointed at the package module in the move item, and kept rather than
deleted, since it is the only mechanical guard against a future hardcoded default.

One thing I checked that strengthens the plan's case rather than weakening it, and that belonged in the
record: `pyproject.toml` declares `packages = ["agent_workflows"]`, so nothing under `tools/` ships in
the wheel and an installed user cannot reach the harness AT ALL today. That is the substantive reason
graduation matters, and it is stronger than the tidiness framing the plan used.

Backlog item `u27q6g` carries no `- Blocks-Release:` and is `Work-Kind: feature`, so no release gate is
owed. Its item 5 (decide the shipped default) is now discharged by OQ-02, and its synthetic-baseline
half remains open and is carried explicitly in Deferred, which is why the gate now says to close the
item only if that half is separately carried.
