WHAT THIS ROUND CHANGED ABOUT THE PLAN'S SHAPE. Nothing about its gating, and one thing about its
feasibility. The plan treats "reuse the existing prompt" as its one absolute, safe constraint, the part
that needs no thought because the item already settled it. Reading that prompt shows it is the opposite:
it is the plan's hardest unsolved problem, because the prompt is an instruction to FIX AND COMMIT against
a live worktree, and the whole point of this verb is to look at work that must not be touched. That
collision cannot be wired around, only decided, which is why a new E-item and a new blocking question
were the only honest responses. Two measurements then compounded it: the verifier is already ON by
default on one of the two hosts, and the baseline the verb would judge against no longer exists for 97
percent of the corpus. Neither kills the idea, but both push in the same direction as the blocking cost
question the plan already asks, and a maintainer answering OQ-01 should see all three together. The
lesson worth carrying is narrow and repeatable: this plan cited the prompt by SYMBOL and never READ IT,
and every defect above except the stale statuses follows from that one omission.
