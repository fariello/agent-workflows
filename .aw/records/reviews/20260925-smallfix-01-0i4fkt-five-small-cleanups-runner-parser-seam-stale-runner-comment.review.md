THE DOMINANT FINDING IS F-6 (recorded as PR-401), and it is a finding ABOUT THE SOURCE BACKLOG ITEM
rather than about the plan's own reasoning. `ykfgpd` instructs the executor to update
`tests/fixtures/runner_shared_premove_fingerprints.json`, to "move `discover_plans` from `INJECTED`
into the clean-fingerprint set (which changes the pinned clean-move count of 23)", and to add a row to
`tests/test_runner_refork_guard.py`'s `REFORK_TABLE`. None of those surfaces exists. The refork guard
file was DELETED in `19313eed` ("test: trim test suite from 9,136 to under 2,000 tests", 680 lines),
and no executing code reads the fingerprint fixture: a tree-wide scan finds `premove_fingerprints` on
seven lines, ALL of them prose, with no `json.load` or `read_text` of it anywhere. An AST walk of
`tests/test_runner_shared.py` finds no definition named
`test_every_clean_symbol_is_a_STRICT_fingerprint_match`, `test_no_call_site_was_rewritten`,
`test_an_unwrapped_symbol_is_the_SAME_OBJECT_in_both_runners` or
`test_exactly_one_definition_package_wide` - all four of which surviving comments in that same file and
in `runner_shared.py` cite as live guards. So the harness is gone and its documentation is not.

That cuts both ways, and the plan needed both halves. It SHRINKS E-01: there is no fixture migration,
which is what the source item (and both host comments, and the module docstring) claimed made this
"belong in its own plan". It also ADDS work the plan did not have: three prose sites now assert a pin
that does not exist, and leaving them is exactly the stale-citation defect `1gw7nl`, the plan's own
second source item, exists to retire. An executor following `ykfgpd` literally would hunt two absent
surfaces and might plausibly RECREATE one, reversing a deliberate suite-trimming decision.

THE SECOND MATERIAL FINDING IS F-8 (PR-403): V-02's proposed mutation, the plan's ONLY falsifiability
proof for its new test, passes vacuously. `attention.scan` reaches `SCAN_ROOTS` through
`core.iter_scan_files(repo_root, scan_roots=SCAN_ROOTS)`, a DEFAULT ARGUMENT bound at def time, so
rebinding `artifact_core.SCAN_ROOTS` at runtime has no effect at all. I measured both forms: the
attribute rebind still returned the synthesized specs item (so the mutation appears to FAIL to fail),
while editing the source line out of `artifact_core.py` returned zero items. A plan whose new test's
credibility rests on one mutation cannot leave the mutation ambiguous, and the obvious way to write it
is the wrong one.

F-9 is smaller but would have cost the executor a debugging detour: the five tracked trees do not
share one front-matter grammar, so the plan's "write one minimal valid record" instruction is not
uniformly satisfiable. `research` is parsed by `research_contract.parse_frontmatter`, which requires a
`---` delimited block with a lowercase `status` key and returns `None` for the repository's ordinary
`- Key: value` bullets; a bullet-style research fixture yields zero items plus an
`attention.missing-status` drift. I ran all five shapes and recorded the working ones in E-06 so the
executor does not rediscover them.
