### Scope and Verification Summary

1. **Synthesized Specification Schema Missing `## Workflow history` (F-80)**: Identified that the YAML front matter schema for Synthesized Specifications in Section 6.3 omitted the mandatory `## Workflow history` section. In `agent_workflows/specs.py`, `validate_spec()` enforces rule `attention.history-missing` ("no conformant `## Workflow history` record") across all specifications. Any synthesized candidate spec written using this schema would immediately fail `aw specs check`. Added `## Workflow history` with a conformant creation record to the schema.
2. **State Diagram 7.3 Stage 1 Worker Failure Transitions (F-81)**: Discovered that State Diagram 7.3 only modeled permanent worker failures during `CandidateRefining` (Stage 2), while `Generating` (Stage 1) transitioned only to `Failed (Exit 2)` for host crashes. Under FR-30, worker failures can occur during Stage 1 candidate generation; without `--allow-partial-roster`, this must lead to `PartialRoster` (Exit 1), or `Failed` (Exit 1) if all workers fail. Added transitions from `Generating` to `PartialRoster` and `Failed (Exit 1)`, as well as proceeding to `CandidateRefining` when surviving candidates >= 1 with `--allow-partial-roster`.
3. **Research Flow Turn Bounds Mathematical Under-Count & Flowchart Symmetry (F-82)**: Resolved a mathematical contradiction in Section 4.3.1. The closed ceiling formula `Max_Research_Turns` omitted candidate report refinement (`Refine_Cap`), while Table 3.4 defined `--refine-cap <int> (default: 3 thorough, 1 quick)`. In a standard thorough run, candidate refinement adds up to 18 turns across 3 participants, causing dispatched turns to exceed the stated ceiling (27 vs 9 turns). Furthermore, single-participant research flows (N=1) bypass reconciliation, meaning research runs had 0 refinement iterations. Corrected `Max_Research_Turns` to include `[ N_participants * Refine_Cap * 2 * (1 + Max_Retries) ]` and updated Flowchart 7.2 to reflect candidate verification and refinement loops for both N=1 and N>1.
4. **Positional Attribution Regex Outer Optionality for Bare `.md` Dual-Read (F-83)**: Fixed the proposed D177 extension regex for `artifact_naming._CLUSTERED_RE` in Section 6.2. The regex lacked outer optionality on the type facet group, which would cause `_CLUSTERED_RE` to reject valid bare `.md` filenames, breaking the permanent dual-read invariant documented in `artifact_naming.py:124`. Corrected regex to `r"(?:(?:\.(?P<ace>[a-z0-9-]+)\.(?P<model>[a-z0-9-]+)|\.(?P<model_only>[a-z0-9-]+))?\.(?P<type>" + _FACET_ALT + r"))?\.md\Z"`.
5. **Table 3.4 Missing `--max-retries`, Limits on `from-spec`, and Cap Overrides on Resume (F-84)**: Synchronized CLI argument tables with functional requirements. Added `--max-retries <int>` to `aw specs flow new`, `aw specs flow from-spec`, and `aw research flow new`; added limits (`--refine-cap`, `--synth-refine-cap`, `--budget`, `--turn-timeout`, `--max-retries`, `--allow-partial-roster`) to `aw specs flow from-spec`; and added cap and budget override flags (`--synth-refine-cap`, `--budget`, `--force-stale-resume` to `specs flow resume`; `--refine-cap`, `--reconcile-refine-cap`, `--budget`, `--force-stale-resume` to `research flow resume`).
6. **Premature Finalization Claims for `merge` and `reconcile` (F-85)**: Corrected Table 3.4 where `aw specs flow merge` claimed to unconditionally finalize to `to-review/`. Under FR-11, FR-20, and DL-17, if synthesis refinement reaches cap with unresolved critical or major findings, or if candidates originated from a single model, auto-advancing to `to-review/` is forbidden. Clarified that `merge` only finalizes to `to-review/` when all clean multi-model synthesis criteria are satisfied; otherwise, it leaves the spec in `draft/` (or `draft/intermediate/`) and exits 1 if capped with findings. Synchronized `aw research flow reconcile` similarly.
7. **Table 6.2 NN Collision Between Input Brief and Scoped Context Packet (F-86)**: Resolved NN collision in Table 6.2, where both `0. Input` (frozen brief) and `0. Context` (scoped repository context packet) were assigned NN `00` in `.aw/records/prompts/pending/`. Clarified that `00` is reserved for the frozen brief/scope, while participant-scoped context packets allocate deterministically within `01..09` (e.g. `01`..`04` prior to generation prompts), maintaining strict NN ordering.
8. **Missing `config` CLI Subcommand in Phase 1 Implementation Plan (F-87)**: Added `config` to the Phase 1 implementation command lists in Section 11 for both `aw specs flow` and `aw research flow`, reconciling Section 11 with Table 3.4.
9. **Acceptance Test Matrix Coverage Expansion (F-88)**: Added acceptance tests `AT-37` (two-digit NN sequence space exhaustion handling at 99), `AT-38` (`aw research flow prepare` Stage 1 prompt staging without agent execution), `AT-39` (resuming a budget-exhausted or synthesis-capped flow with updated limits), and `AT-40` (`aw specs flow cancel` refusal with exit 1 on inactive/finalized run), expanding audited scope to `AT-01..AT-40`.
