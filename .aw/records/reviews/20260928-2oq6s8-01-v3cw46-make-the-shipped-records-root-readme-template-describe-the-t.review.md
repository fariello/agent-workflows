THE DIAGNOSIS IS TRUE AND WAS RE-MEASURED END TO END. A fresh install into a scratch repo emits the

absence, and the zero-coverage baseline all reproduce as stated (F-04, F-05, F-06, F-08).

THE DOMINANT FINDING IS THAT E-04 AS SPECIFIED WOULD HAVE FAILED AGAINST E-01'S OWN CORRECTED TEMPLATE.
E-04 mandated resolving every path-shaped backticked token "against the README's OWN DIRECTORY", while
E-01 mandated a framework pointer of `.aw/system/workflows/index.md` written repo-root-relative. Those
two instructions are incompatible, and the incompatibility was measured rather than reasoned: a
simulated corrected template resolves that pointer to `<repo>/.aw/records/.aw/system/workflows/index.md`
and reports MISSING. The plan therefore commissioned a guard that is RED against the fix it
commissions. The dangerous part is the likely repair path: an executor facing a red test on the correct
template, and holding E-04's explicit single-base instruction, would most plausibly make the pointer
records-relative to go green, which restores the exact dead-link shape E-01 exists to remove and leaves
a passing test certifying it. Fixed by specifying a TWO-BASE RULE (a `.aw/`- or `.agents/`-prefixed
token resolves from the install's repo root, every other token from the README's own directory), which
was demonstrated to admit the fix (8 tokens, zero missing), still catch the live defect (two real
misses), still catch a bogus repo-root-relative token, and still catch the reverted-E-03 legacy case.

THE SECOND FINDING IS THAT THE PLAN'S SUITE BASELINE IS NOT MERELY STALE BUT INVERTED. F-12 instructed
the executor that ONE failure is expected and pre-existing, and set the bar as "this failure and no
other appears". That failure was fixed by commit `f1b5b9ff` between authoring and review; the tree is
now fully green at `3069 passed, 2 skipped`. As authored, the plan would have taught an executor to
accept a red suite, and to accept it on a named test it has no reason to re-check, which is a licence
to ship a regression. The bar is now ZERO failures against a baseline the executor re-derives at lane
start rather than against either recorded number.

A THIRD, QUIETER HAZARD WAS FOUND IN THE CODE E-03 TOUCHES. `ensure_plans_readmes` wraps its template
read in `except OSError: continue` with the comment "No template shipped for this target; skip rather
than invent content". So if E-03 selects `agents-legacy-README.md` and E-02's file is missing or
misnamed, a legacy install writes NO records-root README at all and still exits 0 with no warning. That
is the realistic way this change fails, it produces no error to notice, and the plan did not mention it.
E-04's legacy case does catch it, so V-03 now requires that state demonstrated red.

WHAT THIS REVIEW DID NOT CHANGE. The route is sound and the split-the-template decision is right; OQ-01
was upgraded from argued to DEMONSTRATED (the review built both scratch layouts and measured the
single-file alternative failing) rather than re-decided. OQ-02's admissibility reasoning stands: E-04
resolves what a document NAMES against a real install and pins no wording, so it sits on the correct
side of the 2026-09-26 no-text-pins ruling. OQ-03's `bug` classification and inherited
