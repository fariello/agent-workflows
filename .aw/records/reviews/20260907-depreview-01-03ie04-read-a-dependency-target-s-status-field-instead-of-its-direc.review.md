## Round 1

Reviewed at HEAD `01b0b150`. Structural preflight `aw ipd lint --phase author` conformed before semantic
review; `--phase review-finalize` conformed after the revisions.

METHOD. This plan makes claims about what specific code does, so I read that code at HEAD, ran an
interpreter identity probe over the two runner modules, and REPRODUCED the reported defect in an
isolated throwaway repository rather than accepting the session's earlier terminal output as proof.

WHAT THE PLAN GOT RIGHT, and it is most of the plan. All three of its central claims are TRUE and each
is confirmed: the review relaxation exists and is action-aware (`oc_runipd.py:3316`, `:3339`);
`plan_bucket` reads directory components only and this layout has no `reviewed/` or `approved/`
directory (`runner_shared.py:1094-1108`, plus `ls .aw/records/plans/`); and the status reader is already
imported and already used for this exact comparison 2,500 lines away (`:258`, `:5813-5822`). The isolated
probe reproduced the refusal message verbatim. Its diagnosis, its precedence rule (OQ-01), and its
insistence on not relaxing the execute path are all correct, and its E/V structure was already sound.

THE VERDICT IS NOT ABOUT CRAFT. It is NO-GO for one reason the plan cannot fix by itself: the change is
forbidden by an approved spec. `25kzda` carries `- Status: approved` and its §2.9 defines an `executed:`
edge as satisfied when the target "is in `executed/` with status `executed`", with no review-action
exception anywhere in the section; §2.10 adds "All surfaces call this evaluator; none reimplement the
rules." So the `("executed", "reviewed", "approved")` tuple is itself an unsanctioned deviation. Today
that deviation is INERT precisely because the relaxation is unreachable, which is a genuinely
interesting property: the bug this plan fixes is also what has kept the code spec-compliant in effect.
Making it reachable converts a dormant deviation into a live one, and that is a contract decision a
human owns. I did not resolve it, because the repository does not answer it: code and approved spec
disagree and nothing reconciles them. It is raised as OQ-04 with `- Blocking: yes` and PR-001 stays OPEN.

THE ONE STRUCTURAL ERROR would have shipped a half-fix while claiming host parity. The plan asserts
`agy_runipd.py` "BINDS these symbols rather than defining them, so the fix reaches it without an edit",
and fences agy out of Scope-Paths on that basis. Measured, that is false: agy defines its OWN
`dependency_status_detailed`, and `agy.dependency_status_detailed is oc.dependency_status_detailed`
returns `False` while `dependency_status`, `edge_satisfied` and `plan_bucket` all return `True`. The
consequence is subtle enough to be worth stating exactly. Agy re-exports oc's `dependency_status`, whose
body resolves `dependency_status_detailed` in OC's globals, so agy's DISPATCH path would have inherited
the fix; its DRAIN path calls the local copy and would not. One driver, two dependency paths, two
semantics. Worse, the local copy is already broken independently: it never calls `edge_satisfied` and
uses the raw dependency string as an id6, so it cannot resolve a typed edge at all (measured: it reports
`executed:tttttt: no plan resolves to this id6 in the repo`). Every plan in this tree declares typed
edges. The existing anti-copy guard misses it because `_SHARED_NAMES` lists `dependency_status` but not
its `_detailed` sibling, and the module's own comment 3 lines below the copy already describes this exact
failure mode for the sibling function, so the class of defect is known and recurring.

A second, smaller error: E-03 (now E-05) would have deleted `reviewed`/`approved` from `plan_bucket`
calling it "observably a no-op", but a test explicitly asserts those members resolve, and its file was
not in Scope-Paths.
