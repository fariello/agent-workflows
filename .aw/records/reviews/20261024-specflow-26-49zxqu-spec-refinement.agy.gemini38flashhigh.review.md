### Scope and Verification Summary

1. **Flowchart 7.1 Missing Participant Failure and Partial Roster Decision Diamonds (F-137)**: In Section 7.1 Flowchart 7.1, candidate loops in `Refine_Phase` proceeded linearly to candidate ready states without any branch or decision diamond handling permanent worker failure after exhausting `--max-retries`. FR-30, Table 3.4, and State Diagram 7.3 explicitly define partial roster handling: when a worker fails, if `--allow-partial-roster` was passed, the flow proceeds to `I[Synthesis Stage]` with surviving valid candidates; otherwise it halts in state `partial` (exit 1). Added explicit failure decision diamonds `FailDec1`, `FailDec2`, and `FailDec3` checking `--allow-partial-roster` to route surviving candidates to `I[Synthesis Stage]` or halt in state `partial` (exit 1 via `Halt_part1`, `Halt_part2`, `Halt_part3` entering `Q_halt`).
2. **Flowchart 7.2 Missing Cap-with-Findings Decision Diamonds for --allow-unresolved-findings and Partial Roster Branches (F-138)**: In Section 7.2 Flowchart 7.2: (a) cap-with-findings halt nodes (`RC_solo_halt`, `RC_multi_halt`, `RM_halt`) connected directly to terminal halts with zero decision branches checking `--allow-unresolved-findings`. Under Table 3.4, passing `--allow-unresolved-findings` forces finalization into `reference/` with exit 1; (b) in `Evidence_Phase` (`RE1`, `RE2`, `RE3`), participant failure was unhandled. Added `RCapDec_solo{--allow-unresolved-findings?}`, `RCapDec_multi{--allow-unresolved-findings?}`, and `RSynthCapDec{--allow-unresolved-findings?}` to Flowchart 7.2 routing to destination reference placement with exit 1 or halting in `capped_with_findings`. Added participant failure decision diamond `RFailDec{--allow-partial-roster?}` in `Evidence_Phase` routing surviving candidates to `Reconcile_Phase` or halting in `Stop_partial`.
3. **Flowchart 7.1 Solo Cap Routing to Clean Exit 0 Contradicting FR-11 and Table 3.4 (F-139)**: In Section 7.1 Flowchart 7.1, solo cap decision diamond `CapDec_solo -- Yes --> O_solo` routed to `P_solo`, which terminated at `Q[End: Exit 0 clean]`. However, FR-11 item 6 and Table 3.4 mandate that when `--allow-unresolved-findings` is passed to finalize a capped run with findings into `draft/`, the command MUST exit with code 1 (`findings`), never exit 0 clean. Disambiguated solo cap routing: created node `O_solo_findings[Write Final Candidate Spec to draft/ with Findings Header]` routing to `P_solo_findings[Output aw specs set to-review Command]` and terminating at `Q_findings[End: Exit 0 clean or 1 findings]`.
4. **ERD 6.1 and Persistence Classification Missing Dedicated REVIEW_RECORD Entity (F-140)**: In Section 6.1 ERD, explicit entities existed for `PROMPT_ARTIFACT`, `CANDIDATE_ARTIFACT`, `SIMILARITIES_DIFFERENCES_MATRIX`, `SYNTHESIS_ARTIFACT`, `RESEARCH_REPORT`, and `FINAL_SPEC_OR_REPORT`, but completely omitted `REVIEW_RECORD` (the physical `.review.md` file in `.aw/records/reviews/`). Instead, `ITERATION_FINDING` was connected directly to candidate and research reports without reflecting the physical review record document that encapsulates the review front matter, audited scope, round header, and findings table. Added `REVIEW_RECORD` entity to ERD 6.1 with attributes `id6`, `subject_id`, `subject_type`, `reviewer`, `verdict`, `round_num`, `file_path`, connected via `FLOW_RUN ||--o{ REVIEW_RECORD : records`, `REVIEW_RECORD ||--o{ ITERATION_FINDING : contains`, and critique relationships to `CANDIDATE_ARTIFACT`, `SYNTHESIS_ARTIFACT`, and `RESEARCH_REPORT`. Added `REVIEW_RECORD` row to Table 6.1 persistence classification.
5. **Table 6.2 Artifact Matrix Missing Synthesis and Reconciliation Refinement Critique and Revision Rows (F-141)**: Table 6.2 listed Stage 6 Synthesis (`...-80-<id6>-synth-i0.reconciliation.spec.md`) and Reconciliation (`...-80-<id6>-reconcile-i0.reconciliation.reconciliation-report.md`), but omitted rows for Synthesis Refinement Critique (`...-81-<id6>-synth-iter1.<ace>.<model>.review.md`), Synthesis Revised Candidate (`...-82-<id6>-synth-i1.reconciliation.spec.md`), Reconciliation Refinement Critique (`...-81-<id6>-reconcile-iter1.<ace>.<model>.review.md`), and Reconciliation Revised Report (`...-82-<id6>-reconcile-i1.reconciliation.reconciliation-report.md`). These artifacts are explicitly produced in Worked Inventory 1 (lines 845, 847) and Stage 4/5 of Section 4.3.1. Added explicit rows in Table 6.2 for `6. Synthesis Critique`, `6. Revised Synthesis`, `6. Reconciliation Critique`, and `6. Revised Reconciliation Report`.
6. **State Diagram 7.3 Missing BudgetExhausted and Interrupted Recovery Transitions to Finalizing and Synthesizing (F-142)**: In State Diagram 7.3: (a) `BudgetExhausted` defined recovery transitions to `Dispatching` (via `aw specs flow resume`) and `Synthesizing` (via `aw specs flow merge`), but omitted `BudgetExhausted --> Finalizing: aw specs flow finalize --allow-unresolved-findings` when an operator wishes to finalize the candidate generated up to the budget cap; (b) when a flow entered `PartialRoster`, it checkpointed to `Interrupted`, but State Diagram 7.3 omitted `Interrupted --> Synthesizing: aw specs flow resume --allow-partial-roster` (AT-62), which allows resuming an interrupted partial run directly into synthesis with surviving candidates without re-dispatching initial generation. Added `BudgetExhausted --> Finalizing: aw specs flow finalize --allow-unresolved-findings`, `PartialRoster --> Synthesizing: aw specs flow resume --allow-partial-roster`, and `Interrupted --> Synthesizing: aw specs flow resume --allow-partial-roster` in State Diagram 7.3.
7. **Table 3.4 CLI Synchronization for Prepare, Merge, and Finalize Options (F-143)**: In Table 3.4: (a) `aw specs flow prepare` and `aw research flow prepare` stated that `prepare` "displays the execution plan and turn bounds without dispatching execution", but omitted options `--refine-cap`, `--synth-refine-cap` / `--reconcile-refine-cap`, and `--budget`, preventing users from previewing turn bounds under custom caps and budgets. Also omitted `--from-spec <spec-selector>` on `specs flow prepare`; (b) `aw specs flow merge` and `aw research flow reconcile` omitted `--mode quick|thorough` (which defaults caps to 0 in quick mode); (c) `aw research flow finalize` omitted `--destination reference|archive (default: reference)`; (d) `aw specs flow status` and `aw research flow status` clarified that selector is optional, defaulting to the latest active/recent run in the repository when omitted. Synchronized Table 3.4 options across `prepare`, `merge`, `reconcile`, `finalize`, and `status`.
8. **Intermediate and Synthesized Spec Front Matter Missing - Author: Bullet and Expanding Acceptance Test Coverage (AT-65..AT-68) (F-144)**: Section 6.3 spec schemas omitted `- Author: <runner> (<model>)` for intermediate candidate specs and `- Author: aw specs flow` for synthesized specs, which every spec in the repository carries (`specs.py` convention). Acceptance test matrix lacked explicit coverage for Flowchart 7.1 and 7.2 participant failure and partial roster execution (`AT-65`), Flowchart 7.2 cap-with-findings `--allow-unresolved-findings` routing (`AT-66`), ERD 6.1 `REVIEW_RECORD` entity and Table 6.2 refinement rows (`AT-67`), and `aw specs flow prepare` custom cap bounds calculation and `specs flow merge --mode quick` (`AT-68`). Added `- Author:` to Section 6.3 spec schemas, added acceptance tests `AT-65` through `AT-68` to Section 9, updated Section 6.3 review front matter schema scope to `AT-01..AT-68`, and updated Section 12.1 inspection baseline to include iteration 20 (`ca24f93bccd2f0b0e54ff8349ec515e9f7f218e6`) and iteration 21 (`f10f8f3cd50567f123f81df697efc05128038933`).
