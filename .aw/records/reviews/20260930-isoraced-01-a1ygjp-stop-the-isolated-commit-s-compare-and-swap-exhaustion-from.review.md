## Round 1

Reviewed at HEAD `2183c2110` in an isolated review lane. The plan file was committed and unmodified in the
lane (`git status --porcelain` empty), so no pre-review snapshot was needed. Structural preflight
`aw ipd lint --phase author --agent` reported `conforming` (exit 0, zero findings) BEFORE semantic review;
`--phase review-finalize --agent` reports `conforming` after revision, so nothing here was structural. The
plan is `- Kind: child`, so the `IPD-S407` orchestrator checklist row check does not apply.

DISCLOSURE: the same agent and model authored this plan, so this is a SELF-REVIEW. Its value therefore rests
on RE-EXECUTING the measurements against the real code rather than re-reading the plan's account of them, and
on probing the shapes the plan did NOT measure. Both were done, and the second is where the review earned its
keep.

EVERY MEASUREMENT THE PLAN RECORDS WAS RE-EXECUTED AND ALL HOLD. Against the real `commit_lock.commit_isolated`
in git-backed fixtures under `.aw/state/` (gitignored), with `commit_lock._git` patched to land a peer commit
immediately before the `update-ref`: `status: raced`, the sha populated, `cat-file -e` rc 0,
`merge-base --is-ancestor <sha> HEAD` rc 1, `for-each-ref` listing only `refs/heads/main`, `reflog --all` NOT
mentioning the sha, `fsck` reporting `dangling commit`, and `gc --prune=now` then taking `cat-file -e` to rc 1
with `fsck` silent (F-01). The shipped detail contains both "the work is preserved as commit" and
"cherry-pick or retry" verbatim (F-04). Driving the real `git_commit_helper.offer_commit` with a peer landing
before EVERY `update-ref`: exactly 5 `commit_isolated` invocations, 5 `dangling commit` lines, 1 of 5 named in
`CommitOutcome.message`, `outcome status: error | commit: None`, all 5 resolving to ONE distinct blob, in
0.644s (F-02, F-03, F-10, F-11). The three non-overlapping recovery shapes reproduce exactly as recorded, each
returning `raced` with the work still staged (`A  new.txt`, `M  tracked.txt`, `D  doomed.txt`) and a plain
re-run returning `committed` with the correct HEAD state (F-05). The two lock paths both resolve to
`.aw/state/runtime/locks/ipd_finalize_writer.lock` while `runner_shared.integration_lock_path` resolves
elsewhere, so F-08's and F-09's SAME/DIFFERENT file claims are exact. `ISO_RACED_MAX_ATTEMPTS` is 5 and
`contention_wait.TIMEOUT_SECONDS` is 1800.0. Neither `tests/test_commit_lock.py` nor
`tests/test_commit_isolated_raced.py` exists while `tests/test_git_commit_helper.py` cites the former by name
(F-14). `abandoned_ref_name` does not yet exist in `commit_lock`, so E-03's convergence branch is live.

WHAT REVIEW FOUND IS THAT THE PLAN'S CENTRAL FRAMING IS WRONG ON A SHAPE IT NEVER MEASURED, and that is the
finding. The plan measured three recovery shapes and generalized from them to "this is NOT a data-loss fix",
then built a Goal disclaimer, an E-05 remedy, a gate prohibition and an open-question resolution on that
generalization. In all three measured shapes THE PEER COMMITTED A DIFFERENT PATH. The fourth shape, where the
peer commits the SAME path we are committing, inverts the conclusion: the agent's bytes end up in the stranded
commit ALONE, and the remedy the plan was about to advertise provably does not work. So the plan was about to
replace one false message with another, which for a plan whose entire subject is message honesty is the defect
that matters most. Everything else found was smaller.
