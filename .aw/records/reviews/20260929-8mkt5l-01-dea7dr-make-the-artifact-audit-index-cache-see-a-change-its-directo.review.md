WHAT REVIEW FOUND THAT AUTHORING DID NOT is one substantive HIGH and one gate-level HIGH.

THE SUBSTANTIVE ONE IS THAT THE FIX WIDENS THE INVALIDATION SURFACE, AND THE PLAN NEVER MEASURED THAT. The
recursive walk fingerprints 56 directories while `build_index` enumerates records from only 33, leaving 23
watched-but-not-enumerated directories holding 574 files. `.aw/records/reviews/` alone holds 543 of them, and
`'reviews' in TYPE_PRECEDENCE` is `False` with `build_index` returning zero review records, so that tree is
watched and never indexed. Demonstrated directly: writing one temporary file into `.aw/records/reviews/`
CHANGES the new signature and leaves today's unchanged. The consequence is concrete and recurring: after this
fix, every `/plan-review` that writes a review record discards a cached index that could not have gone stale,
at a measured cost of roughly 92x a cache hit in this lane (a cold `build_index` about 7.4s against a warm hit
about 80ms). The plan's whole framing is "cheaper AND more correct, so there is no trade to adjudicate", and
that framing is incomplete: the signature is cheaper per call while the cache is invalidated more often. THE
TRADE IS STILL RIGHT, and I did not change the design, because a rebuild is slow while the routes it closes
are wrong answers, and because pruning the walk back to the enumerated set would restore exactly the
type-vocabulary coupling whose removal is what closes routes 2 and 3. But it must be STATED rather than
discovered by whoever next profiles `aw runs`, so E-04 now documents it, E-02 measures it up front, E-07
re-measures it after the change and must say whether the trade still holds, and the gate forbids pruning as an
execution-time reaction (PR-003, F-15).

THE GATE-LEVEL ONE IS THAT THE PLAN COULD NOT HAVE REACHED `approved` AS AUTHORED. All three `- Carrier:`
fields held a prose instruction ("A backlog item must be filed at execution recording F-06's measurements...")
rather than a resolvable id6, so `check.ipd-uncarried-obligation` reported it at severity `error`: "3
obligation(s) name no durable carrier: deferred row 1: malformed `Carrier` reference(s) ...". This also
DECIDES OQ-03, which the plan left `open` with `Owner: maintainer`, presenting the timing of those filings as
a free choice between "before" and "at execution". It is not a choice: deferring them is a state the shipped
gate refuses. So I filed all three during review, each carrying its full measurement so it stands alone
without the plan: `ieg7q6` (the in-place `- Id:` route with candidate B's pinned and unpinned results and its
cost), `an1a33` (the wholesale `clear()` eviction, with an explicit note that its perceptibility is NOT
established and must be measured before any promotion to `bug`), and `1sn4h0` (the four deleted verdict tests,
with the P16 triage requirement so they are not restored mechanically). All three resolve through `aw find`,
the rule is silent, and `aw backlog check` reports conformance (PR-001, PR-002, F-16).

ONE CITATION WAS WRONG AND ITS CORRECTION SHRINKS THE BLAST RADIUS RATHER THAN WIDENING IT. F-12 claimed "two
production consumer surfaces" and named `doctor.probe_artifact_status_location_drift`. That symbol does not
exist in `doctor.py` (it raises `AttributeError`); the real probe is `probe_artifact_audit`, and it calls
`audit_tracked_artifact`, whose source contains neither `build_index` nor `find_artifact`. Instrumenting
`build_index` across a full `doctor.probe_artifact_audit(root)` run recorded ZERO calls. So the cache has
exactly ONE consumer, `run_viewer` (`aw runs`), which audits per displayed step. That is a smaller risk
surface than the plan claimed, and it also sharpens F-15: the one consumer is a read-only viewer, so the
spurious invalidations cost latency in `aw runs` and nothing else (PR-004).

TWO SMALLER GAPS. The module does not import `os`, measured from its import block, so E-03's `os.scandir`
instruction as written does not run; I hit this installing the prototype and had to add the import (PR-005).
And E-05's four tests leave the two same-tick COMPOUNDS unasserted, which matters because routes 2 and 3 need
no mtime control, so their tests prove the walk reaches those directories but not that it survives a directory
whose mtime also failed to move. With the mtime pinned, the entry-name tuple is the ONLY component that can
have changed, so a later "simplification" dropping the name tuple while keeping the recursion would pass all
four tests. E-06 adds the two compounds and V-06 requires the pasted failure against exactly that mutation
(PR-006).

ON THE DRIFTED FIGURES, recorded because a reviewer could mistake them for errors: the plan's suite baseline
(`3246 passed`) and F-04's denominator (55 directories on disk, 8 uncovered) both moved in one day, to `3322
passed` and 56 and 9. Neither is a defect. The plan already instructs the executor to RE-DERIVE the suite
baseline in the lane and to compare by node id rather than by total, which is exactly the live-artifact
re-derivation convention, and F-04's load-bearing numbers (47 covered, 4 live records) held to the digit. I
recorded both re-measurements in place so the next reader is not misled by the stale figure (PR-007).
