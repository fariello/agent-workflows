THE PLAN'S METHOD AND ITS RESTRAINT ARE BOTH EXEMPLARY, and I weakened neither. It verified its backlog item
by CALLING the function rather than reading it, which is what caught the item's second half being unsound;
it then graduated one value instead of two and recorded the measurement that justified the split. I re-ran
`audit_step_artifact` against a synthetic repo and reproduced every number it reports, including the
`substantially-complete` result (`location_mismatch=True status_mismatch=True`, identical to a bare
`complete`) that correctly kept half the item from being built. Its `1f9m2j` boundary argument also
re-verified: `run_viewer` really does read only a parent directory name and a `- Status:` regex.

ONE FINDING MATTERS MORE THAN THE OTHER SEVEN. The plan's justification is stated as a TAUTOLOGY, in the
plan and in the backlog item both: an interrupted item's plan "MUST still carry the status it had when the
turn began... There is no other legal value". That is FALSE, and it is load-bearing.
`oc_runipd.reconcile_interrupted` PROMOTES an interrupted item whose plan reached `executed/`, and the
spec-R22 fabricated-success gate REFUSES that promotion for an INDETERMINATE item, leaving the item at
`interrupted` while its plan sits in `executed/` reading `executed`. The runner produces the "impossible"
state deliberately, as a safety feature. The FIX SURVIVES UNCHANGED, because the tolerance arm admits only
in-flight file values and `executed` is not among them, so the row keeps flagging on both axes; but the
REASONING had to be replaced and pinned by a new test case, because a false premise written into a code
comment becomes the next author's evidence, and the next author widening the arm to admit `executed` would
silently suppress the one row spec R22 exists to surface.

TWO OTHER FINDINGS WOULD HAVE PRODUCED FALSE CONFIDENCE. E-04's over-suppression mutation admits `complete`
into the edited arm, but an earlier arm intercepts `complete`, so the mutation is inert: it changes no
behavior, case (c) keeps passing, and it would have been pasted as evidence having proven nothing. And seven
other run statuses share the defect's exact signature, which the plan never mentions, so an executor meeting
them mid-flight had no guidance and a plausible reason to sweep them in.

Eight findings, all FIXED in place, no deferrals. E-item and V-item counts unchanged at four each: the new
test case belongs inside E-03 and the mutation rewrite inside E-04. OQ-01 was `open` with the executor as
owner although the repository answers it in one function call, so it is now resolved by measurement. No
product code was modified.
