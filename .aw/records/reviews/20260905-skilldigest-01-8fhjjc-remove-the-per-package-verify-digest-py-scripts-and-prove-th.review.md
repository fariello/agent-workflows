## Round 1

All claims re-measured at HEAD `484994ec`. `aw ipd lint` conforming at `--phase author` and again at
`--phase review-finalize`. The target plan was committed and unchanged, so the pre-review snapshot was
correctly skipped.

A MEASUREMENT PRECONDITION THAT SHAPED THE WHOLE REVIEW: `.agents/skills` is NOT tracked in this
repository and does not exist in the working tree (`git ls-files .agents` returns nothing; the
directory is absent), and this repo's own committed manifest carries 202 file entries with ZERO skill
rows. The plan's 45 / 135 / 342 figures therefore describe an INSTALLED TARGET, not this checkout.
Every count in this review was reproduced by installing the bundle into throwaway repos outside the
tree. That is now recorded in the plan's conventions section, because an executor who greps this
checkout will get nothing back and could easily read that as the finding being refuted.

WHAT THE PLAN GOT RIGHT, and it is the majority: the artifact really is 45 near-identical 20-line
files; the body really does compute nothing (`observed == EXPECTED_DIGEST` over `argv[1]`); the
frontmatter digest really is a separate mechanism the validator requires and must survive; the
`.agents/skills` and SKILL.md-wording questions really do belong to other owners; and F-5's
correction of the earlier false `check-generated` equivalence claim is exactly the right instinct.
The plan's own insistence on proving coverage BEFORE deleting is what made the two HIGH findings
below findable, so the structure worked even though two premises did not survive contact.

THE TWO THAT MATTER. First, the headline premise was false in a way that would have broken execution,
not merely misdescribed it: there IS an executing caller, and it fails by RAISING rather than by
asserting. Second, the plan validated only a fresh install, which is the one path no real user takes;
the upgrade path deviates three ways, and one of those deviations aborts the install in exactly the
state this checkout is in right now.
