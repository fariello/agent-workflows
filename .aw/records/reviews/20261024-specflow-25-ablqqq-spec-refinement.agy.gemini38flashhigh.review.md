### Scope and Verification Summary

1. **State Diagram 7.3 Missing Turn Budget Ceiling Exhaustion State and Recovery Transitions (F-129)**: Section 4.3.1 (line 311) and AT-15 mandate that when total dispatched turns reach `Budget_Ceiling` (`--budget`), the engine unconditionally halts further dispatch, serializes active state to the run ledger with status `budget_exhausted` (exit 1), and halts automated execution. AT-39 specifies resuming from a budget-exhausted run via `aw specs flow resume <run-id6> --budget <new-budget>`. However, State Diagram 7.3 omitted the `BudgetExhausted` state and its associated recovery transitions. Added explicit state `BudgetExhausted` to State Diagram 7.3 with transitions from `Generating`, `CandidateRefining`, `Synthesizing`, and `SynthesisRefining` on `Budget Ceiling Reached (Exit 1)`, plus recovery transitions to `Dispatching` via `aw specs flow resume (Increased Budget)`, to `Synthesizing` via `aw specs flow merge (Increased Budget)`, and terminal transition `BudgetExhausted --> [*]`.
2. **Flowchart 7.1 and 7.2 Missing Recovery, Partial Roster, and Citation Check Branches (F-130)**: In Flowchart 7.1: (a) all cap-with-findings halt nodes (`CapHalt_solo`, `CapHalt1`, `CapHalt2`, `CapHalt3`, `SynthCapHalt`) connected exclusively to `Q_halt[End: Exit 1 in state capped_with_findings]`, omitting the `--allow-unresolved-findings` branch that routes to final draft placement under FR-11 and Table 3.4; (b) in `Refine_Phase`, if a participant permanently fails after retries, FR-30 allows synthesis to proceed with surviving candidates if `--allow-partial-roster` was passed, but Flowchart 7.1 had no partial roster branch entering synthesis. In Flowchart 7.2: citation verification nodes `RF_solo` and `RF_multi` connected directly to candidate review turns without verifying citations; under FR-16 and Table 3.4, unverified citations halt with exit 1 unless `--allow-unverified` is passed. Added cap decision branches routing `--allow-unresolved-findings` to draft placement `O`, and added participant failure decision branches supporting `--allow-partial-roster` entering `I[Synthesis Stage]` in Flowchart 7.1. Added explicit citation verification decision diamonds `CV_check_solo{Citations Verified or --allow-unverified?}` and `CV_check_multi{Citations Verified or --allow-unverified?}` branching to `Stop_unverified[Halt: Exit 1 unverified citations]` or continuing to review in Flowchart 7.2.
3. **Worked Inventory 1 Incomplete Refinement Cycles, Missing P2 Chunk Index, and Lack of Artifact Traceability (F-131)**: Section 3 item 31 of the prompt explicitly commands: "Require worked inventories for a three-participant run with at least two refinement iterations, a split candidate, synthesis/refinement, and final output, plus one-participant and resumed cases. Trace each final artifact to its retained inputs." In Section 6.4: (a) Inventory 1 (3-Participant Thorough Spec Run) contained only ONE candidate refinement iteration (Iteration 1 Critiques) and NO Iteration 2 revised candidates (`cand-i2`), NO Iteration 2 critiques (`iter2`), and NO synthesis refinement iterations (`synth-iter1`, `synth-i1`); (b) P2's chunk index manifest (mandated by Table 6.2 `cand-index`) was omitted from Inventory 1; (c) Table 6.2 row 7 assigned a hard-coded NN `19` to `Split Part Index`, conflicting with P2's slot-block allocation (`20..29`); (d) Inventories 1, 2, and 3 lacked explicit input-to-final-artifact traceability mappings. Expanded Inventory 1 to include P2 chunk index manifest `...-20-f1c002-cand-index.agy.gemini38flashhigh.spec.md`, chunks `21` and `22`, Iteration 1 critiques (`11`, `23`, `31`), Iteration 2 revised candidates (`12`, `24`, `25`, `32`), Iteration 2 critiques (`13`, `26`, `33`), initial synthesis `80`, synthesis refinement critique `81`, revised synthesis `82`, and added an explicit Input-to-Final Artifact Traceability Matrix for Inventory 1, 2, and 3. Adjusted Table 6.2 row 7 pattern to dynamic `NN` within the modular candidate's slot block.
4. **CLI Resume Command Missing --allow-partial-roster Option (F-132)**: Table 3.4 rows for `aw specs flow resume` (line 204) and `aw research flow resume` (line 212) listed cap and budget override flags, but omitted `--allow-partial-roster`. When an unattended multi-model flow halts in state `partial` (because a participant worker failed and `--allow-partial-roster` was not pre-authorized), State Diagram 7.3 checkpoints the ledger as resumable (`PartialRoster --> Interrupted: Ledger Checkpointed`). Resuming with `aw specs flow resume <run-id6>` without the ability to pass `--allow-partial-roster` left the run stranded and unresumable. Added `--allow-partial-roster (flag: proceed to synthesis/reconciliation with surviving valid candidates)` to `aw specs flow resume` and `aw research flow resume` in Table 3.4.
5. **Missing Worked Inventory for Multi-Participant Research Flow (F-133)**: While Section 6.4 provided worked inventories for specification runs (Inventories 1, 2, 3), it completely lacked a worked inventory for a research flow. None of the research artifact patterns in Table 6.2 (`cand.research-report`, `cand-<subtopic>.research-report`, `verify.prompt`, `reconciliation-report`) were demonstrated in a concrete inventory. Added Worked Inventory 4 to Section 6.4: "Worked Inventory 4: 3-Participant Research Flow with Parallel Investigation, Citation Verification, Reconciliation, and Sharded Reference Finalization", providing an end-to-end trace from brief through evidence collection, citation verification, reconciliation report, and weekly reference shard indexing.

7. **ERD 6.1 Final Entity Provenance Lineage and Operational Ledger Attributes (F-135)**: In Section 6.1 ERD, `FINAL_SPEC_OR_REPORT` had no relationship to `SYNTHESIS_ARTIFACT`, `CANDIDATE_ARTIFACT`, or `RECONCILIATION_REPORT`, appearing disconnected from the intermediate artifacts it promotes. Additionally, `FLOW_RUN` entity attributes omitted operational tracking fields (`budget_ceiling`, `dispatched_turns`, `frozen_commit_sha`). Updated Section 6.1 ERD to add `SYNTHESIS_ARTIFACT ||--o| FINAL_SPEC_OR_REPORT : promotes`, `RECONCILIATION_REPORT ||--o| FINAL_SPEC_OR_REPORT : publishes`, and `CANDIDATE_ARTIFACT ||--o| FINAL_SPEC_OR_REPORT : promotes_solo`. Added `int budget_ceiling`, `int dispatched_turns`, and `string frozen_commit_sha` to `FLOW_RUN` attributes.
8. **Acceptance Test Matrix Scope Expansion (AT-61..AT-64) (F-136)**: Acceptance test matrix lacked explicit coverage for budget exhaustion state transitions (`AT-61`), resuming partially failed flow runs with `--allow-partial-roster` (`AT-62`), research reconcile and decomposed prompt rendering (`AT-63`), and end-to-end research flow artifact inventory validation (`AT-64`). Added acceptance tests `AT-61` through `AT-64` to Section 9, updated Section 6.3 review front matter schema scope to `AT-01..AT-64`, updated Section 12.1 inspection baseline to include iteration 19 (`61fce3bfd53a53c431889ebf3a452973a166928e`), and updated Section 12.2 self-check item.
