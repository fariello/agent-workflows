`runner_shared._read_from_backlog` still yields `None`. F-3: `releases.check_from_backlog(repo)`
returns 0 findings. F-4 and F-7 reproduced by census (538 values, 0 non-retired non-id6, 1 retired,

`- Graduated-To: forkresid`, neither gated). F-6 reproduced as a doubled line. F-8 reproduced (zero

whose direction (ratify single-valued, one shared classifier, SHAPE separate from RESOLUTION) is
right, and which correctly grounds every design choice in the `Graduated-To` precedent.

WHAT REVIEW FOUND WERE TWO GAPS IN THE PLAN'S MODEL OF THE DEFECT, both found by probing rather
than reading, and both changing what execution must do.

THE FIRST IS A SIXTH READER, AND IT IS THE ONE AN OPERATOR ACTUALLY SEES (PR-801).
`check_engine.build_graduation_reverse_index` does NOT go through `_from_backlog_value`: it applies
`_META_FROM_BACKLOG_RE.finditer` plus its own sentinel filter, deliberately, because it indexes
EVERY source bullet rather than the first. So E-02's list of readers, which re-points
`_from_backlog_value` and three others, leaves it untouched. Measured on a scratch tree with one
plan carrying the no-space form: it indexes `('backlog', 'dstnso,8hx3g3')`. That key is not inert.
`check_engine.graduation_cluster` reads this index, `cli.py` calls `graduation_cluster` for the
`aw graduation` verb, and `runner_shared.summarize_graduation_cluster` calls it for the runner's
pre-graduation guard, whose own docstring insists "NO CLUSTER LOGIC IS DUPLICATED". So today the
defect is not only invisible to the gate, it is VISIBLE AND WRONG on the one surface a human
consults before graduating a source. The plan would have shipped a fix leaving that half live while
its own tests passed. What makes this a gap rather than a defensible scope choice is that the
plan's OWN cited guard already names the reader: `test_regression_guard_all_readers_honor_schema_sentinels`
enumerates six readers and this is number 4. E-02, E-06, V-02, the Goal, the `- Concern:` and two
new conventions bullets now carry it, and a second revert probe in V-06 makes it impossible to
satisfy the test file with that reader still broken.

THE SECOND IS THAT ONE OF THE TWO BAD FORMS IS ALREADY REPORTED (PR-802). The plan frames E-04 as
adding a rule to catch something invisible. Measured: `releases.check_from_backlog` today reports
`check.from-backlog-dangling` for the NO-SPACE form, because `_ITEM_FROM_BACKLOG_RE` captures the
junk token and it is then absent from `known`. Only the SPACED form is invisible, which is why F-3
sees zero findings against a corpus whose single offender is spaced. E-04 is therefore a
RECLASSIFICATION as much as an addition, and that matters twice: the two rules must be mutually
exclusive per artifact (classify SHAPE first, ask RESOLUTION only of a usable id6), and any
existing test asserting `-dangling` for the no-space form is asserting the OLD classification and
must be updated rather than preserved. An executor reading "add a rule, do not widen `-dangling`"
would plausibly have produced an artifact reported under BOTH rules. V-04 now requires the
no-space case be shown BEFORE and AFTER so the move is visible rather than inferred.

A THIRD PROBE CORRECTED AN EVIDENCE CELL RATHER THAN A DESIGN (PR-804). F-6's evidence cites
`ipd_schema.parse_metadata_block` returning a `duplicate field` MetaError, but that function takes a
LINE SEQUENCE ("the lines BETWEEN the H1 and the first H2"), and passing the document returns
`({}, [])`, which reads as "no error". The CLAIM is true when the function is called per its
signature, which I verified, but V-03 as written would have been satisfiable by a call that proves
nothing, and an executor reproducing F-6 literally could have concluded the finding was false. Both
the finding and V-03 now name the correct call shape.

THREE SMALLER CORRECTIONS. The plan's must-stay-green baseline for
`tests/test_check_engine_release_gate.py` was already stale (27 authored, 30 measured), which is a
live count used as a bar and therefore governed by the repository's own re-derivation convention.
`selectors._TYPED_SUBJECT_RE` is named in F-2 as a disagreeing reader but appears in neither the
scope paths nor any E-item, which reads as an omission until you measure it: it is already CORRECT
for its purpose (it refuses a multi-token value on both forms, which is the right answer for a
mutation-ownership test) and re-pointing it would teach one field's classifier to a six-field
predicate. And the `duplicate`-substring prohibition E-04 must obey is real but its cited home,
`tests/test_graduation_view.py`, does not exist; the live assertion is in
`tests/test_check_engine_spec_criteria.py`, and since the stale pointer lives in a comment inside a
file this plan already declares, E-07 now fixes the pointer.

WHAT I DID NOT CHANGE, stated because a reviewer's silence is not evidence of having looked. The
refusal to make the field multi-valued is correct and well argued; I re-derived its factual basis
(F-14) rather than accepting it. The corpus-independence design for the malformed finding is
correct and correctly justified by `check_from_backlog`'s own "do not spread this gap" docstring. The
decision to resolve `nmlx47` by DELETING the value rather than keeping one of two sources is right
on the evidence, and E-05's ordering after E-04 is right for the reason the plan gives. The
single-child-not-a-Set cohesion argument holds. No spec amendment is owed, and I checked rather than
accepting it.

Bare suite at review HEAD before any probe: `3387 passed, 2 skipped, 3 warnings in 63.71s`, 207

files named in the plan's required-tests list: `82 passed in 14.53s`. No production file was
