## Round 1

Reviewed at HEAD `b9944bfc` in an isolated review lane. The plan file was committed and byte-identical to
the lane input (`diff` reports no difference), so no pre-review snapshot was needed. Structural preflight
`aw ipd lint --phase author --agent` reported `conforming` (exit 0, zero findings) BEFORE semantic review;
`--phase review-finalize --agent` reports `conforming` after revision, including the new `E-08`/`V-08` pair.

THE PLAN'S DIRECTION IS RIGHT AND ITS BEST ARGUMENT SURVIVES SCRUTINY. The backlog item asks for the rename
rewriter to be extended over the shipped package; the plan refuses and builds a detector instead, because the
package's citations include a runtime path construction. I read that site: `runner_shared.py` builds
`repo / "tools" / "ipdrunner" / "20260823-pending-ipds-overnight-execution-runbook.md"` and gates it on
`if default_rb.is_file()`, so a rewrite there would silently change or disable the runner's default runbook.
That is a concrete, locatable hazard and it justifies detect-over-rewrite on its own.

I also confirmed the half-built seam the plan exploits. `dead_filename_citations` accepts `scan_roots` but
calls `iter_scan_files(repo_root, scan_roots)` with no `suffixes`, taking the `(".md", ".txt")` default, so
aiming it at the package can never open a file. Measured: it returns `0` findings for BOTH `record_type="plans"`
and `"specs"` over `scan_roots=("agent_workflows",)` while four real danglers sit there. A detector that
answers zero because it opened nothing is the worst failure mode available, and E-02 is a genuine one-line
completion rather than new machinery. Worth noting the rewriter ALREADY reads `.py` (it passes
`_REFERENCE_TEXT_SUFFIXES`), which is why it rewrites `tests/` but not the package; the asymmetry is purely
the scan-root list, exactly as F-1 says.

F-3's token totals reproduced EXACTLY (61 in `agent_workflows/**/*.py`, 22 in `tools/**/*.py`), F-8's
in-tree objection is verbatim as quoted, F-10's two truncated near-misses both resolve to the real records
named, and F-11's type-filter asymmetry is real.

WHAT REVIEW FOUND, all of it from running the plan's own E-01 census rather than from reading. The census is
what exposed both serious problems, which is a point in the plan's favour (it prescribed the right first
step) and against it (it did not run it to conclusion before drawing its numbers).

FIRST, THE DETECTOR AS SPECIFIED COULD NEVER EXIT ZERO. All 21 dangling full-filename tokens in `tools/` are
invented fixture names inside three test files (`tools/test_agy_run.py`, `tools/awphysical/test_awphysical_tools.py`,
`tools/ipdrunner/test_runagy.py`) which MUST NOT resolve: `20260816-test-01-abc123-test.md`,
`20260815-x-01-x-thing.md`, `20260824-authsystem-01-p00001-login.ipd.md` and so on. E-04 requires the mode to
"exit nonzero when any finding exists so it is usable in a script"; including these pins it at nonzero forever.
The plan treated `tools/` as under-reported EXPOSURE ("or it under-reports by a quarter") when it is in fact
pure NOISE. Sibling plan `2wmwf7` independently measured the identical 21 and wrote them off as "deliberate
TEST FIXTURE paths that SHOULD NOT resolve", so the correct treatment was already established in-tree.

SECOND, ONE OF THE FIVE NAMED DANGLERS IS NOT DANGLING. `runner_shared.py`'s runbook citation resolves on disk
at `tools/ipdrunner/20260823-pending-ipds-overnight-execution-runbook.md`; `find` locates it and the code's own
`is_file()` guard succeeds. It is reported only because the existence set comes from `selectors.record_dirs`,
which covers the eight record trees and not `tools/`. So the plan's headline count is 4, and the fifth entry is
an artifact of the measurement rather than a defect in the tree.

THIRD, AND THE ONE THAT WOULD HAVE DONE REAL DAMAGE: E-05 was permitted to write "there is no successor" into
`comms.py` on the strength of F-10's claim that none exists. The record does exist, renamed onto the research
grammar as `.aw/records/research/20260714-same-box-agent-wakeup-mechanisms-00-j2000q-same-box-agent-wakeup-mechanisms.research-report.md`,
findable by slug once the old path is known to be gone. Acting on that permission would have replaced a stale
statement with a fresh false one in shipped source, which is strictly worse than the defect being fixed.
