### Scope and Verification Summary

1. **Missing Prompt Artifact HTML Metadata Comment Schema in Section 6.3 (`check.prompt-metadata-missing` / I-09 Compliance) (F-97)**: Identified that Section 6.3 provided front matter YAML schemas for specs, review records, and research reports, but completely omitted schemas for prompt artifacts (`.prompt.md`). In `agent_workflows/check_engine.py:1826-1835`, `check.prompt-metadata-missing` strictly enforces that every prompt artifact's first line must begin with `<!-- aw-prompt:` and carry required pipe-separated metadata fields (`Kind`, `Id`, `Set`, `Status`, `Created`, `Author`, `Targets`), parsed via `prompts_index._parse_metadata_comment()`. Without an explicit normative schema in Section 6.3, prompt staging engines generating prompt artifacts during `--prepare-only` or live execution would trigger `check.prompt-metadata-missing` and `check.prompt-id-mismatch` repository check failures. Added the normative HTML comment frontmatter schema for Prompt Artifacts to Section 6.3.
2. **Invalid Front Matter Syntax, Non-Enum Outcome, and List Type Failures in Research Schemas (`research_contract.py` Invariant Violation) (F-98)**: Identified that the research report schemas added in Section 6.3 contained three critical violations of `agent_workflows/research_contract.py`:
   - Syntax: Formatted as bullet points (`- id: <id6>`) instead of a `---` delimited front matter block, which `research_contract.parse_frontmatter()` requires.
   - Outcome enum: Showed `- outcome: <outcome_summary>`, whereas `OUTCOMES` in `research_contract.py:166` is strictly closed to `("adopted", "rejected", "informational", "none-yet")`. A free-form summary triggers `'outcome must be one of [adopted, informational, none-yet, rejected]'` during `validate_frontmatter()`.
   - List typing: Showed `- consumed-by: null`, which `parse_frontmatter()` parses as scalar string `"null"`, failing `validate_frontmatter()` with `'consumed-by must be a list'`. Empty list must be `consumed-by: []`.
   - Order typing: Documented scalar string `order: NN` (`_ORDER_RE = re.compile(r"\A\d{2}\Z")`), ensuring quotes do not produce malformed order tokens.
   Replaced bullet blocks with conforming `---` delimited YAML front matter blocks for Candidate Research Reports and Reconciled Research Reports in Section 6.3.
3. **State Diagram 7.3 Missing Single-Participant Bypass Transition to Finalizing and PartialRoster Resumability (F-99)**: Discovered that State Diagram 7.3 showed `CandidateRefining` and `CappedCandidate` unconditionally transitioning to `Synthesizing`, directly contradicting FR-06, Flowchart 7.1, Section 6.4 Inventory 2, and Section 13.1, which specify that single-participant runs (`N = 1`) bypass multi-candidate diffing and synthesis, transitioning directly from candidate refinement to finalization. Added direct transitions `CandidateRefining --> Finalizing: Single Participant Converged (N=1)` and `CappedCandidate --> Finalizing: Single Participant Cap Proceed (N=1)`. Furthermore, added `PartialRoster --> Interrupted: Ledger Checkpointed (if resumable)` to model resumption under FR-30/FR-31.
4. **Table 6.2 Hardcoded Prompt NN Inconsistency vs Inventory 1 and Dynamic Prompt Phasing (F-100)**: In Table 6.2, row 1 Gen Prompt hardcoded pattern `01`, row 1 Refine Prompt hardcoded `02`, row 1 Synth Prompt hardcoded `05`, and row 3 Verification Prompt hardcoded `06`. In multi-participant runs (Section 6.4 Inventory 1), generation prompts across participants occupy `01..04` (`f1p001`..`f1p004`), and Section 4.6 FR-26 notes that subsequent stage prompts are generated dynamically. Hardcoded numbers in Table 6.2 contradicted Inventory 1 and caused NN allocation collisions. Updated prompt rows in Table 6.2 to use dynamic range `NN in 01..09`.
5. **CLI Options Gaps: Missing `--mode quick\|thorough` on `prepare` and Title/Slug on Standalone `merge`/`reconcile` (F-101)**: `aw specs flow prepare` and `aw research flow prepare` omitted `--mode quick\|thorough`. Because `--mode` determines the default participant roster (`preferred-three` vs `quick-solo`) and execution bounds, `prepare` cannot accurately render Stage 1 prompts or display execution bounds without knowing the mode. Furthermore, `aw specs flow merge` and `aw research flow reconcile` accept `<setid> (or <candidate-paths...>)` to synthesize independently, but omitted `--title <str>` and `--slug <slug>`, preventing users from specifying or overriding final artifact names when synthesizing from standalone candidate paths. Added `--mode quick\|thorough` to `prepare` and `--title`/`--slug` to `merge` and `reconcile` in Table 3.4.
6. **Ergonomic CLI Selector Asymmetry: Support `<setid>` on `finalize` and `cancel` (F-102)**: In Table 3.4, `aw specs flow resume` and `aw research flow resume` accept `<flow-run-id6> \| <setid>` (resolving latest run for set). However, `finalize` and `cancel` accepted only `<flow-run-id6>`, forcing users and agents to inspect internal JSON run ledgers under `.aw/records/runs/` just to finalize or abort a known Set. Updated `aw specs flow finalize`, `aw specs flow cancel`, `aw research flow finalize`, and `aw research flow cancel` in Table 3.4 to accept `<flow-run-id6> \| <setid>`.
7. **Metastore Spec `4sd62s` Coordination and Refinement Review Event Integration (F-103)**: The metastore spec `4sd62s` (at `.aw/records/specs/reviewed/20260925-metastore-01-4sd62s-artifact-metadata-store.spec.md`, amended 2026-10-24) explicitly coordinates with `18hh1u`: it defines that review events carry `kind: gate | refinement`, where `refinement` events carry refinement verdicts (from the registry-owned vocabulary) and reference the refinement review record via `review_ref: <own-id6>`. Added `4sd62s` coordination to Section 2.2 integration seams, Section 11 Phase 1, and Section 12.1 source inventory.
8. **Acceptance Test Matrix Coverage Expansion (F-104)**: Added acceptance tests `AT-45` (prompt artifact HTML metadata comment validation against `prompts_index` and `check.prompt-metadata-missing`), `AT-46` (candidate and reconciled research report front matter validation against `research_contract.validate_frontmatter()`), `AT-47` (`<setid>` selector resolution on `finalize` and `cancel`), and `AT-48` (`--mode quick` handling in `prepare`), expanding audited scope to `AT-01..AT-48`.
