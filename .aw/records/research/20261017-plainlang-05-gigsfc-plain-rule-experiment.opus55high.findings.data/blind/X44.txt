Some context first. The work is one "plan," with ID 7hvkk0. A plan is a unit of changes produced by an automated coding agent. Before the changes are merged, automated checks run the test suite on the merged code. If the checks decide the merged code is broken, they mark the plan "fail-merge." That happened here, but all 745 tests passed.

**What happened, in order**

1. The tests ran on the merged code, and all 745 passed.
2. The repository's test setup file, `conftest.py`, includes a time limit. On a machine with 12 or more CPUs, if the core tests take longer than 30 seconds, it marks the whole run as failed with exit code 1, even when every test passed.
3. The machine was overloaded. Four overnight automated runs were going at once. The load average (the number of processes running or waiting for CPU) was 34 on 12 CPUs, roughly three times what the machine can handle.
4. Because of that load, the core tests took 47 seconds on the merged code. That is over the 30-second limit, so the run exited with code 1.
5. The merge checks saw exit code 1 and treated the merged code as failing ("red"). They sent the work back to the agent for fixes twice, which used up both allowed attempts.
6. The agent reported that the failure was "not mine." That was correct: no code change could have fixed it.
7. The plan's changes did not cause the failure. The code before the merge failed the same way, and its core tests took even longer: 68 seconds.
