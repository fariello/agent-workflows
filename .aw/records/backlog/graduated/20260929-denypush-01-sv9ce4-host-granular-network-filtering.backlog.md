Filed AT AUTHORING TIME rather than by the Set's closeout plan deliberately: a carrier that only exists if the Set executes is exactly the obligation-loss this Set was created to fix, when plan `4h7tt0` declined a carrier for the sandbox work and backlog `oq05nc` had to be filed later to recover it. WHY THIS IS NEEDED, measured in research `uq4y6q`: Landlock ABI 4 CAN deny a TCP connect, two-sided (an allowed connect succeeded and a denied one returned `PermissionError(13)`), and one ruleset carries both filesystem and network rules, so the existing `landlock_bootstrap_source` extends in place. But `landlock_net_port_attr` is `{allowed_access, port}` with NO ADDRESS FIELD (measured: 16 bytes; with port 443 allowed, both `140.82.113.4:443` and `1.1.1.1:443` connected, while `:22` was refused). So a Landlock rule cannot separate a git remote from the model API, because both are TCP 443. Since `oc_runipd._apply_execution_profile` wraps the argv of the agent process itself, and that process needs the model API, a port-only partition has two settings and neither is the goal: allow 443 and push works too (no boundary), or deny 443 and the agent cannot run (no product). WHAT WOULD CLOSE IT: a network namespace plus a filtering proxy that allows the model endpoint and refuses git remote hosts BY HOST rather than by port, probed BY ATTEMPT exactly as `supports_os_sandbox` is. WHY IT IS HARD, also measured: on the measuring host `bwrap`, `unshare` AND `slirp4netns` were all installed yet `unshare -Urn --map-root-user true` failed with `write failed /proc/self/uid_map: Operation not permitted`, so this is per-host capability work and presence proves nothing. SIZE AND POSTURE: this is the `1o4eif`-magnitude security-boundary project backlog `d07nz2` predicted and should not be picked up casually; priority is low DELIBERATELY because nothing is unsafe today (no capability claims push denial, so the descriptor fails CLOSED). This is a missing capability, not a live hole. THIS IS THE PRECONDITION for any future `supports_deny_push` field and for reintroducing a `RUN-NO-PUSH`-shaped finding code in spec 4.2, which backlog `oq05nc` gates on a real probe existing; note `run_evidence.validate_finding_table` also hard-fails on a code count other than 12. DO NOT bind any push-denial claim to the mere PRESENCE of a proxy, a namespace tool, or a config flag: forbidden in writing in `host_sandbox_profile`'s module docstring and again in `run_evidence`'s retirement comment, and it would convert today's safe fail-closed state into a fail-OPEN checker.
