THE DETECTION WAS NEVER THE PROBLEM. 'python -m agent_workflows attention --check --agent' is wired in CI as a fail-closed job ('.github/workflows/tests.yml', job 'attention-check'), the duplicate-id rule is emitted with a non-info severity, artifact_core.drift_exit_code returns 1 for it, and I verified the real process exit code IS 1 at the corrupted origin/main in a clean detached worktree. The first duplicate entered at 2c316ef0 (2026-09-20 03:11) and 143 further commits reached origin/main afterwards, so the attention job was RED for roughly two days and work continued past it. A gate that only speaks after the corrupt commit is already pushed cannot prevent the corruption, it can only report it, and a gate that stays red across 143 commits stops being read at all - which is the same 'trains people to ignore the rule' failure this repository already records for other false-positive checks. THE ASYMMETRY IS THE DEFECT: an artifact WRITE (aw oc run's backlog close, via oc_runipd.commit_backlog_close -> git_commit_helper.offer_commit) can commit a tree that violates a contract the repository already knows how to check, and nothing consults that checker at write time. The repo has FOUR opt-in pre-commit hook helpers for exactly this class (engine.create_backlog_close_gate_hook, create_dependency_gate_hook, create_precommit_scope_gate_hook, create_prepush_authorization_gate_hook) plus the shared idempotent no-clobber wiring helper engine._wire_optin_precommit_hook, and NONE of them checks cross-tree record integrity. SCOPE A FIX SHOULD CONSIDER, in increasing strength: (i) have the RUNNER assert record integrity for the ids it touched immediately after its own commit, since it already knows which id6 it wrote and a scoped check is cheap - this is the narrowest fix and would have caught all 36 at the moment each was created; (ii) an OPT-IN pre-commit hook via the existing helper that refuses a commit introducing a duplicate id6 among the STAGED artifact paths (scoped to staged paths, not a whole-tree walk, so it stays fast); (iii) make a red attention gate visible where work is actually dispatched, i.e. have 'aw oc run'/'aw agy run' report at startup that the cross-tree view is currently INVALID and name the rule ids, so an operator or agent is told before spending a night's compute on top of a known-broken board. RECOMMENDATION: (i) plus (iii). (i) is the fix that makes the specific class impossible to accumulate, and (iii) addresses the two-day blindness directly without adding a new refusal that could wedge a commit. (ii) is defensible but note its honest limits, already stated in this repo for its siblings: git hooks are local, are not cloned by default, and are skippable with --no-verify, so the portable authority remains the aw check rule plus CI. DO NOT fix this by making the CI gate louder alone: the gate was already correct, already fail-closed, and already red.
