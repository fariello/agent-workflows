## Workflow history
- 2026-09-20 created (aw backlog): Found while establishing the bare-suite baseline for plan wenmg4 inside a runner-created lane worktree. THE SYMPTOM: 'tests/test_turn_bounds.py::TestArmedForEveryUnattendedTurn::test_the_permission_policy_by_contrast_IS_isolation_scoped' FAILS on an otherwise clean tree (measured at 007d05e1 with no local edits: '1 failed, 7597 passed, 3 skipped, 2 xfailed'). THE CAUSE, proven rather than guessed: the test asserts that a NON-isolated turn receives no permission-denial policy, checking 'OPENCODE_CONFIG_CONTENT not in main_env'. It reads the AMBIENT environment, and inside a contained worker lane that variable is already set by the harness running the agent. Ran the identical node with the variable unset and it PASSES: 'python3 -m pytest <node>' -> 1 failed, while 'env -u OPENCODE_CONFIG_CONTENT python3 -m pytest <node>' -> 1 passed. WHY THIS IS A DEFECT AND NOT JUST AN ODDITY: every agent turn the runners dispatch executes inside exactly such a lane, so the repository's own suite has a guaranteed false failure in the environment where agents are told to run it and to paste the output. That imposes a real cost on a user (an agent, and then the human reading its report) who must diagnose a failure that is not theirs; every executing agent pays it independently, and an agent who does NOT diagnose it may either report a spurious regression or, worse, 'fix' code that is correct. It also weakens the delta-by-node-id criterion plans rely on, because the baseline is environment-dependent. LIKELY FIX DIRECTION, for a maintainer to rule on: the test should control the variable it asserts on rather than inheriting it, e.g. clear 'OPENCODE_CONFIG_CONTENT' from the environment it builds the non-isolated case in (monkeypatch.delenv or an explicit env dict), so the assertion tests the code under test rather than the ambient shell. Note the assertion itself appears CORRECT and should not be weakened or deleted; only its environmental isolation is at fault. Gated on the next release because it is a reproducible false failure on the documented happy path for running the suite.
