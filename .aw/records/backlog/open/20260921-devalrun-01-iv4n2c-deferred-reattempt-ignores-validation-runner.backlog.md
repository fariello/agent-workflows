## Workflow history
- 2026-09-21 created (aw backlog): MEASURED 2026-09-21 while executing plan daexj1 E-03. runner_shared.reattempt_deferred_integrations declares 'validation_runner_for: Callable[[Mapping[str, Any]], Any]' as a REQUIRED keyword-only parameter (runner_shared.py:3586) and NEVER CALLS IT: grep for 'validation_runner_for' across agent_workflows/ and tests/ returns exactly three hits, the declaration plus the two host call sites that dutifully pass a lambda (oc_runipd.py:2727, agy_runipd.py:1639), and zero call sites inside the function body. WHY IT IS A DEFECT AND NOT MERELY DEAD CODE: the function's own docstring says 'EVERY RE-ATTEMPT GOES THROUGH integrate, i.e. through integrate_lane_branch and therefore through orchestrate_isolation.execute_merge_and_revalidate_gate'. It reaches the gate through the injected 'integrate' closure, which each host builds with its OWN validation runner, so the runner actually used is whatever that closure closed over and the explicitly injected one is discarded. Today those happen to be built from the same factory, so the bug is LATENT rather than active; the hazard is that the signature ADVERTISES a per-item choice the body does not honor, so a caller that passes a deliberately different runner for a re-attempt (a stricter one, or a cheaper one) gets silently ignored. That is the shape of defect this repository has measured repeatedly: an injection that looks wired and is inert, exactly like the constant-True full_validation_runner daexj1 E-03 just replaced and like the GATE_ANSWERS vocabulary that shipped inert at 395fc06b with nothing reading it. DISCOVERED while wiring the suite checker into the validation-runner factory: I passed suite_check at both of those call sites for correctness, and the parameter is still discarded, so the deferral ladder's re-attempts inherit their revalidation from the 'integrate' closure rather than from the parameter named for it. A FIX MUST DECIDE which is authoritative: either call validation_runner_for(item) and hand its result to 'integrate' (making the parameter mean what it says), or delete the parameter and the two lambdas that feed it and state in the docstring that the injected 'integrate' owns revalidation. Do NOT leave it accepted-and-ignored. A regression test should assert the injected runner is actually invoked for a re-attempt, since nothing currently would notice its removal.
