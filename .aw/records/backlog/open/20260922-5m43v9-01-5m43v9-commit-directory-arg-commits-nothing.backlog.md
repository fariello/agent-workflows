## Workflow history
- 2026-09-22 created (aw backlog): Found while executing plan 8u6770 (planprio Order 02). THE DEFECT: git_commit_helper.offer_commit stages the caller's paths with 'git add -- <paths>', which git resolves RECURSIVELY for a directory, then computes 'our_staged = set(_staged_paths(repo_root)) & set(rel_paths)'. _staged_paths returns FILE paths while rel_paths holds the DIRECTORY the caller named, so the intersection is EMPTY and the verb returns STATUS_NOTHING_TO_COMMIT ('nothing to commit: requested paths have no staged changes', git_commit_helper.py:650-660) having staged the files and committed none of them. MEASURED at HEAD e96dc154 in a two-file throwaway repo: with one modified file under .aw/records/plans/pending, 'aw commit --no-plan -m msg -- .aw/records/plans/pending' exits reporting nothing to commit, while 'git add -- .aw/records/plans/pending' on the same tree stages that file correctly and 'aw commit --no-plan -m msg -- .aw/records/plans/pending/a.ipd.md' (the explicit file) commits it. So the directory argument is valid to git and is dropped only by the intersection. WHY IT MATTERS: a directory is the NATURAL argument, because a plan's own '- Scope-Paths:' is routinely a directory (8u6770 declares exactly '.aw/records/plans/pending'), and AGENTS.md instructs every agent to commit through 'aw commit'. An agent that passes its declared scope path therefore gets a confusing refusal on a tree that genuinely has 31 modified files in scope, and the plausible next move is to reach for raw git, which is precisely the path the tooled-commit rule exists to keep agents off. It is fail-CLOSED (nothing is committed, nothing is corrupted), which is why this is high and not a blocker. WORSE, THE PREVIEW DISAGREES WITH THE REAL RUN: 'aw commit ... --no-commit -- <dir>' reports 'skipped: --no-commit requested', i.e. a clean preview, for the exact invocation that then refuses, so the dry run cannot be used to discover the problem. FIX SHAPE: expand each requested path to the file paths git actually staged under it before intersecting (or intersect by path-prefix rather than equality), so a directory argument behaves as a caller reasonably expects. Do NOT fix it by widening the commit to everything staged: the intersection is the guard that stops a co-worker's staged change being swept in, and it must keep that property. Note the same rel_paths/staged-paths mismatch is present in commit_lock.commit_isolated, which mirrors the caller's paths into an isolated worktree file-by-file ('src.exists()' is false for nothing, but 'shutil.copy2' on a directory raises), so both layers need the same expansion.
