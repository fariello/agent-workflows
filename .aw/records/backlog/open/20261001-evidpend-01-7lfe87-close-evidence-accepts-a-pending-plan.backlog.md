'aw backlog set done 2wae2x --evidence .aw/records/plans/pending/20261001-a2zpzq-01-ayhveg-...ipd.md --dry-run --agent' returns outcome clean, exit 0, findings 0, on an item carrying '- Blocks-Release: next'. The cited plan is in pending/ and carries '- Status: to-review', i.e. nothing has shipped. THE DEFECT: check_engine.resolve_evidence_artifact tests only that the citation is safe, in-tree, EXISTS, and lives under '.aw/records/' or '/.agents/'; it never reads the cited artifact's lifecycle status or disposition directory. So the SATISFIED route accepts a plan that is pending, draft, or not-executed. WHY THAT MATTERS: the HANDOFF route deliberately requires EVERY same-gate From-Backlog carrier to be executed/implemented (its refusal text is 'the work has not shipped (carrier is not executed/implemented)'), so the two routes to the same conclusion disagree and the weaker one is reachable with a single flag. The gate exists to stop a release shipping with a live blocker silently closed, which is exactly what a pending-plan citation permits. NOT A DUPLICATE of the deliberate permissiveness the function documents: its own docstring describes the accepted value as 'an executed IPD, a records file, or another committed doc' and says it generalizes the specs predicate so a NON-IPD item (README/research/prompt/check work) can be closed with a cited artifact. Widening the ARTIFACT TYPES is the intended generalization; accepting a NON-TERMINAL PLAN is not, and the docstring's own words ('an executed IPD') assert the opposite of the measured behavior. FIX SHAPE, and the choice needs recording: when the citation resolves to a PLAN, require a terminal disposition (executed/) rather than mere existence, while leaving a non-plan records artifact resolvable as today; specs' stricter executed-IPD-only predicate is the existing in-repo model. Do NOT simply forbid plan citations, which would remove the legitimate 'closed by this executed plan' route.
