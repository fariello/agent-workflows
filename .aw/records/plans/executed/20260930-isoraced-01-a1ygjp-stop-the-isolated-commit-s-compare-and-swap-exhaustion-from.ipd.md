## Goal

Make the work that `commit_isolated`'s compare-and-swap strands FINDABLE and NAMEABLE, and make the message the operator actually reads TRUE.

WHAT THIS GOAL CLAIMS, AND ON WHICH SHAPE, because review measured that the answer DIFFERS by shape and the plan originally asserted only the benign half (F-15, F-16). There are two, and the fix is worth doing for both:

ON A NON-OVERLAPPING RACE (the peer commits a DIFFERENT path) this is a DIAGNOSABILITY AND HONEST-REPORTING fix and nothing more. The caller's bytes are still on disk, measured on all three shapes (new file, tracked modification, deletion), and a plain re-run commits them correctly, so nothing here rescues content that would otherwise be gone. This is the shape the backlog item anticipated and it is why the plan does not simply copy `hf76th`'s remedy.

ON AN OVERLAPPING-PATH RACE (the peer commits THE SAME PATH) it IS a data-loss fix, and retention is the only thing that preserves the bytes. Measured at review: the peer's commit becomes HEAD, the shared working tree holds the PEER's content with `git status --porcelain` EMPTY, and the agent's bytes exist ONLY in the dangling commit, which `gc --prune=now` collects. Through `offer_commit` the outcome is `nothing-to-commit` naming NO sha, and a plain re-run of the verb reports `nothing to commit` instead of recommitting. So on this shape the "just re-run" remedy does NOT work and `hf76th`'s framing DOES apply. Its reach is bounded and the bound is measured: an integration publish cannot produce it, because `git merge --ff-only` refuses over a dirty or staged overlapping path, so the reachable producer is a hand-run `git commit` in the shared tree (F-16).

WHAT THE GOAL STILL DOES NOT CLAIM: it is not a concurrency fix. The retry already lands the work in the ordinary case and this plan leaves the retry, the attempt cap and the wait budget exactly as `9bq5o4` set them. What changes is only what survives, what the caller can name, and what the message says.

## Project conventions discovered (Step 0)

- A THROWAWAY WORKTREE PLUS A REF MOVE IS THE ESTABLISHED SELF-COMMIT MECHANISM, and `commit_isolated` is its compare-and-swap variant. Its docstring records why the CAS exists ("A blind `update-ref` WOULD discard a peer commit that landed meanwhile ... That hazard is real: it was reproduced"), so the CAS itself is correct and this plan changes only what happens to the commit when the CAS loses.
- `commit_isolated` AND `coordinator_worktree` ARE DELIBERATE SIBLINGS, NOT DUPLICATES, and both strand a commit on a failure arm. `coordinator_worktree`'s is `c8ioct`'s subject; this plan takes `commit_isolated`'s, which that plan explicitly filed out of scope with `Carrier: 0ndipg`. The two fixes share a namespace and a name function by design and must not invent two.
- A SINGLE SOURCE FOR A DERIVED STRING IS THE HOUSE PATTERN whenever a writer and a reader must agree; `artifact_core.finalize_commit_subject` records the reasoning (the gate and the run viewer both MATCH what the transaction produces, and a hand-written copy drifts silently). That is why E-03 routes the ref name through one function shared with `c8ioct`.
- APPENDING TO A `NamedTuple` IS A DOCUMENTED CONTRACT HERE, NOT A PREFERENCE. Both `IsolatedCommitResult` and `CommitOutcome` already carry appended-with-default fields and both docstrings state why: callers unpack positionally, so a field inserted in the middle would silently reassign every unpack. E-04 follows that exactly.
- GIT'S EXIT CODE, NEVER ITS PROSE, DECIDES AN ARM (`ReconcileLanding`'s docstring states it, and `commit_isolated` already classifies its own arms on rc). Any reachability check this plan adds uses `cat-file -e` / `merge-base --is-ancestor` rc rather than matching git's wording.
- FAIL-SOFT IS CORRECT FOR HOUSEKEEPING INSIDE AN ALREADY-FAILING OPERATION, and the repository does this deliberately: escalating over a regenerable generated view "would block an operator for no safety gain" (quoted string located in `agent_workflows/ipd_lifecycle.py`; review corrected the symbol attribution, which originally named `_rollback_precommit`'s docstring, F-19b). E-03's retention and its prune are the same class, hence both fail soft.
- TESTS ASSERT OUTCOMES, NEVER CODE STRUCTURE, per the execution contract: no `inspect`, `ast`, regex or substring search over production source, and no symbol censuses. E-02's cases drive the real helper in a real git fixture and assert on git's own observable state, which is also the only thing that can prove a reachability claim.
- Cite code by SYMBOL (`module.function`) or by a quoted content string, with a line number only appended to one of those and never alone: an offset expires before this plan executes (spec `ipd-structure-and-linting` Section 10.2; advisory `IPD-C801`).
