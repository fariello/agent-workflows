## Project conventions discovered (Step 0)

- `agent_workflows/status_set.py` moves artifacts between directory dispositions (e.g. `pending/` to `executed/`) when status is changed, but currently leaves the derived `INDEX.json` and `INDEX.md` stale until an explicit `aw index` command is executed.
- Manifest indices for plans (`.aw/records/plans/INDEX.json`) and research (`.aw/records/research/INDEX.json`) are derived artifacts regenerated by `plans_index.run_index` / `research_index.run_index` (which call `build_index_json`/`build_index_md`); the freshness comparison itself is `plans_index.check_drift` / `research_index.check_drift`, wired into `aw check` via `check_engine.check_content` and into `aw doctor` remediation.
- `aw check` and `aw doctor` check manifest freshness and report the exact rule string `stale-index` (hyphen) when manifest files are out of sync with filesystem state (`plans_index.py:276,281`, `research_index.py:244,248`).
- `apply_status_change` (`agent_workflows/status_set.py:345-497`) updates frontmatter `- Status:`, appends `## Workflow history`, and moves the file between directory dispositions, but calls NO indexing function - this is the exact gap this plan closes.

## Findings

Operators and agents currently have to remember to run a secondary `aw index plans` or `aw index` command after every `aw set executed <id>`. If forgotten, subsequent runs of `aw check` or `aw doctor` report `stale-index` drift. Automating index refresh on mutation eliminates this error mode entirely.
