## Project conventions discovered (Step 0)

- RETIREMENT DELIBERATELY SKIPS THE PRE-TRANSITION E/V CHECKPOINT on the premise that a parent's items are performed by nobody (`AGENTS.md`; `ipd_lifecycle.ROLLUP_OMITTED_GATES['pre-transition-ev-checkpoint']`), which is why a parent carrying real work must be caught BEFORE it retires.
- THE PROBE GATE AND THE RETIREMENT PREDICATE ARE DIFFERENT MECHANISMS AT DIFFERENT MOMENTS, and conflating them is the error this plan originally made. `enforce_orchestrator_probe_gate` runs ONCE per run, before any agent turn, and decides whether the RUN proceeds; `evaluate_set_retirement` plus `retire_orchestrator` decide whether a PARENT retires, and contain no reference to the probe. Establish which one you are changing before you change it.
- THE STRUCTURAL PRECONDITION ALREADY EXISTS: `evaluate_set_retirement` refuses `unfinished-children` unless EVERY child's on-disk status is exactly `executed` (`SET_RETIREMENT_DONE_STATUS`), and `find_unauthored_child_rows` separately refuses a declared row resolving to no plan in the Set. A coverage child that is `approved` therefore already blocks its parent's retirement.
- AN ORCHESTRATOR SHOULD KEEP ITS CHECKLIST: it is what makes a human-driven `execute <setid>` complete and ordered, and deleting it to satisfy a gate causes the lost work the gate prevents (`AGENTS.md`; `ipd_lint.ORCH_ROW_NO_DELETION` says the same at the refusal site).
- THE TYPED CHILD-TRACKING ROW RULE (`IPD-S407`, spec `r07vma`) ALREADY EXISTS and is the nearest shipped mechanism to what this plan wants: a conforming orchestrator row is `- [ ] E-NN CONFIRM <child-id6> REACHED <status>` and nothing else. It fires only at `review-finalize` and `pre-transition` (`ipd_lint._ORCH_ROW_BLOCKING_CHECKPOINTS`).
- A PLAN IN A TERMINAL DIRECTORY SHORT-CIRCUITS TO `legacy/not evaluated` for every checkpoint except `post-transition` (`ipd_lint._is_terminal_dir` in `lint_text`), which is what makes the two retired parents lint clean today despite non-conforming rows.
- THE OVERRIDE IS `--allow-uncovered-orchestrator-work` and it REQUIRES a justification which is recorded; a second, quieter escape hatch would defeat that design.
- TESTS IN `tests/test_orchestrator_retirement.py` HAVE BEEN PINNED TO LIVE SETS BEFORE and went red when those Sets completed (`jsomff`); `RealRepositorySets` is the live-reading class, so build fixtures instead (`SyntheticSetCase`, `RollupTransitionCase.make_set` are the precedents).
- Cite code by SYMBOL (`module.function`) or by a quoted content string, with a line number only appended to one of those and never alone: an offset expires before this plan executes (spec `ipd-structure-and-linting` Section 10.2; advisory `IPD-C801`).
