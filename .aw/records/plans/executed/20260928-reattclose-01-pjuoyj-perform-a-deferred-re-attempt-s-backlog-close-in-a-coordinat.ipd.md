## Goal

Make the ONE remaining backlog close that still writes into the shared checkout mid-run land the way every other write on this path lands: performed in a coordinator-owned throwaway worktree and published to main as a single fast-forward ref update, so a hook rejection or a peer's in-flight edit produces a REPORTED refusal instead of a half-moved item stranded in main's working tree.

WHAT THIS GOAL DELIBERATELY DOES NOT CLAIM. It does not change WHETHER any item closes: the eligibility decision stays exactly where `process_backlog_close` takes it, against main, and this plan changes only the tree the resulting MOVE and COMMIT happen in. It does not remove every write to main from a run, because landing the change IS a write to main; what it removes is the window in which main holds a moved-but-uncommitted item. And it does not claim to fix the other three `process_backlog_close` call sites, each of which is listed with its reason in `Deferred / out of scope`.

## Project conventions discovered (Step 0)

- A COORDINATOR-OWNED THROWAWAY WORKTREE IS THE ESTABLISHED WAY TO MUTATE-THEN-LAND, and it already ships. `commit_lock.coordinator_worktree` yields a worktree on its own short-lived branch and cleans up both unconditionally; `ipd_lifecycle._finalize_transaction` is its live caller and demonstrates the full sequence (mutate in `coord.path`, commit there, then `land_worktree_commit`). This plan reuses both rather than adding a third mechanism.
- THE FAST-FORWARD IS THE SINGLE STEP THAT ADVANCES THE BRANCH, and the ordering is load-bearing. `ipd_lifecycle`'s module comment above `RECONCILED_OK` records the measurement: a `git merge --ff-only` run AFTER the ref already points at the landed commit prints "Already up to date.", exits 0 WITHOUT touching the working tree, and makes the peer-protecting refusal unreachable. So never advance the ref first.
- `commit_isolated` IS NOT THE HELPER FOR THIS. It copies each named path FROM the shared tree INTO its own detached worktree and then advances the ref under a compare-and-swap, so a mutation made in a different worktree is invisible to it. Its own docstring and `coordinator_worktree`'s explain why the sibling exists; do not re-litigate it.
- THE CLOSE IS FAIL-CLOSED THROUGHOUT, BY DESIGN. `process_backlog_close` records a verdict on the item whether or not it closes, catches its own evaluation failures, and treats a refused setter as the reason; `commit_backlog_close` returns None rather than raising on every error path including a partial porcelain view. Any new arm must keep that property.
- THE `--status done` SPELLING IS LOAD-BEARING AND MUST NOT BE "SIMPLIFIED". `close_backlog_item`'s docstring records that the positional `aw backlog set done <selector>` form does NOT run the shared release-gate predicate while the `--status done` form does, verified live on a gated item. This plan changes the tree, never the spelling.
- ONE SHARED LADDER, TWO HOSTS. `retry_deferred_integrations` is defined in `runner_shared` and both hosts delegate to it with injected bindings, which is why this fix is one edit; the injected-parameter pattern exists precisely so a host that forgot a binding fails loudly at the call.
- Cite code by SYMBOL (`module.function`) or by a quoted content string, with a line number only appended to one of those and never alone: an offset expires before this plan executes (spec `ipd-structure-and-linting` Section 10.2; advisory `IPD-C801`).
