## Project conventions discovered (Step 0)

- `git_commit_helper.offer_commit` is THE shared commit gateway. The module docstring and `commit_lock` name four verbs (`aw set`, `aw rename`, `aw commit`, the runners), but the actual in-tree call sites number SEVEN (`cli.py`, `plans_archive.py`, `research_archive.py`, `runner_shared.py`, `specs.py`, `status_set.py`, `work_cmd.py`), audited at review. A fix sited here protects every writer, which is the argument for fixing the gateway rather than one writer.
- EVERY IN-TREE CALLER PASSES COMPUTED FILE LISTS, never directories (audited at review). The exposed surface is therefore `aw commit`'s user-supplied `-- <paths>` tail, which is precisely how `ca8e22e4` happened. That is what makes a refusal safe.
- ONLY CALLER-NAMED PATHS ARE EVER STAGED, and the helper snapshots the index first so a co-worker's staged change cannot be swept in. Any expansion added by E-02 must preserve that property rather than widening what gets staged.
- A REFUSED CALL MUST LEAVE THE INDEX AS IT FOUND IT. The `git add` failure path already honors this (`git reset --quiet HEAD -- *rel_paths`), and F-6 shows the `nothing-to-commit` early return does NOT, which is why E-02's refusal belongs before staging.
- GIT'S DEFAULT `--porcelain` COLLAPSES AN UNTRACKED DIRECTORY to a single directory entry, hiding the files inside it; `-uall` lists them. `commit_backlog_close` learned this the hard way and records it, and E-02's refusal message needs the same flag to name the files it is refusing.
- `aw backlog set` relocates by `core.atomic_write(dest, ...)` + `src.unlink()`, NOT `git mv`, while `status_set` was converted to `git mv` in 2026-09-13 precisely so a move is one staged rename. That inconsistency between two record writers is the root of this plan's shape and is OQ-02.
