MEASURED IN THIS LANE (review, 2026-09-24): from the lane's `tests/` subdirectory, `python3 -c "import agent_workflows; print(agent_workflows.__file__)"` printed the MAIN checkout's `__init__.py`.   THE MECHANISM IS ONE, NOT TWO, AND THE AUTHORED SECOND MECHANISM IS FALSE (review correction, F-9). This plan was authored claiming two mechanisms, the `.pth` absolute path AND "the console script runs under a fixed interpreter (its shebang names an absolute virtualenv `python3`)". THE SHEBANG IS NOT A MECHANISM. Measured: `which python3` and the `aw` shebang name the SAME interpreter (`<venv>/bin/python3`), so the shebang changes nothing that a bare `python3` does not already do. What ACTUALLY distinguishes the console script is that its `sys.path[0]` is the SCRIPT'S OWN DIRECTORY (`<venv>/bin`) rather than the cwd, so no cwd entry exists to win over the `.pth`. Measured with `-P` (which reproduces exactly that no-cwd-entry shape): `python3 -P -c 'import agent_workflows'` from the lane ROOT resolved to MAIN, while plain `python3 -c` from the same cwd resolved to the LANE. An executor told to fix "a fixed interpreter shebang" would look for a mechanism that is not there; there is ONE selecting mechanism (`sys.path` ordering versus the `.pth`) with two exposure shapes (no cwd entry at all; or a cwd entry that is not the tree root).
  WHY IT IS USUALLY INVISIBLE, WHICH IS WHAT MAKES IT DANGEROUS. From a lane's ROOT directory the cwd entry precedes the editable path on `sys.path`, so the lane's own package wins and everything looks correct; re-verified at review. Step outside the root, or let any tool run without a cwd entry, and the resolution silently flips to main. A defect that behaves correctly in the common interactive case and incorrectly under a subprocess is exactly the shape that produces confidently wrong evidence.
  THE HARM IS FALSE EVIDENCE, NOT A CRASH, AND THE EXECUTION CONTRACT DEPENDS ON THE THING THAT IS BROKEN. `AGENTS.md` requires an agent to paste ACTUAL runner output and forbids claiming success it did not run; an agent in a lane that runs `aw <verb>` to demonstrate its change is, at that moment, exercising main's code and pasting main's behavior as proof of the lane's. The failure direction is the bad one: the change looks verified. `uin96r`'s own filing says it "silently produces FALSE EVIDENCE", and `ccbe60` generalizes it to the suite, where a subprocess CLI test asserts against a tree the test did not modify.
  THE MOST IMPORTANT THING AN EXECUTOR MUST KNOW IS NOT IN THE THREE FILINGS: HALF THIS PROBLEM IS ALREADY SOLVED, DELIBERATELY, IN THE OPPOSITE DIRECTION (review finding F-10). ## Project conventions discovered (Step 0)

- THE EXECUTION CONTRACT DEPENDS ON CLI EVIDENCE: `AGENTS.md` requires pasting actual runner output and forbids claiming unrun success. This defect silently falsifies exactly that evidence, which is why three `high` bugs point at it.
- LANE WORKTREES ARE THE NORMAL EXECUTION MODE: `aw oc run` isolates each item in its own worktree by default, so "measured in a lane" is the common case and not an edge case.
- THE CONTROL-PLANE PIN ALREADY EXISTS AND IS DELIBERATE (added at review, and the most important convention here): `af7i6p` shipped `runner_shared.pinned_child_env` / `pinned_module_argv` / `_AW_PIN_BOOTSTRAP` so a driver-spawned nested `aw` resolves the DRIVER's tree, guarded by `tests/test_lane_tool_identity.py` and required by spec `7ckptx` A8. The runner's `-P`-plus-bootstrap technique is also the reference implementation for suppressing a cwd entry across the declared floor (`requires-python = ">=3.9"`; `-P` and `PYTHONSAFEPATH` are both 3.11 features, so neither is available on 3.9/3.10 and a `-P`-only fix would silently degrade there).
- `agent_workflows/selectors.py` SHADOWS THE STDLIB `selectors` MODULE for any interpreter whose `sys.path` head is `agent_workflows/` itself. This is a SINGLE-TREE hazard (verified at review with a one-file decoy and no `agent_workflows` import), so it is a caution for any fix that manipulates `sys.path`, NOT evidence of cross-tree mixing.
- Cite code by SYMBOL (`module.function`) or by a quoted content string, with a line number only appended to one of those and never alone: an offset expires before this plan executes (spec `ipd-structure-and-linting` Section 10.2; advisory `IPD-C801`).
