## Project conventions discovered (Step 0)

- Cite code by SYMBOL (`module.function`) or by a quoted content string, with a line number only appended to one of those and never alone: an offset expires before this plan executes (spec `ipd-structure-and-linting` Section 10.2; advisory `IPD-C801`). - AN EXECUTED PLAN IS APPEND-ONLY, NOT IMMUTABLE, and that distinction is the whole mechanism of E-01. `AGENTS.md` forbids changing what such a plan RECORDS and in the same breath permits appending a dated history line pointing at later work. So "the false claim stays readable in an approved plan" (the item's option 3 objection) is answerable without rewriting anything.
- THERE IS NO `aw ipd note`. The annotation verb exists for two other types (`aw backlog note`, `aw specs note`, both documented as "the annotation verb ... reach for it whenever the intent is to record a reason rather than to transition") and not for plans, so E-01 is a hand edit by necessity rather than by choice.
- PLAN HISTORY IN THIS REPOSITORY IS NEWEST-FIRST, and readers depend on it: `.aw/records/plans/README.md` states a new record "is inserted directly under the `## Workflow history` heading, so the FIRST record is the most recent", and names `plan_readiness.extract_newest_history_entry` as the reader, recording that a reader which "sliced to end of file and took the last bullet is the bug that fix replaced". Hence E-01's placement constraint.
- A HISTORY LINE'S LEADING TOKEN DISTINGUISHES A TRANSITION FROM A NOTE. `ipd_lifecycle` holds "the full plan status vocabulary a history line's leading token may legitimately be (a STATUS transition)" and treats a line whose token is not one of those as "a workflow NOTE". So a note token is the correct choice for E-01 and a status token would be a false lifecycle claim.
- THE CITATION-ANCHOR ADVISORY IS DELIBERATELY ADVISORY, and E-03 must not change that: `check_citation_anchors` documents that it "returns ADVISORY diagnostics only; the caller must place them in `LintResult.advisories` so the conformance disposition and process exit status are untouched."
- ITS DATE FENCE IS A BORROWED PRECEDENT, not an accident: `_citation_anchor_applies` records that suppressing a plan with no parseable `- Date:` is "copied from the carrier precedent and for its stated reason", so the grandfathering is a considered design choice and widening it by default would revert one.
- BEHAVIORAL TESTS ONLY (maintainer ruling 2026-09-26), which E-04 follows. This repository deleted source-text pins in bulk and records two live instances of such a pin passing vacuously, so a test asserting the new flag's existence in source would be both forbidden and useless.
