## Goal

Close the hand-edit bypass for an illegal BACKLOG status transition, by adding the one commit-scoped rule that is missing and by adding nothing else. Plans already have this: `check_status_untooled` reads a staged plan status delta and `check_commit_invariants` puts it in front of a commit. Backlog has neither. Once `cc2m29` publishes `BACKLOG_TRANSITIONS`, the only missing piece is a rule that asks that table about a staged backlog delta, and the only genuinely new engineering in this plan is HOW that delta is recovered: not by path, as the plan-side template does, but by `- Id:`, because a backlog status move relocates the file and git's similarity index is not a reliable enough join for a gate to depend on.

## Project conventions discovered (Step 0)

- Cite code by SYMBOL (`module.function`) or by a quoted content string, with a line number only appended to one of those and never alone: an offset expires before this plan executes (spec `ipd-structure-and-linting` Section 10.2; advisory `IPD-C801`). THIS PLAN CITES BY SYMBOL THROUGHOUT.
- THE COMMIT-SCOPED RULE SHAPE IS ESTABLISHED AND MUST BE COPIED, NOT INVENTED, EXCEPT FOR ITS JOIN. `check_engine.check_status_untooled` is the template: it runs `git diff --cached --name-status -M` scoped to a records prefix, returns early when that output is empty so an ordinary commit pays nothing, and compares `_blob_text(repo, ":0:", path)` against `_blob_text(repo, "HEAD", path)` through the shared `_status_meta`. Its docstring records why commit-scoping is "the key simplification": only files in the commit are examined, so historical records are never touched and no grandfathering list is needed. What this plan does NOT copy is its PATH-KEYED join, for the reason F-03 measures.
- `_staged_backlog_done_items` ALREADY ESTABLISHES THE BACKLOG PATHSPEC. It scopes its `git diff --cached` to both `.aw/records/backlog` and `.agents/backlog`, and its docstring says it is commit-scoped "like check_status_untooled". That pathspec is the one to reuse; a rule scoped only to `.aw/records/backlog` would silently miss the legacy layout `BACKLOG_ROOTS` still supports.
- ONE PREDICATE, MANY SURFACES, NEVER A SECOND COPY. `check_engine`'s own section banner states this, and `evaluate_blocking_close` demonstrates it across a setter, a check rule and an opt-in hook. The hook modules under `agent_workflows/hooks/` are deliberately thin: `status_untooled_gate.check` and `backlog_blocking_close_gate.check` are each three lines that call a `check_engine` rule and format its drift. This plan therefore puts ALL logic in `check_engine` and adds no hook module.
- A NEW COMMIT-SCOPED INVARIANT DOES NOT NEED ITS OWN HOOK. `hooks.precommit_scope_gate` is the generalized layer whose docstring says it exists because "the earlier gates each enforce ONE commit-scoped invariant" while it delegates to the single aggregating surface `check_commit_invariants`. Composing into that aggregator is what makes a new rule enforceable at commit time with no new hook id and no `.pre-commit-config.yaml` edit.
- THE COMMIT-SCOPED / WHOLE-TREE LINE IS DELIBERATE AND DOCUMENTED. `check_engine`'s full-sweep block records that whole-tree release-gate rules are deliberately NOT added inside `check_commit_invariants`, "that function is composed by the opt-in pre-commit aggregator and must remain commit-scoped so a local hook cannot refuse a commit over an unrelated artifact in a shared checkout." That is the governing constraint for where this rule may be composed.
- THE SIBLING RULE IS `error` SEVERITY UNDER `I-03`. `RULE_REGISTRY` carries `check.status-untooled` as `RuleSpec("error", ASSURANCE_REPOSITORY, DET_DETERMINISTIC, "I-03")`. `artifact_core.drift_exit_code` exempts only `info`, so `error` fails CI and pre-commit alike.
- THE STATUS ENUM IS DERIVED, NEVER RE-LISTED. `lifecycle_dirs.LIFECYCLE_SUBDIRS["backlog"]` is the single definition; `backlog.STATUSES` derives from it and `status_set` re-derives from `backlog.STATUSES`. This rule consults `backlog.STATUSES` and never writes a status literal of its own.
- THE HONEST-LIMIT PARAGRAPH IS A CONVENTION, NOT DECORATION. Every hook module here carries one, and `AGENTS.md` records the same limit for `backlog-blocking-close-gate`: git hooks are local, not cloned by default, and skippable with `--no-verify`, so the portable authority is the `aw check` rule family plus CI. The backlog item explicitly asks the plan to state this.
- A `- Readiness:` field is an OUTPUT of `/plan-review` and is deliberately ABSENT here; writing one while authoring would forge a review that has not happened, and the auto-approve predicate reads that field first.
