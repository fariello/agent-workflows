## Project conventions discovered (Step 0)

- Cite code by SYMBOL (`module.function`) or by a quoted content string, with a line number only appended to one of those and never alone: an offset expires before this plan executes (spec `ipd-structure-and-linting` Section 10.2; advisory `IPD-C801`).
- SPECS LIVE IN STATUS SUBDIRECTORIES, NOT FLAT, and this single fact invalidates the backlog item's reproduce line. The tree carries `approved/`, `deferred/`, `draft/`, `implemented/`, `implementing/`, `reviewed/`, `superseded/`, `to-review/`, so `.aw/records/specs/*.spec.md` matches NOTHING and a census must recurse. The `specdirs` Set made location authoritative, and it is also the direct cause of the stale-flat-root citations this plan repairs.
- GRANDFATHERING IS DELIBERATE AND IS NOT A BUG TO FIX. `check_engine._spec_requires_id6` extracts the leading `YYYYMMDD` from a spec's filename and compares it against `config.resolve_cutover_date(repo_root, "spec_id6")`, which resolves this repository's stamped `cutovers.spec_id6` of `2026-08-29` from `.aw/config/project.json` (falling back to the module constant `SPEC_ID6_CUTOVER_DATE` when unset). A spec dated before the cutover is exempt, and `specs.validate_spec` has NO `- Id:` rule at all, so neither of these two specs is nonconformant today. This plan therefore converts for REACHABILITY and must not claim to fix a conformance failure.
- THE CONVERSION VERB IS DOCUMENTED IN THE GRANDFATHERING PATH ITSELF. The finding `check_engine` emits for a POST-cutover legacy spec carries the recovery command `aw rename specs <filename> --to-id6 --apply`, so the verb this plan uses is the one the checker names. What the checker does not say, and what F-04 measures, is that the command can refuse.
- `--to-id6` FORCES PART OF THE NAME AND PRESERVES THE REST. Through `artifact_rename.compute_target_name`'s legacy-timestamp branch into `artifact_naming.build_clustered_name`, the result is `YYYYMMDD-<id6>-01-<id6>-<slug>.spec.md`: the original DATE is preserved and never recomputed, the Order is hard-coded to `01`, and the setid is hard-coded to the minted id6, so `--set` and `--order` are silently IGNORED on this branch. Do not pass them and do not expect them to matter.
- THE `- Id:` BULLET IS INSERTED AFTER `- Status:`, falling back to after `- Date:`, and if a file has neither bullet it gets NO bullet and the id6 lives only in the filename. Both specs in scope carry `- Status:`, so both get the bullet; `_update_frontmatter_metadata` writes it atomically and reuses an existing `- Id:` rather than ever re-minting.
- MINTING IS COLLISION-CHECKED REPOSITORY-WIDE, not merely within specs: `artifact_core.mint_id6` unions `global_id6s` (which walks every supported artifact type via `artifact_adopt.repository_id6s`) with the per-type set from `_existing_type_id6s`, so a minted spec id6 cannot collide with a plan, backlog item, or research id6.
- THE RENAME FAILS LOUD RATHER THAN HALF-REWRITING. `find_unrewritable_path_citations` compares each cited directory against the file's real directory by SUFFIX in both directions, and `run_rename_generic` returns exit 2 on `--apply` when that list is non-empty, printing `error: full-path citation ... cannot auto-rewrite. Fix it by hand, then retry.` It masks fenced code and skips commit-pinned permalinks first, so a transcript inside a fence does not trip it.
- `--no-refs` DISABLES THE GUARD ALONG WITH THE REWRITES, which is the whole reason it works here and also the reason it is dangerous. In `run_rename_generic` the unrewritable-path check is gated on `update_refs`, so `--no-refs --apply` renames past a citation the tool would otherwise refuse over. That is acceptable only because E-02 classified every occurrence first and E-04 then applies the KEEP set by hand.
- EDITING AN EXECUTED PLAN'S TEXT IS PERMITTED ONLY AS REFERENCE REWRITING, AND MUST BE DECLARED. `AGENTS.md` forbids changing what an executed plan RECORDS, naming a closed list ("its steps, evidence, results, or status"); a path citation is none of those. `iyi4hc` states the operative convention and had it reviewed and approved, and the maintainer's commit `4c3aa79f` repaired 98 stale flat-root spec citations across 53 records (38 of them executed plans) with the attestation "Paths only; no record's claims change (maintainer-approved)". Every executed plan this plan touches is declared individually in `- Scope-Paths:` for that reason.
- THE PRECEDENT'S ORDERING IS THE ORDERING THIS PLAN COPIES: the maintainer repaired the stale paths FIRST (`4c3aa79f`) and ran `--to-id6` immediately AFTER (`d6b2fa00`, which converted two specs exactly as this plan converts two). `d6b2fa00`'s message also enumerates what the tool did not cover and had to be hand-fixed, including reviews, source comments, and a quoted transcript restored to its original text.
- OVER-REACH INTO A TRANSCRIPT IS A REAL, RECORDED FAILURE MODE, not a theoretical one: commit `084689ef` exists solely to restore a quoted `would rename` transcript that the `d6b2fa00` rename had rewritten. This is why E-02 classifies transcripts LEAVE and why V-03 demands per-occurrence diff proof.
- THERE IS NO BULK CITATION-REPAIR TOOL. `aw check` has no `--fix`, `aw doctor` is read-only, no check rule detects a stale full-PATH citation in prose, and `find_unrewritable_path_citations` is detect-only with no repair path. The only mitigations are `--no-refs` and hand editing, which is why the hand work is explicit here.
- THE REFERENCE SCAN IS NARROWER THAN THE REPOSITORY. `REFERENCE_SCAN_ROOTS` is the record trees plus `.aw/records/reviews` and `tests`, limited to `.md`/`.txt`/`.py`, skipping `README.md`/`INDEX.md`/`STATUS.md`; `agent_workflows/**`, `tools/**`, `docs/**`, `.aw/system/**` and root-level text files are not scanned. E-05 exists for that gap.
- THE RENAME APPENDS TO AN UNTRACKED LEDGER. `record_history.record_rename` writes `.aw/records/history.jsonl`, which is gitignored (`.aw/.gitignore` line `records/history.jsonl`), so it must never be staged; its write is failure-isolated and its absence is not an error.
- THE RENAME VERB HAS NO STRUCTURED OUTPUT. `artifact_rename` uses bare `print()` and never reads `--agent`/`--json`, so both flags are accepted and IGNORED on this path (measured: identical human `--- would ... ---` text). Evidence for this plan must therefore be pasted human output, not parsed JSONL.
- A CITATION THAT WAS CORRECT WHEN WRITTEN IS NOT A DEFECT. Pending plan `2wmwf7` refuses to repoint a stale spec path inside executed plan `u06zo2` on exactly this ground, and `68hdic` bounds its dangling-citation detector to packaged SOURCE for the same reason. This plan honors that by repairing only the flat-root class (invalidated by a migration, and the subject of the maintainer's own repair commit) and leaving every `.agents/` path alone.
