## Goal

Make "extract the section between these two markers" a single call that cannot silently widen, so the
next author writing a section assertion gets the bound for free instead of re-deciding it, and a test
whose terminator disappears FAILS SAYING SO rather than quietly asserting over the rest of the file.

The helper must be honest about what it is not. It does not find unbounded slices that already exist
(that is Order 02, site by site) and it does not stop a new one being written (Deferred, with the
reason). It removes the excuse for writing one.

IT ALSO REFUSES IN A THIRD CASE THAT IS NOT A DEFECT IN THE INPUT. A document that mentions a heading
name only in PROSE has no anchored occurrence, so the anchored default reports the start marker ABSENT
where an unbounded caller silently returned prose. Review measured 66 such tracked files (F-09). That
refusal is correct, and it is the one an Order 02 converter will hit first, so the message must point at
`anchored=False` rather than implying the document is malformed.

### Why the helper refuses instead of falling back

Every defect in this class is a FALLBACK, not a missing bound. The original `1pgrii` guard fell back to
end of file. `plan_readiness`' predecessor fell back to end of file and returned a non-history line for
35 of 35 plans. `test_project_layout`'s `if end != -1 else content[start:]` is a fallback written on
purpose, and F-05 measures what it costs. So a helper that quietly returned the tail when the
terminator was missing would reproduce, in shared code, the exact behavior the Set exists to remove,
and it would do so in the one place every future caller inherits.

The cost of refusing is a test that fails when a producer stops emitting a heading. That is the correct
outcome: the assertion's premise really has changed, and a human should look. The cost of falling back
is an assertion that silently changes meaning, which nobody looks at.

### Why `tests/support.py` and not `agent_workflows/`

Two reasons, the second decisive. FIRST, this is test infrastructure: the production readers that need
bounding ALREADY have it three times over (`attention._history_section_lines`,
`selectors.metadata_region`), so there is no production caller to serve. SECOND, `agent_workflows` is a
package this toolkit INSTALLS into other repositories; adding a public helper there means shipping,
documenting and versioning an API for a need that exists only in our own suite, which is the
project-agnostic discipline `GUIDING_PRINCIPLES.md` P7 and the KISS bound in P6 both point away from.

The honest counter-argument, recorded because it is not absurd: `tests/support.py` is not importable by
a managed target repository's suite, so a target repo that wants this must write its own. That is
acceptable, because a target repo's tests are its own business and this helper encodes OUR convention
about OUR record format markers.

### OQ-01: Should the helper be given a regex-marker mode for a caller whose marker is not a fixed string?

- Blocking: no
- Status: resolved
- Owner: none
- Resolution or deferral rationale: RESOLVED FROM REPOSITORY EVIDENCE as NO, and E-01 states the prohibition. Two measurements settle it. FIRST, no measured site needs it: the authoring census of marker-located extractions in `tests/` found 44 sites, and every single marker is a string LITERAL or a module constant that holds a literal (`pol.SUMMARY_HEADER`, `pol.DISPOSITION_HEADER`, `RC.REPORTING_SECTION_TITLE`). Not one uses a pattern. SECOND, and decisively, a regex parameter would re-open the defect: `section(text, start, r".*")` or any pattern matching end-of-input would restore the fallback this plan exists to remove, and it would do so through the shared helper every future caller inherits. The one site whose marker is not a literal in the source text (`tests/test_merge_conflict_sendback.py`, which lowercases its subject first) needs case handling, not a pattern, and `anchored=False` serves it. If a genuine pattern caller ever appears, the correct move is to add a narrow named mode with its own refusal, not a general regex escape.

### OQ-02: Should `section()` return the text INCLUDING the start marker, or only the body after it?

- Blocking: no
- Status: resolved
- Owner: none
- Resolution or deferral rationale: RESOLVED as INCLUDE THE START MARKER, matched to how the measured callers actually read. Three of the four line-oriented sites assert something about the heading line itself or count lines relative to it (`tests/test_lifecycle_style.py` starts its walk AT the `## 5. ` line; `tests/test_plans_board.py` and the `pol.SUMMARY_HEADER` sites both index within a block whose first line is the marker), and every one of them today holds a slice that starts at the marker. Returning the body only would force each caller to re-add the marker or shift its expectations, turning Order 02's behavior-preserving diffs into semantic ones. The contrary case is `attention._history_section_lines`, which returns the body only and strips a leading blank; it is a production reader whose callers want records, not the heading, so the two conventions are each right for their own callers and the difference must be stated in the docstring rather than silently differing. E-01 therefore returns `text[start:end]`, and the docstring says so and names the production helper it deliberately differs from.
