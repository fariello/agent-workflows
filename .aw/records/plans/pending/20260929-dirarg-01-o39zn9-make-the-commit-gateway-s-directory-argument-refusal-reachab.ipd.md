## Goal

Make `aw commit`'s treatment of a directory argument DISCOVERABLE and UNIFORM: a `--no-commit` preview must report the same refusal the real run will, and the shared commit path's other public entry point must return a typed refusal rather than raising `IsADirectoryError`. The outcome an agent sees is unchanged on the happy path and, on the directory path, is a copy-pasteable corrected call that is now visible from a dry run.

AND MAKE "A DIRECTORY ARGUMENT" MEAN WHAT THE REFUSAL CLAIMS IT MEANS, which review measured that it does not. Both fixes key on `Path.is_dir()`, which is FALSE for a directory whose files were all deleted or moved away, so the gateway's refusal SKIPS such a path and the code beneath it misbehaves in two measured ways: a mixed call commits the file half and LEAVES A STAGED DELETION of the vanished directory's files behind in a shared index (F-11), and `commit_isolated` still raises, now from `Path.unlink()` on the deletion arm rather than `shutil.copy2` (F-10). That is not a corner: emptying a directory by moving its contents out is precisely the records-move shape `hv9gar` was written for, and the residue F-11 leaves is a worse outcome than the preview mismatch this plan was filed to fix, because `AGENTS.md` tells every agent that `aw commit` leaves a co-worker's index alone. The bar is therefore that the refusal covers a path that IS or WAS a directory, while still not catching a deleted plain FILE, which `commit_isolated` deliberately supports and which `offer_commit` commits correctly today.
