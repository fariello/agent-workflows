### Task group 2: give the other public entry point a typed refusal

- [ ] E-03 REFUSE A DIRECTORY IN `commit_lock.commit_isolated` WITH A TYPED OUTCOME instead of letting `shutil.copy2` raise.

  THE DEFECT IS THE SAME ROOT CAUSE THE ITEM NAMES. `commit_isolated` mirrors the caller's `rel` paths into the throwaway worktree with `if src.exists(): shutil.copy2(src, dst)`. `Path.exists()` is TRUE for a directory and `shutil.copy2` on a directory raises `IsADirectoryError`, so a directory in `paths` escapes as an exception while every other bad input returns an `IsolatedCommitResult`. F-03 measures it.

  SITE THE REFUSAL BEFORE THE WORKTREE IS CREATED, next to the existing `if not rel: return IsolatedCommitResult(ISO_NOTHING, None, "no paths requested")` guard. That keeps the refused arm free of the `worktree add` / `mkdtemp` it would otherwise have to unwind, and matches the reason `offer_commit`'s own refusal is sited early.

  RETURN `ISO_ERROR`, NOT `ISO_NOTHING`. A directory argument is a CALLER MISTAKE, and `ISO_NOTHING` means "there was legitimately nothing to commit", which `git_commit_helper` maps onto `STATUS_NOTHING_TO_COMMIT` (a normal, non-alarming outcome). Conflating the two would let a mistake read as an ordinary empty commit. Name the offending directory (or directories) in `detail` so a direct caller can correct the call.

  DO NOT EXPAND, AND DO NOT REACH FOR `_contained_files`. That helper lives in `git_commit_helper`, and `commit_lock` is deliberately positioned BELOW it (`git_commit_helper` imports `commit_lock`, not the reverse); importing upward would create a cycle. Refusing needs no enumeration, which is a second reason refusal is the cheap answer here.

  THIS ARM IS CURRENTLY UNREACHABLE FROM `offer_commit` AND THAT IS FINE; say so in the docstring. `offer_commit` refuses a directory first, so no in-tree path reaches this guard today. It is defense for a DIRECT caller (tests call `commit_isolated` directly today, in `tests/test_merge_conflict_sendback.py` and `tests/test_contention_wait.py`), and a guard whose unreachability is undocumented is the kind a later reader deletes as dead code.
  - Depends on: E-01
  - Expected outcome: `commit_isolated(repo, ['sub'], message=...)` RETURNS `IsolatedCommitResult` with `status == ISO_ERROR` and a `detail` naming `sub`, instead of raising `IsADirectoryError`; no throwaway worktree is created on that arm; no `git worktree list` residue and no `.aw-isocommit-*` directory is left behind; and `offer_commit`'s behavior is unchanged because its own refusal still fires first.

## Project conventions discovered (Step 0)

- `git_commit_helper.offer_commit` IS THE SHARED COMMIT GATEWAY, and a fix belongs here rather than at a caller. `hv9gar`'s review audited the in-tree call sites and found SEVEN (`cli.py`, `plans_archive.py`, `research_archive.py`, `runner_shared.py`, `specs.py`, `status_set.py`, `work_cmd.py`), every one passing a computed FILE list. That is what makes a refusal safe and is why this plan does not add a CLI-level guard.
- A REFUSED CALL MUST LEAVE THE INDEX AS IT FOUND IT. This is the property `hv9gar` established for the directory refusal and it is asserted by two existing tests (`test_mixed_file_and_directory_argument_is_refused_before_staging` and `test_all_directories_argument_is_refused_before_staging`) via `git status --porcelain` byte-comparison plus an unchanged `git log`. E-02 must not weaken it, and E-03 adopts it.
- `commit_lock` SITS BELOW `git_commit_helper` IN THE IMPORT GRAPH. `git_commit_helper.offer_commit` does `from agent_workflows import commit_lock as _lock`; there is no reverse import. Any helper E-03 wants from the upper module would be a cycle, which is a design constraint on E-03 rather than a preference.
- THE GITIGNORE FILTER IS NOT FORCE-ADD, AND THE REFUSAL MESSAGE INHERITS THAT. `_contained_files` uses `git status --porcelain -z -uall`, which respects `.gitignore`, so an ignored file inside a refused directory is correctly absent from the refusal's file list. MEASURED: with 31 modified files plus one gitignored `sub/ig`, the refusal names the 31 and not `sub/ig` (F-05). Do not "improve" this by enumerating ignored paths.
- `git`'s DEFAULT `--porcelain` COLLAPSES AN UNTRACKED DIRECTORY to one directory entry and hides the files inside; `-uall` lists them. `runner_shared.commit_backlog_close` records learning this the hard way, and `_contained_files` already carries the flag.
- `tests/test_git_commit_helper.py` OWNS THIS SURFACE and supplies the fixtures to extend: a `repo` fixture (`init_repo` plus one seed commit), `_write`, `_head`, `_create_untracked_move_fixture` (the write+unlink shape production actually emits), and a `rec` fixture whose `assert_contract_clean()` proves the helper never used `add -A`/`-a`, `push`, or `--no-verify`. Use them rather than hand-rolling a fixture.
- THERE IS NO `tests/test_commit_lock.py` TODAY, though `tests/test_git_commit_helper.py` cites one by name. Pending plan `c8ioct` proposes creating it. To avoid two plans racing to create the same file, E-03's test goes in its own new file (`tests/test_commit_isolated_directory.py`), declared in `- Scope-Paths:`.
