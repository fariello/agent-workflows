# IPD: Make aw migrate metadata migrate any repository from any prior format, and prove it on a real-shape corpus

- Date: 2026-11-07
- Kind: child
- Concern: Spec `4sd62s` C12 (added 2026-11-07, maintainer direction) makes it a Must that the metastore Set BUILDS the tool that migrates ANY repository from ANY prior format this toolkit has written, and 5.3 forces every repository through that tool by refusing every command until it runs. The Set as planned builds the migration against this repository only: 5.2 names this repository's 34 renames, 28 minted ids, `wvlk84` and 466 sidecar records, AC-10 runs "on a copy of this repository", and `dcerjg` proves `m0001` on fixtures plus a clone of this repository. Measured 2026-11-07 on a copy of one of the maintainer's private repositories (`.agents/` layout, prose plans with no metadata bullets; called repository P below): `status_set.inventory_all_artifacts` saw 201 records while `artifact_meta.query` saw 0, because `project_context.resolve_project_context` placed the records root at an empty per-project directory under AW_HOME and the legacy loader scans that one root. 28 repositories on that machine use the toolkit; most are on `.agents/`, five mix `.agents/` and `.aw/`.
- Scope: (1) Make the phase-A cache (`artifact_meta`) read every record today's readers read in a repository of each C12 shape: scan the same directory set as `selectors.record_dirs` (the resolved records root plus the literal `.aw/records/<type>` and legacy `.agents/<type>` trees), so a phase-B reader move preserves behavior in every repository, and give an id-less record a stable path-keyed identity in the cache instead of a fresh random id6 per process. (2) Make `aw migrate metadata` (built by `dcerjg`) generic per 4sd62s 5.2a: discover its inputs instead of using this repository's constants; chain the existing transactional layout migration (`layout_migration.MigrationManager`) as stage one in the same journal for shapes (a) and (b); resolve the records root through `project_context`; mint ids, statuses, titles and Set/order for id-less records (shape (c)); treat "no sidecar" as normal unless the repository's own records show a sidecar writer ran (shape (d)); migrate companion/home backends in place (shape (e)); list every unclassifiable file in the census and leave it untouched. (3) Build the AC-42 corpus: one anonymized fixture repository per shape, generated by code from the STRUCTURE of the maintainer's repositories (directory layout, filename grammar, front-matter shape) with synthetic text, and prove migrate, re-migrate, round trip and before/after `aw find` parity on each and on a copy of this repository. EXCLUDES: this repository's attended cutover (`cxxmyv`); short-description generation (`ya4ee4`); moving any reader or writer onto the cache (Orders 07 to 11); shapes no toolkit release has written (4sd62s 3c).

## Goal

Ship one `aw migrate metadata` that converts any repository this toolkit has ever written records into, and a phase-A cache that sees the same records today's readers see in that repository, both proven on a corpus of the real shapes in the field, so that 5.3's refusal never strands a repository with an untested way out.
