## Project conventions discovered (Step 0)

- The auto-approve predicate and the human-approval gate live in ONE module by design and deliberately DISAGREE: `plan_readiness.is_plan_review_approved` fails closed because a false negative merely defers to a human, while `plan_readiness.approval_refusals` is looser about prose because its verdict refusals have NO override and a false positive is an unoverridable lockout. The module docstring states this asymmetry explicitly, which is why this plan changes one and not the other.
- Review PROVENANCE and review VERDICT are separate questions owned by separate predicates: `history_has_review_record` answers "did a review ever run", `newest_verdict` answers "what did it decide". `is_plan_review_approved`'s own docstring says asking the verdict question twice "gives one plan two verdict gates that can disagree", so the fix must add the provenance call and not a second verdict check.
- `is_review_history_entry` classifies a review record STRUCTURALLY (a review token in the record's own status/workflow middle, plus a leading verdict or workflow name) precisely so a bare MENTION of `APPROVE` in a non-review record does not count; its docstring contrasts this with `ipd_lint._REVIEW_EVIDENCE_RE`, which scans the whole history text and does match such mentions.
- The gate's live call site keys on the TURN'S RECONCILED DISPOSITION, not on the plan's on-disk status: `runner_shared` reaches `is_plan_review_approved` only when `is_review`, the queue entry is an `ipd`, `disposition in ("reviewed", "approved")`, and `full_auto`. `reconcile_disposition`'s plan-review arm returns `"reviewed"` for an exit-0 turn with positive evidence even when the on-disk status is something else, so a status-keyed reading of reachability understates it.
- `attention_contract.TRANSITION_AUTHORITY` has entries for `->reviewed` (requiring a review record) and `->approved` (requiring a human), and NO entry for `->auto-approved`. The tier the predicate promotes into is therefore gated by the predicate itself rather than by the transition table, which is why a hole in the predicate is not caught downstream.
- `tests/test_readiness_absence_invariant.py` is the file that owns this invariant and its docstring enumerates four properties, the third being the fallback arm. A change to the fallback must amend that docstring, or the file documents a weaker gate than it tests.
- Pre-existing suite failures exist in this lane (3 measured), so "the suite passes" is not an available claim; the repository's execution contract demands pasted runner output, which makes an explicit baseline subtraction the honest form of that evidence.
- Cite code by SYMBOL (`module.function`) or by a quoted content string, with a line number only appended to one of those and never alone: an offset expires before this plan executes (spec `ipd-structure-and-linting` Section 10.2; advisory `IPD-C801`).
