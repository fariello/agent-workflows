## Project conventions discovered (Step 0)

- TESTS ASSERT OUTCOMES, NEVER CODE STRUCTURE. `AGENTS.md` forbids reading production source with `inspect`, `ast`, regex or substring search, forbids caller counts and symbol censuses as correctness proxies, and requires restored coverage to CALL the code and assert on real outputs (`GUIDING_PRINCIPLES.md` P16). This directly deletes three arms of the file being restored (F-07) and is why E-07 replaces a source-reading arm with a behavioral one. The surviving sibling file `tests/test_release_readiness_child_pin.py` states the same rule in its own docstring ("No source-reading or code-structure tests") and is the local precedent.
- A COUNT OR PROPERTY OVER THE LIVE `.aw/records/` TREE MUST NOT GATE A LANE. `pyproject.toml` defines the `livecorpus` marker for tests that assert a property over EVERY artifact in this repository's own records tree, and documents the measured reason they are deselected by default: a runner lane merges only if the suite passes, so one such test went red on three correctly-cleared plans and cost run `run-20260919T194413Z-2056285` 2h 10m with nothing integrated. `gate_ipd_lint`'s verdict is exactly such a property (F-04), which is why no restored arm asserts it and why this file carries no `livecorpus` marker: it needs none, because every arm is synthetic. `tests/test_lost_guard_census.py` is the local precedent for deliberately building fixtures instead ("References NEITHER the real trim commit shas NOR the live tree. Carries NO livecorpus marker").
- THE SUITE RUNS BARE. `pyproject.toml` `addopts` already supplies `-q -n auto --dist=worksteal -m 'not slow and not livecorpus'`, so validation uses `python3 -m pytest` with no added flags; `-o addopts=""` appears above ONLY for the narrowed per-file runs where per-test counts are needed, which is the documented exception.
- THE DELETED FILE WAS MARKED `slow`, AND THE RESTORATION SHOULD NOT BE. `git show 19313eed^:tests/test_release_readiness.py` carries `pytestmark = pytest.mark.slow` because its live-tree subprocess arms were heavy. Since every arm here is synthetic and the two subprocess gates already have their own file, the restored file runs in the DEFAULT fast suite, where it actually guards lanes, rather than in `make test-all` where a regression would surface late. This is a deliberate improvement on the deleted shape, not an oversight.
- A COUNT OVER A LIVE POPULATION IS RE-DERIVED, NOT MATCHED (repository plan-review convention). A suite total is a LIVE population that other lanes move, so an exact-match bar fails on correct work; the authoring figures in F-08 are dated context for orientation, and E-08 requires the executor's OWN before-and-after measurement.
- PER-MODULE TEST FILES ARE THE CONVENTION, and the name `tests/test_release_readiness.py` is FREE at authoring (the trim deleted it and nothing recreated it), so the restoration takes back its canonical name and sits beside the narrower `tests/test_release_readiness_child_pin.py`, matching the established pairing of `tests/test_run_analytics.py` with `test_run_analytics_cli.py`.

Cite code by SYMBOL (`module.function`) or by a quoted content string, with a line number only appended to one of those and never alone: an offset expires before this plan executes (spec `ipd-structure-and-linting` Section 10.2; advisory `IPD-C801`).
