## Goal

Make the decision order that plan `65cuw0` shipped falsifiable by a test, so the fix cannot be
silently reverted. Today it can: moving the merged branch back below the `holds_work` bail-out
restores the exact inert state `65cuw0` existed to remove, and the whole suite stays green.

The guard must be an OUTCOME guard. The deleted `TheNoDirectForceTeardownTests` pinned this same
property by parsing the reclaimer's AST and comparing line numbers, which the 2026-09-26 maintainer
ruling forbids and which would in any case be satisfied by a reordering that kept the line numbers and
changed the behavior. What this plan asserts instead is what an operator observes: for a merged,
accounted lane the worktree is GONE and `action` is `reclaimed`; for every shape that must survive,
the directory and its content are still there.

## Project conventions discovered (Step 0)

- WE TEST OUTCOMES, NEVER CODE STRUCTURE, and this rule is what decides the ENTIRE shape of this plan. `AGENTS.md`: "NEVER write or restore tests that read production source code using `inspect`, `ast`, regex, or substring search"; "restored coverage must always exercise the code ... and assert on real outputs, exit codes, and side effects (see GUIDING_PRINCIPLES P16)". The deleted guard for this exact property (`TheNoDirectForceTeardownTests::test_the_merged_decision_PRECEDES_the_holds_work_bail_out`) worked by `inspect.getsource` plus `ast.walk` plus a LINE-NUMBER comparison, so it is the excluded kind twice over and must not be restored.
- THE DELETED FILE MAY NOT BE RESTORED WHOLESALE, AND THE DIRECTIVE IS EXPLICIT. Backlog `xvp5vx` carries the maintainer's instruction that an audit of what the trim deleted "must strictly ignore tests that pinned code, AST, or text, and must never propose restoring them". Backlog `dwfmxz` repeats it for this file specifically. So the behavioral subset is re-authored and the structural subset is abandoned by design, not by omission.
- `reclaim_lanes_on_interrupt` HAS ONE BODY AND TWO HOST SHELLS, which is what makes a two-host table cheap and still meaningful. `runner_shared.reclaim_lanes_on_interrupt` holds the logic (its docstring: "ONE IMPLEMENTATION FOR BOTH HOSTS (`runresidue` `gqo6if` E-03)"), and each driver keeps a same-named wrapper that injects its own `_lane_reclaim_prompt`/`disable_lane_prompt` because those read and write a per-module `_LANE_PROMPT_DISABLED` through `global`. Driving the HOST symbol therefore tests the shell and the body together, which is the right surface.
- THE DECISION ORDER IS ALREADY DOCUMENTED AS LOAD-BEARING IN THE CODE, so this plan adds a guard for a stated invariant rather than inventing one. The shared docstring says "THE ORDER OF THOSE LAST THREE IS LOAD-BEARING AND WAS THE WHOLE DEFECT (laneorph `65cuw0`). The recovered check MUST precede the `holds_work` bail-out, because a merged lane is STILL `holds_work`", and `lane_is_recovered_and_reclaimable` calls itself "THE ONE PLACE THE DECISION ORDER IS EXPRESSED".
- THE TEARDOWN GATE HAS ONE DEFINITION AND THIS MODULE MUST CONSUME IT, NOT REIMPLEMENT IT. `runner_shared.reclaim_lane_through_gate` delegates to `lane_containment.teardown_lane_if_classified` and documents itself as "THE ONLY WAY THE INTERRUPT PATH MAY REMOVE A LANE". The tests drive the driver entry point and let it reach that gate; they never call the gate directly, because the thing under test is the ROUTE to it.
- RUN THE SUITE BARE. `AGENTS.md`: `python3 -m pytest`, with no added `-n0`, no second `-q`, no `-p no:randomly`; `pyproject.toml` `addopts` already supplies the quiet, parallel, fast-subset configuration, and `-o addopts=""` is the sanctioned way to get per-test counts from a narrowed run.
- Cite code by SYMBOL (`module.function`) or by a quoted content string, with a line number only appended to one of those and never alone: an offset expires before this plan executes (spec `ipd-structure-and-linting` Section 10.2; advisory `IPD-C801`).
