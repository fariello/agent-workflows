## Goal

Make `--fix` handle the third home class its own detector already knows about, by consuming the three-class redaction primitive the repository landed a day earlier, instead of keeping a second POSIX-only rewriter beside it. Today `_rewrite_line` applies only `_HOME_ANY_RE` and `_USERS_ANY_RE`, so a `<drive>:\Users\<user>` path is reported as needing manual edit (correct, if unhelpful) while a `<drive>:/Users/<user>` path is MANGLED into `c:~/proj/a.md`, a string that is no longer a valid path and no longer the leak either, with `--fix` exiting 0 and the follow-up scan reporting the tree clean. The fix is a delegation, not a new pattern: `agent_schema.redact_home_paths` already covers all three classes, preserves the drive prefix, is idempotent, and is pinned by its own tests.

F-07 explains why: the sanitizer's side carries rule names, a config-gated severity model, placeholder lookaheads and allowlists with no counterpart in the validator's single fused alternation.
