## Project conventions discovered (Step 0)

- THE REFUSAL MACHINERY IS ALREADY WRITTEN and returns a `CommandResult` with `changes`, `next_actions`, `verified=False` and `exit_code=2`. E-01 must route the newly-guarded path INTO it, never duplicate it.

- `--force` IS ALREADY TAKEN in this code path, meaning "act on all of an ambiguous multi-match" (`:1250-1257`), which is why E-02 prefers a dedicated override flag. THE PRECEDENT FOR DECLARING A NEW OVERRIDE is `--allow-open-questions`, registered on every surface reaching the gated path precisely so the gate cannot be bypassed by choosing another spelling (`cli.py:3219-3230`).

### OQ-01: Should the terminal-reopen override be a dedicated flag or should the transition be refused outright with no override?
