# IPD: Report a plan filename date that disagrees with its own Date metadata, as an advisory the measured corpus proves has no false-positive population

- Date: 2026-10-02
- Kind: child
- Concern: Nothing compares a plan's FILENAME date against the plan's own `- Date:` metadata, so the two can disagree indefinitely with no finding from any checker. Reproduced at authoring through the real CLI: a copy of pending plan `j7dsci` renamed to a `20260101-` leading date while its body still reads `- Date: 2026-10-01` draws `check.ipd-uncarried-obligation` and nothing else from `aw check plans`, with ZERO date findings of any kind. The cost is that the name's claim and the body's claim are each independently well-formed, so neither `ipd_schema.validate_metadata` (which now value-checks `- Date:` since `fqcax0`, but reads only the body) nor `check_engine.check_names` (which validates filename SHAPE, not its date's agreement with anything) has standing to complain. It is not hypothetical: `.aw/records/plans/executed/20260101-instsafe-07-qrokie-clean-delta-and-tracking-modes-design-spec.ipd.md` has carried a fabricated `20260101` since `05c4deb1` while its real date is `20260723`, and the wrong name then propagated into three live records and one tracked test fixture, all of which assert it (repairing that one record is `tf4jz5`; this plan is about DETECTING the class so the next one cannot sit unreported).
- Scope: Add ONE new advisory (`info`) check rule, `check.plan-date-filename-mismatch`, to the plans-type content path in `check_engine`, comparing each clustered plan's leading filename `YYYYMMDD` against its own parseable `- Date:` and reporting a disagreement. Register it in `RULE_REGISTRY` and pin it with behavioral tests driving the real engine over a synthetic tree. THE RULE IS UNCONDITIONAL AND NEEDS NO SET-CANONICAL EXEMPTION, which is the one substantive design finding of this plan and inverts the backlog item's stated premise: the exemption the item says a human must design first is measured UNNECESSARY, because a set-canonical date is shared per MEMBER with its OWN body date and never across members (F-04, F-05, F-06). OUT: every repair of any existing record (none is needed; the corpus is clean, F-03), the `20260101` fabricators in `plans_refs._plan_date` and `plans_archive._plan_date`, any widening to a non-plans artifact type, and any attempt to make the rule `warning` or `error` (F-10 fixes the tier at `info` for this change).

## Goal

Make a plan whose filename date contradicts its own `- Date:` metadata produce a finding, so the next fabricated or hand-typed filename date is reported at the moment it enters the tree instead of surviving for months and propagating into other records by citation.

The deliverable is one advisory rule, `check.plan-date-filename-mismatch`, registered `info` in `check_engine.RULE_REGISTRY` and wired into the plans-type content path so both `aw check plans` and the `aw check all` fan-out reach it exactly once. It fires when, and only when, a plan's name parses as clustered AND its `- Date:` parses as an ISO calendar date AND the two dates differ.

THE MEASURED EFFECT IS A QUIET RULE THAT CHANGES NO EXIT CODE TODAY. The whole 1198-file clustered plan corpus currently has ZERO disagreements (F-03), so the rule reports nothing on this tree on the day it lands; `info` does not contribute to exit 1 under the published severity contract (F-10), so no existing caller's exit behavior changes even when it does fire. Its value is entirely prospective: it is a tripwire for the class of defect that already cost this repository one record's date for two and a half months.

WHAT THIS GOAL DELIBERATELY DOES NOT CLAIM. It repairs NO existing record, because the corpus needs no repair and the one historical casualty is owned by `tf4jz5`. It does not touch the two `20260101` fabricators, so a plan with an unparseable `- Date:` still gets `20260101` substituted by `plans_refs._plan_date` (`949enf`) and `plans_archive._plan_date` (`dkfthf`); the new rule cannot even see that case, because it requires BOTH dates to parse before it compares them, which is the deliberate fence that keeps it from double-reporting `fqcax0`'s `IPD-M104`. It does not extend to specs, research, backlog, prompts or walkthroughs even though research measurably has 3 disagreements (F-07, OQ-02). And it does not promote the rule above `info`, which is a decision the corpus cannot yet justify (F-10, OQ-01).

## Project conventions discovered (Step 0)

- Cite code by SYMBOL (`module.function`) or by a quoted content string, with a line number only appended to one of those and never alone: an offset expires before this plan executes (spec `ipd-structure-and-linting` Section 10.2; advisory `IPD-C801`).
