## Project conventions discovered (Step 0)

- P16 NAMES THIS EXACT TEST AS ITS SANCTIONED EXCEPTION, which is what makes E-08 permissible rather than a code-structure pin. `GUIDING_PRINCIPLES.md` Section 16's "The one narrow exception" bullet permits content verification "where the text or file itself is the artifact under test (for example, verifying published documentation does not cite deleted test files, or checking that test modules do not attempt network installations in offline suites)". The backlog item anticipated this ("a repository-CONTENT check ... not a production-source-text pin") and it is confirmed verbatim in the principle.
- A TEST ASSERTING OVER `.aw/records/` MUST BE `livecorpus` AND IS DESELECTED BY DEFAULT, which decides E-08's scan root. `pyproject.toml`'s `markers` entry records the reason with a measured cost (2026-09-19: one such test went red on three correctly-cleared plans, costing 2h 10m and $55.02 with nothing integrated) and `addopts` carries `-m 'not slow and not livecorpus'`. A records-tree scan would therefore have to be deselected to be safe, and a deselected test cannot catch the next deletion.
- CITE BY SYMBOL OR CONTENT, NOT BY A BARE LINE NUMBER (spec `ipd-structure-and-linting` Section 10.2; advisory `IPD-C801`), because offsets expire before a plan executes. This plan's own item measurements bear that out: the backlog item anchored its sharpest case at line 91 of `docs/cli-output-contract.md`, and that offset no longer holds, because the surrounding section was rewritten by `44323024` and the sentence containing `enforces both pairs across the CLI surface` now sits well below it. Every E-item here therefore locates its edit site by a quoted content string.
- THE COMMIT THAT CREATED THIS DEFECT CLASS IS ONE TRIM, AND ANOTHER IS A DELIBERATE RETIREMENT. `19313eed` (2026-09-24, "trim test suite from 9,136 to under 2,000 tests") deleted `test_release_readiness.py`, `test_security_hardening.py`, `test_wtiso_taxonomy_freeze.py`, `test_packaging.py` and `test_flag_surface_uniformity.py`; `d4dd6b88` (2026-09-18, "retire change-detector tests over code text and prose") deleted `test_wtiso_characterization.py`. The distinction matters: the second was a P16-motivated retirement of tests that pinned code text, so the doc passage recording it is a correct record, not debris.
- `chore` VERSUS `bug` TURNS ON USER-PERCEPTIBLE IMPACT (`AGENTS.md`), and a live `bug` must carry `- Blocks-Release:`. Editing prose is imperceptible, so `chore` is right for THIS plan; whether the coverage holes E-07 files are `bug` is a separate judgement E-07 requires the executor to state with its reasoning rather than assume.
