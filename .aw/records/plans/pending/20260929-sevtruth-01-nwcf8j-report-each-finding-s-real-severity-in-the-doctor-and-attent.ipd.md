## Goal

Make every `aw` surface that tells a human or agent how serious a finding is read that from the finding's SEVERITY, and make every surface that tells them HOW MANY findings there are count all of them. After this plan `aw doctor`'s summary line accounts for every finding it reports, `aw attention`'s machine payload preserves an advisory as advisory, and a behavior test module keeps both from regressing.

## Required tests / validation

One new behavior test module, `tests/test_severity_truth_surfaces.py` (E-04, E-05), is the durable verification. It drives the real `aw doctor` and `aw attention` CLIs over fixture repositories and asserts three properties: doctor bucket count conservation (`git + names + version + other == total`), attention severity preservation (a non-`error` drift severity survives into the rendered diagnostic), and exit-code independence (neither fix moves the exit code, since `drift_exit_code` is untouched). Each must fail against the base and pass after its fix; demonstrating that failure is required by V-04 and V-05, because a test that passes both before and after proves nothing.

Beyond it: E-01's reproduction of both defects with independently computed numbers, E-06's bare `python3 -m pytest`, a re-measurement of both surfaces by the same method E-01 used, `python3 -m agent_workflows check all` for new findings, and `aw sanitize --agent`.

HOW THE ASSERTIONS AVOID THE STALE-NUMBER TRAP. The live-tree numbers in this plan (87 findings, 63 unbucketed, 35/17/11 by rule, 24 in `names`) are measurements on a SHARED, CONCURRENTLY-EDITED tree and WILL move before this executes. No `V-*` may assert any of them. Every live-tree check asserts a RELATION measured inside ONE run (the rendered buckets against that same run's total; the rendered severity against that same run's drift severities) or a SHAPE (a nonzero unbucketed remainder exists before the fix; none after). The fixture-repo tests own the deterministic assertions.

HONEST LIMITS ON WHAT THIS PROVES. First, count conservation proves no finding is EXCLUDED from the doctor summary, not that the three named categories are the right categories to show; that question is untouched. Second, severity preservation proves the payload reports what the drift carries, not that every rule carries the RIGHT severity: five rules relevant here are unregistered and default to `error` (deliberately deferred above), so this plan makes the display honest about the data without auditing the data. Third, the item's own `cli.py` symptom is NOT fixed by this plan and a validator must not claim it is; `tzjtg4` fixes it, and E-01 verifies only that the ownership boundary still holds.
