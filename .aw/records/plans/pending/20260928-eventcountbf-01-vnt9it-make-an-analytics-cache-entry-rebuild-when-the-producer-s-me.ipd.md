- Date: 2026-09-28
- Kind: child

## Goal

Make the analytics cache notice that its PRODUCER changed, not merely that its INPUTS changed, so a metric key added by a future change cannot read as missing on every historical run until somebody remembers to run a rebuild by hand. Backlog `36nh0o` asks for that hand rebuild; this plan discharges the obligation durably by making the next ordinary `aw runs analyze` do it automatically, and records the measurement showing the one-off sweep it asks for is already a no-op here.

## Project conventions discovered (Step 0)

- Cite code by SYMBOL (`module.function`) or by a quoted content string, with a line number only appended to one of those and never alone: an offset expires before this plan executes (spec `ipd-structure-and-linting` Section 10.2; advisory `IPD-C801`).
- THE CACHE TREE IS DISPOSABLE BY DESIGN, and that is the convention that makes this fix cheap. `run_analytics_cache`'s module docstring states "a cache entry that cannot be read is REBUILT" and that the tree is gitignored, so invalidating entries costs recompute and never migration. Measured recompute cost on a 298-run synthetic corpus of the same size as the live one: a cold sweep took 6.76s against 0.44s warm, i.e. about 22.7ms per run and about 6.3s of extra one-time cost for the whole corpus.
- THE PATH IS NEVER COMPOSED BY HAND. `cache_root` delegates to `runner_shared.analytics_cache_dir`, and that module's docstring says hand-composing `<repo>/.aw/records/runs` "would reintroduce exactly the hardcoded-literal defect that resolver exists to remove". Every test here must resolve through `cache_mod.cache_root(repo)` / `cache_mod.entry_path(...)`.
- OMIT, NEVER ZERO-FILL. `run_analytics._metric_payload` documents that "every absent value is OMITTED rather than zero-filled, which is what keeps the persisted form from asserting a count nobody observed", and `event_count=None` versus `0` is the live case: a run with no `events.jsonl` gets no key, a run with an empty one gets a real `0`. No item here may fill a missing key.
- A REASON CODE IS A CONTRACT, NOT A DEBUG STRING. `CacheDecision`'s docstring says "``verdict`` values and ``reason`` codes are stable machine-readable tokens rather than prose", and `docs/run-analytics.md` publishes the whole table to operators. E-02 therefore REUSES `fingerprint-changed` and amends its prose rather than minting a new token.
- TESTS ASSERT OUTCOMES, NOT CODE STRUCTURE. `GUIDING_PRINCIPLES.md` section "16. Test outcomes and behavior, never code structure or text" prohibits `inspect.getsource`, `ast.parse`, `read_text()` and substring or regex searches against production code to verify implementation details, and the repository execution contract repeats it. E-03 must therefore derive the producer's real key set by RUNNING the producer over a fixture run.
- THE SUITE RUNS BARE. `pyproject.toml` `addopts` already supplies `-q -n auto --dist=worksteal -m 'not slow'`; a narrowed per-file count needs `-o addopts=""` rather than `-n0`.
