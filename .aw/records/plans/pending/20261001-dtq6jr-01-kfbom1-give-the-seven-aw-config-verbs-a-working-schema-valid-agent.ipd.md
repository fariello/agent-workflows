## Project conventions discovered (Step 0)

- THE ABSENT SYMBOL NEVER EXISTED, so this is not a regression to revert but a branch that was never exercised. `git log --all -S "def format_agent_json"` returns exactly one commit, `e962c91c6`, which adds a PLAN that quotes the string; no commit on any branch ever defined it. `git log --all -S "format_agent_json"` shows the import arriving with the two feature commits that added these verbs (`18226ebd5` and `8e02853d9`), so the branches have been dead since the day they were written.
- `render_jsonl_record` VALIDATES BEFORE IT SERIALIZES, which is what makes a hand-built record safe. `agent_schema.render_jsonl_record` calls `assert_valid_agent_record` as its first statement, so an invalid record RAISES instead of being written. That is why defects 2 and 3 are not cosmetic: supplying an emitter without fixing them converts a crash into a different crash.
- `CommandResult.to_agent_record` DOES NOT COPY `data`, and this is the single most load-bearing convention here. It builds a fixed key set (`schema`, `kind`, `cmd`, `outcome`, `exit`, `verified`, `complete`, plus optional `applied`/`target`/`checked`/`findings`/`changes`/`evidence`/`diagnostics`/`next`) and reads `data` only for `repo_root`, `target`, `applied`, `checked`, and `findings`. Arbitrary keys in `data` are DISCARDED, in compact and verbose mode alike.
- `Evidence` IS NOT A PAYLOAD CHANNEL EITHER, in compact mode. `agent_schema.sanitize_evidence_item` returns `f"{key}:{value}"` only for a scalar; for a list, dict, or None it returns the BARE KEY and discards the value. So `Evidence(key="value", value=["~/src"])` renders as the string `"value"`.
- THE VALIDATOR WALKS NESTED STRINGS, so a payload is only as clean as its deepest leaf. `_check_string_values` recurses through dicts and lists and reports the dotted path of the offender (measured: `config.repos.search[0]`). A nested foreign home path is therefore refused exactly as a top-level one is.
- `config._preserve_home` IS THE REPOSITORY'S OWN SANITIZER FOR THIS CASE and these handlers already call it. It folds a path under the CURRENT user's home to `~/...` and leaves others absolute; the `~` form is accepted by the validator and the absolute form is refused. `config.load` applies it to `repos.*` entries through `_coerce_repo_list`, which is why the operator's own paths are already clean on the whole-config payload and a foreign user's are not.
- THE MACHINE EXIT VOCABULARY IS NARROWER THAN THE HUMAN ONE. `agent_schema` admits `exit` only in `(0, 1, 2)` and enforces parity: exit 2 requires outcome `cannot-run` or `error`, exit 1 refuses the positive outcomes, and an `error` record must carry exit 2 and may not be `complete`. The `config` family's declared `exit_contract=(0, 1, 2)` fits entirely inside this, so no exit code needs to change anywhere in this plan.
- ONLY ONE OF THE TWO SUITES THAT OWN THESE HANDLERS IS `slow`-MARKED, CORRECTED AT REVIEW (PR-004). `tests/test_cli.py` carries a module-level `pytestmark = pytest.mark.slow` at line 29 and IS deselected by the `addopts` `-m 'not slow and not livecorpus'` (measured: `--collect-only -q` on it reports `64 tests were deselected`). `tests/test_config.py` carries NO `pytestmark` and does not import `pytest` at all; it is DEFAULT-COLLECTED, and `--collect-only -q` reports `tests/test_config.py: 31`. The authored claim that both are `slow` is false for `test_config.py`. E-05 still adds a NEW file rather than extending `test_config.py`, but for a different and better reason: the new cases drive the CLI as a SUBPROCESS to observe the real process exit code, while `test_config.py` is an in-process `unittest.TestCase` suite using `redirect_stdout`, so the two have incompatible harnesses. The `slow`-mark hazard E-05 must actually avoid is introducing one on the NEW file.
- `XDG_CONFIG_HOME` IS THE ISOLATION MECHANISM for these verbs and it is sufficient. `config.config_dir` honors it before falling back to `~/.config`, and `tests/__init__.py` already redirects it suite-wide. Verified in this lane that a subprocess with it set writes only under the temp directory.
- TESTS MUST ASSERT OUTCOMES, NOT CODE STRUCTURE (AGENTS.md P16). No `inspect`, no `ast`, no regex over production source, no call-site censuses. This rules out the tempting "assert `format_agent_json` no longer appears in `cli.py`" check, which is unnecessary anyway: a branch that still crashes cannot emit a valid record.
- `/home/<other>/` IN THIS PLAN IS A PLACEHOLDER AND WILL NOT REPRODUCE ANYTHING IF COPIED LITERALLY. This matters because this plan's subject IS home-path sanitization, so the one string it most needs to quote is the one it is least able to write down. Both the leak-sanitizer's `home-path` rule and `agent_schema._HOME_PATH_RE` carry the SAME placeholder allowlist (`/home/u/`, `/home/alice/`, `/home/user/`, `/home/USER/`, and any `/home/<...>`), so a literal `/home/<other>/...` is ACCEPTED by the very validator this plan's findings describe REFUSING it (verified both ways). Every quoted example is therefore written with the placeholder to keep this file committable, and an executor reproducing F-04 or F-09 must substitute a path under a real, non-placeholder user name. If a reproduction unexpectedly passes, suspect the placeholder before concluding the defect is fixed.

- Status: resolved
