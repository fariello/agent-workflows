# IPD: Carry the rename and group facts out of the backends in a typed MutationResult

- Date: 2026-10-01
- Kind: child
- Concern: `aw rename <type>` and `aw group <type>` DISCARD every fact a machine consumer would need, keeping only `rc` and a flat tuple of touched paths. `plans_refs.MutationResult` is `(rc: int, touched_paths: Tuple[str, ...])` and that is the entire structured surface; the per-file old/new pair, the preview-versus-applied distinction, the reference-rewrite edits, the setid warning and the error text all exist only as arguments to bare `print()` calls inside `plans_refs.apply_renames`, `artifact_rename.run_rename_generic`, `artifact_rename.run_group_generic` and `research_refs`. So no caller CAN build a payload today, however the renderer is wired: the facts are gone by the time the backend returns. This plan makes the backends return what they already computed. It emits nothing new on any stream.
- Scope: Widen the shared `MutationResult` with optional, defaulted fields carrying the facts these backends ALREADY compute (per-target old/new path pairs, whether the run applied or previewed, the reference-rewrite edits, diagnostics for the refusal paths), and populate them in all four backend modules WITHOUT changing one byte of emitted output or one exit code. Human stdout stays byte-identical, measured, because the `print()` calls are left exactly where they are; the payload that consumes these fields is Order 02's job. EXCLUDES: emitting anything, reading `args.json`/`args.agent` anywhere in a backend, and touching `plans_index`/`research_index`.

## Goal

Make the four rename/group backend modules RETURN the facts they already compute, by widening the shared `MutationResult` with optional defaulted fields, so that Order 02 has something to build an `aw.agent/v1` payload out of. This plan is deliberately invisible: no stream changes, no exit code changes, no flag reads. It exists as its own Order because the alternative, building the payload and the fact-plumbing in one pass, would mix a wide mechanical change across four modules with a narrow behavioral change at one dispatch site, and a reviewer could not tell which half broke a given test.

## Project conventions discovered (Step 0)

- Cite code by SYMBOL (`module.function`) or by a quoted content string, with a line number only appended to one of those and never alone: an offset expires before this plan executes (spec `ipd-structure-and-linting` Section 10.2; advisory `IPD-C801`).
- THE CONTRACT THIS SET SERVES IS ALREADY WRITTEN, which is why the Set is a bug fix and not a feature. `docs/cli-output-contract.md` Section 7 reserves stdout "strictly for final structured results (the interactive human view or machine JSONL records)"; Section 11.3 specifies the mutation convention verbatim ("Previews emit `outcome: "preview"`, `applied: false`, `complete: true`, `changes: [...]`, and a `next` command with `--apply`"); and implemented spec `command-surface-redesign` R4 ("Every cross-cutting verb: `--json` (structured) where a machine consumer benefits, documented exit codes (0/1/2)") plus AC5 ("Every cross-cutting verb honors `--json`/`--agent`") require it. `rename` and `group` are two of the seven cross-cutting verbs that spec defines.
- `MutationResult` HAS NO TEST CONSUMERS, which is what makes widening it safe. Measured: `rg -l "MutationResult" tests/` returns nothing. Its only consumers are `cli._run_noun_verb` (which reads `.rc` and `.touched_paths`) and the `research_cmd in ("set-assign", "mv")` branch (which reads the same two). A `NamedTuple` with defaulted fields appended is therefore source-compatible at every site.
- THE BACKENDS DELIBERATELY PERFORM NO COMMIT, and that must stay true. `MutationResult`'s own docstring records why: "group/rename backends ... RETURN this instead of a bare int so the CALLER ... can place the `git_commit_helper.offer_commit` offer ONCE at the call site (PR-012: never inside a shared backend, or `aw group research` would double-fire)". The same argument applies to emitting a payload, which is why Order 02 emits at the dispatch site and this plan adds no emission anywhere.
- THE REGENERATED MANIFESTS ARE NOT PART OF ANY PATH-SET. `MutationResult`'s docstring states there is "deliberately no `index_paths` companion" because the INDEX.json/INDEX.md manifests "are generated output that no `aw` verb commits (idxuntrack `4r0qp1` E-03)". So the new `targets` field must NOT include them either, even though Order 03 silences the line that announces them.
- THE SUITE RUNS BARE. `pyproject.toml` `addopts` already supplies `-q -n auto --dist=worksteal -m 'not slow and not livecorpus'`. Run `python3 -m pytest` with no added flags; use `-o addopts=""` only when per-test counts from a narrowed run are genuinely needed.
