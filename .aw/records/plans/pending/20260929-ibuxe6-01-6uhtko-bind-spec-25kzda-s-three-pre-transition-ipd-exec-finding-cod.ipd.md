## Goal

Turn three of spec `25kzda` Section 4.6's unbound `IPD-EXEC-*` names into a shipped, importable, enumerable vocabulary whose every row RECORDS, HONESTLY, what a shipped predicate does and does not decide about it, using the exact `RunFindingCode` convention the `RUN-*` family already established. After this plan a consumer (the retryable-class allowlist, a driver report, a future verifier) can key on a CODE whose binding field states truthfully whether a predicate answers that code's whole question. The spec's own admitted gap is thereby DECLARED for three of its eleven codes and DISCHARGED for the one of those three a shipped predicate wholly decides, rather than papered over for all three (F-13).

THE GOAL IS AN HONEST TABLE, NOT THREE BINDINGS, and the difference is the whole safety argument. The module's own comment above `BOUND`/`UNBOUND_BY_DEPENDENCY`/`UNBOUND_UNBUILT` states that "a code silently wired to a predicate that does not answer its question is a fail-OPEN checker - it passes because nothing was checked", and that "a binding is recorded only where a shipped predicate genuinely answers THAT code's question". Review MEASURED (F-13) that two of the three rows' `pass_criterion` clauses are NOT fully decided by any shipped predicate, so writing `BOUND` on all three would have shipped exactly that fail-open state. A row that says `UNBOUND_BY_DEPENDENCY` and NAMES the undecided clause is strictly more useful to the next reader than a row that says `BOUND` and is wrong, because the first tells a consumer that the check did not run while the second invites it to treat an unrun check as a pass.

## Project conventions discovered (Step 0)

- Cite code by SYMBOL (`module.function`) or by a quoted content string, with a line number only appended to one of those and never alone: an offset expires before this plan executes (spec `ipd-structure-and-linting` Section 10.2; advisory `IPD-C801`).
- A FINDING-CODE ROW RECORDS ITS OWN BINDING STATE, AND THE THREE STATES ARE ALREADY DEFINED. `run_evidence` ships `BOUND`, `UNBOUND_BY_DEPENDENCY` and `UNBOUND_UNBUILT` with the reason stated at the definition: "An unbound code that HONESTLY REPORTS ITSELF UNBOUND is safe ... A code silently wired to a predicate that does not answer its question is a fail-OPEN checker". This plan therefore does not invent a vocabulary for "bound"; it uses the one that exists, and it may only write `BOUND` where a shipped predicate genuinely answers THAT code's question.
- THE `RUN-*` BLOCK DELIBERATELY INTRODUCED THIS CONVENTION FOR OTHERS TO FOLLOW. Its comment says the policy "has to be readable in ONE place and enumerable by a test", names the parallel `EV-*` taxonomy as the counterexample ("docstring prose plus inline literals, so no test can enumerate them and a reworded message drifts silently"), and states that it "deliberately INTRODUCES the convention `EV-*` should have had". An `IPD-EXEC-*` table in the same module, with the same record type and the same accessors, is the intended use of that convention rather than a new one.
- A BOUND ROW MUST NAME ITS PREDICATE AND AN UNBOUND ROW MUST NAME WHAT IT WAITS ON, enforced at runtime. `validate_finding_table` fails `RC-BINDING` when a `BOUND` row carries no predicate, when a `BOUND` row also declares `waiting_on`, when an unbound row claims predicates, or when an unbound row does not say what it waits on. The new table's validator must enforce the identical rule, because the rule is the whole reason the `binding` field is trustworthy. NOTE WHAT THIS RULE DOES NOT CHECK, which is what made F-13 possible: it verifies that a row's binding claim is INTERNALLY CONSISTENT, never that a named predicate actually decides the row's `pass_criterion`. Only a human or a driven test can check that, which is why E-02 is a measurement and E-05(c) is a pin.
- THE SHAPE OF AN HONEST `waiting_on` IS ALREADY ON DISK and is the model E-02 copies. `RUN-COMMIT-CONTENTS` reads "a trailer READ-BACK predicate. `runtrail-01` (`m73aet`) executed and `git_commit_helper.run_item_trailers` WRITES `AW-Run:`/`AW-Item:`, but nothing reads a trailer back or proves a commit's tree diff equals the item-owned delta". It names the MISSING predicate, names what DOES exist so a reader is not misled into rebuilding it, and cites the receipt establishing the gap. It also shows that naming a symbol in `waiting_on` prose is not a `predicates` claim. Two such rows have shipped in that state since 2026-09-05 with no carrier, which is the precedent for this plan's two unbound rows.
- PREDICATES ARE RECORDED AS `module.symbol` STRINGS, NOT AS IMPORTS, and the stated reason is that "a test can prove each one still resolves, which is what stops the mapping rotting silently". That also keeps `run_evidence` free of the dependency edge; F-08 measured that neither `run_evidence` nor `ipd_lint` currently loads the other.
