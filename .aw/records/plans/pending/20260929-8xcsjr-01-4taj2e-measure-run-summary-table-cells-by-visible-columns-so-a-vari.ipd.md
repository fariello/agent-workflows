# IPD: Measure run-summary-table cells by visible columns so a variation selector cannot misalign the box

- Date: 2026-09-29
- Concern: `render_stream.render_run_summary_table` measures every padded element of its box-art table with `len()` over ANSI-stripped text. Stripping ANSI is correct and is not the defect; the defect is that `len()` counts a ZERO-WIDTH code point as one terminal column, so any measured text containing a combining mark, an enclosing mark, or a format control (Unicode `Mn`/`Me`/`Cf`) is over-measured and the affected line renders one column SHORT, breaking the box. `term.visible_width` is the shared primitive that does both halves (it is built on `strip_ansi` and skips those three categories) and `render_stream` already imports `term` as `_T` and already consumes `_T.visible_width` in `format_activity_cell`, so no new import and no new helper is needed. Measured at authoring HEAD `d21651b2`: a single `Set` cell containing `⚠︎` (U+26A0 U+FE0E) renders that row at 120 visible columns inside a 121-column box, and an `exit_reason` banner containing one NFD-decomposed accent renders that banner line at 237 inside a 238-column box. Fourteen measurement sites in the one function share the defect.
- Scope: Convert every padding and column-width measurement inside `render_run_summary_table` to `term.visible_width`, and add behavioral regression coverage that asserts the box is rectangular in visible columns when a cell or banner carries a zero-width code point. IN: the thirteen `len()`-based measurements the function uses for padding (the `col_widths` seed and loop, the totals-column width pass, the three banner pads and the banner-driven `Set`-column widening, the header pad, the row-cell pad, the totals-label pad, and the three totals-metric cell pads), plus a new test module. OUT: any change to which columns exist, their order, their alignment, the box-drawing characters, the status vocabulary, the diagnostics block (which is not padded), the ambiguous-width problem spec `uonrjg` Section 9.4 declines to solve, and the identical `len()`-based measurements in this module's OTHER functions (`format_statusline_lines`, `format_event_prefix`), which are separate surfaces with their own pinned tests.

## Goal

Make the run summary table rectangular in VISIBLE TERMINAL COLUMNS for every input, not only for inputs whose code-point count happens to equal their column count, by routing all of `render_run_summary_table`'s padding arithmetic through the one shared measurement (`term.visible_width`) the repository already built for exactly this.

Close the coverage hole that let this ship: no existing test measures the rendered width of any summary-table line, so a box that misaligns by one column passes the whole suite silently.

## Project conventions discovered (Step 0)

- `term.visible_width` IS THE ONE SANCTIONED MEASUREMENT and using it is following precedent, not setting it. Spec `uonrjg` Section 9.4 requires "no use of `len(styled_text)` to compute a visible column" and permits "a shared display-width helper" while forbidding "per-renderer width guesses". `term.py` is that shared home (its own section comment says so) and `attention.py`, `run_viewer.py` and `render_stream.format_activity_cell` already consume it. So E-01 removes a per-renderer guess rather than adding a helper.
- `render_stream` MAY IMPORT `term`, and already does: `from agent_workflows import term as _T` at module scope, guarded by a comment explaining why this module's import discipline permits it. No import barrier stands in the way, exactly as backlog `8xcsjr` says.
- ASSERT THE INVARIANT, NOT THE BYTES. This repository forbids code-pinning tests (`GUIDING_PRINCIPLES` P16) and forbids tests that read production source with `inspect`/`ast`/regex. So E-02's guard measures RENDERED OUTPUT, and E-02's byte-identity check compares two renders rather than a stored blob.
- STAGE A MUTATION IN MEMORY, NOT BY EDITING A TRACKED FILE. This is a shared checkout; a `git checkout --` restore after a long suite run can discard a co-worker's concurrent edit. An out-of-tree pytest plugin on `PYTHONPATH` that re-execs patched source and rebinds the symbol works here and was used for every fix-side measurement in this plan.
- RUN THE SUITE BARE (`python3 -m pytest`). `pyproject.toml` `addopts` already supplies `-q -n auto --dist=worksteal -m 'not slow and not livecorpus'`; adding `-n0` makes it several times slower, a second `-q` suppresses the summary line this plan requires be pasted, and `-p no:randomly` disables the order randomization.
- THE DIAGNOSTICS BLOCK IS NOT PADDED and therefore cannot misalign. Verified by rendering a `merge-refused` item whose deferral reason carries a combining mark: the box stayed at one width (123) and the reason printed correctly. This bounds the fix to the padded region and is why the diagnostics block is out of scope.
- Cite code by SYMBOL (`module.function`) or by a quoted content string, with a line number only appended to one of those and never alone: an offset expires before this plan executes (spec `ipd-structure-and-linting` Section 10.2; advisory `IPD-C801`).
