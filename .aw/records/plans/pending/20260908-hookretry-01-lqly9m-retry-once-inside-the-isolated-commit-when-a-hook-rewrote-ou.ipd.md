## Goal

Stop charging every agent a commit round trip for a stripped trailing space, without weakening any hook that legitimately refuses. Two independent levers: make a self-rewrite rejection recoverable in one bounded retry, and stop producing the whitespace the hook objects to.

## Project conventions discovered (Step 0)

- THE COMMIT NO LONGER HAPPENS WHERE THE ITEM SAYS. `offer_commit` delegates to `commit_lock.commit_isolated` (`git_commit_helper.py:559`), which commits in a throwaway detached worktree so pre-commit's stash/restore cannot clobber a peer's in-flight edit. That relocation is the single most important fact for this plan.
- CITATION CORRECTIONS APPLIED IN REVIEW (F-22), because two were load-bearing: the `writer_lock` window is `git_commit_helper.py:530` (the plan said `:459`), the `ISO_NOTHING` -> `STATUS_NOTHING_TO_COMMIT` mapping that E-02 now depends on is `:571-574`, and the `commit_isolated` delegation is `:559` (the plan said `:488` throughout). Re-locate by symbol if any drift again.
- FINALIZE SHARES THIS EXACT CODE PATH, so every change here reaches it: `ipd_lifecycle.py:2740` calls `commit_isolated` directly (OQ-01, resolved). It is also the caller that passes an absent path by design (`:2591`, `:2710`).
- `atomic_write` IS NOT THE ONLY WRITE PATH AND IS NOT MARKDOWN-ONLY. `ipd_authoring` keeps a duplicate (`:214-228`) that plans are written through, and the core helper also carries JSON/config writers and the verbatim-preserved research tree. See F-17/F-18/F-19; E-05, E-06 and E-10 are scoped accordingly.
- `commit_isolated`'s docstring (`commit_lock.py:157-183`) records four MEASURED properties, one of which directly constrains this work: "The hooks STILL RUN and STILL GATE: a deliberately failing hook rejected the commit and nothing landed. This is emphatically NOT `--no-verify` in disguise." A retry must preserve that for the refusal case.
- The branch advance is a COMPARE-AND-SWAP (`:270`), returning `ISO_RACED` (`:272-279`) when a peer commit landed meanwhile, because a blind `update-ref` was reproduced discarding a peer commit. A retry must not bypass it.
- `IsolatedCommitResult` (`:124-133`) and `CommitOutcome` (`git_commit_helper.py:250-262`) are both `NamedTuple`s with positional contracts, so new fields need defaults and must be appended.
- The status vocabularies are separate and both must be respected: `ISO_COMMITTED`/`ISO_NOTHING`/`ISO_HOOK_REJECTED`/`ISO_RACED`/`ISO_ERROR` (`commit_lock.py:136-140`) and `STATUS_COMMITTED`/`STATUS_SKIPPED`/`STATUS_DECLINED`/`STATUS_REFUSED_DIRTY`/`STATUS_NOTHING_TO_COMMIT`/`STATUS_ERROR` (`git_commit_helper.py:242-247`).
- Four hooks rewrite-and-reject; the read-only local hooks never rewrite. Mutating: `trailing-whitespace` (`.pre-commit-config.yaml:15-16`), `end-of-file-fixer` (`:17-18`), `ruff --fix` (`:31-33`), `ruff-format` (`:34-35`). Their shared exclude covers only `.agents/docs/research/`, `.aw/records/docs/research/` and `.aw/system/`. Read-only refusals: `local-leaks` (`:42-47`), `ipd-executed-transition-gate` (`:55-60`), `ipd-status-untooled-gate` (`:69-74`).
- The argv contract test is a real fence and should be leaned on, not worked around: it forbids `-A`, `--all`, `-a`, `push` and `--no-verify` across every recorded git call (`tests/test_git_commit_helper.py:60-77`).

## Proposed changes (ordered, validatable)

1. Detect a self-rewrite inside `commit_isolated`, hashing the WORKTREE copies, with an absent path treated as a sentinel rather than a crash (E-01).
2. Retry exactly once on a rewrite; never on a refusal; never loop; return `nothing-to-commit` when the hook's fix erases the whole diff (E-02).
3. Carry the rewritten paths out on both result types and into the human message (E-03).
4. Preserve and prove the shared-checkout and argv-contract properties across both attempts (E-04).
5. Reconcile the shared tree with the committed bytes under a content compare-and-swap, and correct the docstring invariant the retry falsifies (E-09).
6. Normalize per-line trailing whitespace in `atomic_write`, markdown only, research trees exempt (E-05).
7. Document the hard-break tradeoff at the normalization site; do NOT touch `.editorconfig` (E-06).
8. Delegate `ipd_authoring._atomic_write` to the core helper so plans inherit the normalization (E-10).
9. Add the rewrite, refusal, empty-retry, reconciliation, and deletion fixtures at both layers (E-07).
10. Verify one lock and one worktree per call even with a retry, and that a peer write survives both the hook window and the write-back (E-08).
