# IPD: Delete the two dead divergent FULL_AUTO constants from runner_shared and pin that no third actor can reappear

- Date: 2026-09-28
- Kind: child
- Concern: `runner_shared` defines `FULL_AUTO_ACTOR = "aw-driver/full-auto"` and `FULL_AUTO_APPROVAL_MESSAGE = "Auto-approved via --full-auto (review passed all gates)"`, neither read by anything and neither matching either host. Remove the two-name trap in `runner_shared` that would misattribute permanent plan history if a future consolidation read it, and leave behind a test that fails rather than a comment that asks to be read. ## Project conventions discovered (Step 0)

- A SHARED CONSTANT IS A MISATTRIBUTION HAZARD ONLY BECAUSE `ast.unparse` MATCHES ON THE NAME. `tools/runner_fork_scan.py`'s module docstring states this as the scanner's "most important limitation" and names this exact pair as the measured case: "two bodies that both read `FULL_AUTO_ACTOR` compare EQUAL while resolving to different strings per host". Its `_value_differs` helper exists solely to answer what the identity report cannot. So the guard E-01 adds is the in-suite form of a check the repo already built as a tool, and it must compare RESOLVED values, not source text.
- THE FORK SCANNER'S `--triples` REPORT DOES NOT COVER CONSTANTS. Its census reads top-level `def`/`class` symbols; run at this HEAD it reports `triples: ['StallWatchdog']` and does not list `FULL_AUTO_ACTOR` at all. That is why this plan's guard belongs in the suite rather than as a scanner flag: the scanner is a tool a human chooses to run, and this defect survived two Sets that ran it.
- `HostLabels` IS THE SANCTIONED SEAM FOR A HOST-VARYING STRING, WITH NO DEFAULTS BY DESIGN. Its docstring states the reason in the same terms this plan needs: a value "reaches a plan's PERMANENT finalize record", so "a defaulted or empty value would misattribute in durable history", and "a plain mapping with `.get()` is the one form this must not be (plan `tx6q0h` OQ-02)". `full_auto_actor` is already a field of it and both hosts already read it.
- THE HOST CONSTANTS ARE ALREADY DERIVED, NOT DUPLICATED. `oc_runipd.FULL_AUTO_ACTOR = runner_shared.OC_HOST_LABELS.full_auto_actor` and the agy twin read the descriptor rather than re-spelling the literal, with a comment recording that this is `li44r9` E-08's work so the name "and `OC_HOST_LABELS.full_auto_actor` CANNOT DISAGREE". So the backlog item's second fix direction ("make it the single definition with the HOST-identifying value supplied through the existing HostLabels descriptor") is ALREADY SHIPPED; what remains is only the deletion. This is the finding that decides OQ-01.
- DELETING A `runner_shared` NAME IS NOT A PUBLIC-API CHANGE IN THIS REPOSITORY. `agent_workflows/__init__.py` is 42 lines and imports only `versioning` and `._compat`; it re-exports no runner symbol. `runner_shared` declares no `__all__`. The documented compatibility surfaces are the CLI and the `aw.agent/v1` JSON contract (`docs/cli-agent-protocol.md`, `docs/cli-output-contract.md`), not module attributes. `li44r9` declined the deletion for a reason its own backlog entry states was scope, not risk: "removing a public module attribute is a compatibility change, and that plan's scope is a pure code MOVE with no behavior change authorized."
- CODE IS CITED BY SYMBOL, NOT BY BARE LINE OFFSET, per spec `ipd-structure-and-linting` Section 10.2 and advisory `IPD-C801`. This matters unusually much here: EVERY line number in backlog item `zf999x` is now stale, each having drifted by roughly fourteen thousand lines as `runner_shared` absorbed the `rununify` lifts, so an executor following the item's offsets lands in unrelated valid code. This plan therefore cites `runner_shared.FULL_AUTO_ACTOR` and `runner_shared.FULL_AUTO_APPROVAL_MESSAGE` by name throughout and never by position.
- THE SUITE RUNS BARE. `pyproject.toml` `addopts` already supplies `-q -n auto --dist=worksteal -m 'not slow'`; `python3 -m pytest` with no added flags is the contract, and a second `-q` would suppress the `N passed` line this plan's validation requires.
