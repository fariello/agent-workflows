# IPD: Make every spec reader recursive so a spec in a subdir cannot become invisible

- Date: 2026-09-08
- Kind: child
- Concern: A SPEC PLACED IN A SUBDIRECTORY OF `.aw/records/specs/` IS INVISIBLE TO ITS OWN CHECKER TODAY, AND `aw specs check` REPORTS SUCCESS HAVING READ NOTHING. PROVEN in a throwaway git repo, not inferred: with one real spec copied into `.aw/records/specs/approved/`, `aw specs check` printed `all specs conform`, while `specs._spec_files(repo)` returned ZERO files and `check_engine._iter_type_files(repo, "specs")` returned ONE. So the two surfaces already disagree about what a spec IS, and the disagreement resolves in the most dangerous direction: the type's own validator sees nothing and calls it clean.
  THE ROOT CAUSE IS ONE CHARACTER OF METHOD CHOICE. `specs._spec_files` (`specs.py:70`) collects with NON-recursive `glob("*.md")` (`:89`), while `check_engine._iter_type_files` uses `rglob("*.md")` (`check_engine.py:488`). Both walk the same roots and both resolve the same legacy `.agents/docs/specs` fallback; only the recursion differs.
  THIS IS A LATENT BUG INDEPENDENT OF ANY MIGRATION, which is why this child is worth executing even alone. Any subdirectory anyone creates under `.aw/records/specs/` for any reason (an `archive/`, a topical grouping, a stray directory from a partial move) silently removes every spec beneath it from `aw specs check`. Nothing warns, and the verb's output is indistinguishable from a genuinely clean tree.
  IT IS ALSO THE HARD PRECONDITION FOR THE MIGRATION CHILD. That child migrates 29 specs (re-measured at review; the authored 28 is stale) into status subdirectories. Performed before this fix, it would produce a tree in which `aw specs check` validates ZERO specs and reports conformance, which is a validated-looking tree that was validated against nothing. That is the single most dangerous outcome available in a records migration, and it is why the parent's CID-1 exists.
  THE FIX MUST NOT BE A ONE-LINE SWAP, because `_spec_files` is not the only reader and a partial fix is worse than none: it would make the surfaces agree in the case someone tested and disagree elsewhere. `_spec_files` has at least two consumers inside `specs.py` (`:430`, `:858`), and the module also resolves roots through `resolve_record_read_paths("specs", ...)` (`:74`), so the audit must establish every path by which a spec file is enumerated rather than fixing the one that was measured.
  REVIEW FOUND THE PRESCRIBED FIX IS INCOMPLETE IN A WAY THAT WOULD SHIP A NEW BUG, and it is the single most important correction to this plan. `rglob` ALONE IS NOT THE FIX. `_spec_files` has NO ignored-path filter at all (grep for `is_ignored_path`/`get_ignored_dirs` in `specs.py` returns NOTHING), while `check_engine._iter_type_files` filters BOTH the root dir and every file through `_core.is_ignored_path` (`check_engine.py:510-521`). Non-recursion is currently MASKING that gap: a flat glob cannot descend into an ignored SUBDIRECTORY, so today there is nothing to filter. Make it recursive without adding the filter and the reader starts returning GITIGNORED specs. PROVEN in a throwaway repo: with one tracked spec at the specs root and one spec inside a gitignored `.aw/records/specs/untracked/`, the naive `rglob` returned TWO files while `check_engine._iter_type_files(..., include_retired=True)` returned ONE, so the very set equality E-04 demands FAILS after the prescribed change. THIS IS NOT HYPOTHETICAL: the framework's OWN shipped `.aw/.gitignore` line 6 is `records/*/untracked/`, verified with `git check-ignore -v .aw/records/specs/untracked/x.spec.md`, and two sibling trees already HAVE such a lane (`records/prompts/untracked`, `records/comms/untracked`). So the hazard activates the moment anyone creates the lane specs does not yet have, and `aw specs check` would then validate, and could REFUSE on, a box-local file that is never committed.
  REVIEW ALSO FOUND E-04's SET-EQUALITY ASSERTION CANNOT PASS AS WRITTEN, for a reason unrelated to recursion. It names `check_engine._iter_type_files(..., "specs")` with DEFAULT arguments, but that default drops retired records (`is_retired`, `check_engine.py:482-500`) and 16 of 29 specs are terminal. MEASURED on the live FLAT tree at HEAD: `_spec_files` 29 versus `_iter_type_files` THIRTEEN by default, versus 29 with `include_retired=True`, where the sets are EQUAL. An executor asserting the equality as written would see a 16-file gap on a tree with no subdirectories and would naturally misdiagnose its own correct fix.
- Scope: Make every enumeration of spec files recursive AND ignored-path-aware, so a spec in any subdirectory is seen by `aw specs check` while a gitignored one is not, and prove the two currently-disagreeing surfaces agree. EXCLUDES moving any spec (the migration child owns that), and excludes changing what any check REPORTS about a spec.
