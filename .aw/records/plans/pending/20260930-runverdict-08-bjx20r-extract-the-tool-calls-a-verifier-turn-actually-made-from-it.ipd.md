# IPD: Extract the tool calls a verifier turn actually made from its own session log, and measure whether its claimed tests_run is corroborated

- Date: 2026-09-30
- Kind: child
- Concern: `runner_shared.has_verifier_test_evidence` gates a `verified` verdict on `tests_run` carrying command-like content, and its own module comment states the residual weakness in as many words: "Accepting prose strings and dict entries without session log cross-checking proves ACTIVITY ... not correctness or proof of non-fabrication." A verifier that writes a plausible command string having run nothing passes the gate, so the run's strongest machine-readable trust signal rests on an unchecked self-report. The evidence needed to check it IS ALREADY ON DISK and unread: `runner_shared.execute_item_core` records the verifier turn's full `opencode run --format json` (or Antigravity `stream-json`) event stream at `runner_shared.attempt_log_path(..., suffix="verify")` and stores the path on `attempt["verify_log"]`, and every OpenCode `tool_use` event for `bash` carries `part.state.input.command` while every Antigravity `step_update` of `step_type == "tool"` carries `tool_info.parameters.CommandLine`. Nothing in the package compares those observed commands against the claimed ones.
- Scope: Build the MEASUREMENT AND THE PREDICATE ONLY, as a pure, fail-open-by-construction reader: extract the shell commands a session log shows were actually invoked, compare them against the commands `extract_verifier_test_commands` reports were claimed, and return a three-state corroboration verdict (`corroborated` / `uncorroborated` / `indeterminate`) with the observed and claimed sets attached. Ships with a fixture corpus and a first measurement over whatever real corpus the executing box has. EXPLICITLY NOT INCLUDED: wiring the verdict into `execute_item_core`, storing it on the attempt record, rendering it anywhere, and any refusal or downgrade based on it. Those are Order 09 (`btak7a`), which declares this plan as its `Item-Dependencies`, so a predicate cannot reach a gate before its calibration exists. A REFUSAL IS OUT OF SCOPE FOR THE WHOLE SET, not just for this plan: see this plan's Deferred section and `btak7a`'s OQ.

## Goal

Make "did this verifier actually run the tests it says it ran" a computable, three-state, fail-open
question answered from the verifier turn's own session log, with the false-negative rate MEASURED
against a real corpus before anything consumes the answer. The deliverable is a pure module plus its
calibration evidence; nothing in the runner changes behavior in this plan.
