## Goal

Make the one shared retention predicate answer the question it is actually asked. Today
`submission_retention` answers "is there a completed collection receipt?", reports the answer as
"is a submission still uncollected?", and those two are different questions for the lane shape that
matters most: the interrupted one. An interrupted lane never has a completed receipt, so the gate
refuses it however clean it is, and `teardown_lane_if_classified` is therefore unusable on the whole
interrupt path.

Deliver the distinction spec R2.5 is missing - an absent receipt for a lane that PROVABLY wrote no
submission is a different observation from an absent receipt for a lane that WROTE one - and, in the
same change, add the blocking condition that narrowing exposes. Narrowing a refusal widens
destruction, and measurement shows the refusal being narrowed is currently the only thing that
prevents a lane holding UNMERGED committed work from being force-removed branch and all. The plan is
therefore net-neutral on safety by construction: one refusal becomes narrower and a strictly more
precise one takes over the case it was accidentally covering.
