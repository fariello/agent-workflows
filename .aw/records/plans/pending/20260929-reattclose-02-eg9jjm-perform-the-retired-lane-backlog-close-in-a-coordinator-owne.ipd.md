## Goal

Make the retired-lane backlog close land the way every other mid-run write on this path already lands: performed in a coordinator-owned throwaway worktree and published to main as a single fast-forward ref update, so a hook rejection or a peer's in-flight edit produces a REPORTED refusal instead of a half-moved item stranded in main's working tree. And stop the same call site DESTROYING a successful close record by re-evaluating an item that is already `done`.

WHAT THIS GOAL DELIBERATELY DOES NOT CLAIM. It does not change WHETHER any item closes: the eligibility decision stays exactly where `process_backlog_close` takes it, against main, and this plan changes only the TREE the resulting move and commit happen in. It does not remove every write to main from a run, because landing the change IS a write to main; what it removes is the window in which main holds a moved-but-uncommitted item. It does not modify the performer `pjuoyj` shipped, only its second caller. And it does not claim this site fires often: F-09 measured that the common retirement shape REFUSES before writing anything, so the severity comes from what happens when it does fire, never from frequency.

- A COORDINATOR-OWNED THROWAWAY WORKTREE IS THE ESTABLISHED WAY TO MUTATE-THEN-LAND. `commit_lock.coordinator_worktree` yields a worktree on its own short-lived branch and cleans both up unconditionally; `ipd_lifecycle._finalize_transaction` is the original caller and demonstrates the sequence (mutate in `coord.path`, commit there so real hooks run in a private tree, then `land_worktree_commit` as the single step that advances the branch).
- THE GUARD THIS SITE LACKS IS ALREADY WRITTEN TWICE, WITH ITS REASONING. Both `retry_deferred_integrations._finish` and `finish_reintegrated_item` wrap their close in `if not (item.get("backlog_close") or {}).get("closed"):` and both carry a comment explaining that re-evaluating an already-closed item answers `item is already done` and overwrites a success record with a refusal. Copying the comment as well as the predicate is the convention here.
- `process_backlog_close` IS INJECTED, NEVER IMPORTED. It lives in `oc_runipd` (agy re-exports it) and `runner_shared` may import neither host, so `integrate_retired_lane` receives it as a keyword parameter and `execute_item_core` binds it from the driver module with `getattr(driver_module, "process_backlog_close", process_backlog_close)`. A fix must thread the injected name.
- ONE SHARED PATH, TWO HOSTS, AND ONE TEST MODULE THAT ALREADY KNOWS IT. `tests/test_inlane_retirement_lands.py` drives this exact call site through `_HOSTS = (("oc", oc_runipd, "run_opencode"), ("agy", agy_runipd, "run_agy_turn"))`, so a test added there is a both-hosts test by construction.
- THE CLOSE IS FAIL-CLOSED THROUGHOUT, BY DESIGN. `process_backlog_close` records a verdict on the item whether or not it closes, catches its own evaluation failures, and treats a refused setter as the reason; `commit_backlog_close` returns None rather than raising. Any new arm must keep that property, and a close refusal must not turn a landed retirement into a failure.
