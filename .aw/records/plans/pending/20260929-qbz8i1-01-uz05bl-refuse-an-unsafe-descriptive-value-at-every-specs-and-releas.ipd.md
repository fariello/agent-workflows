## Goal

Make every specs and releases write path refuse a descriptive value that violates the Section 8.8 contract, so a creating or mutating verb cannot manufacture a record carrying metadata its author never wrote. The severe case is not cosmetic: a `--title` newline currently writes a `- Status: approved` bullet that wins the first-match race in `specs._read_status`, which is the exact attestation forgery `AGENTS.md` forbids an agent from hand-writing.

## Project conventions discovered (Step 0)

- THE PREDICATE IS ALREADY SHARED AND NEEDS NO CHANGE, so this plan adds CALL SITES only. `attention_contract.is_safe_descriptive` documents itself as "Section 8.8: a descriptive field is a single, bounded, control-char-free line" and `specs.py` already consults it at three sites. The defect is that the WRITE paths do not consult what the reader does.
- THE REFUSAL SHAPE IS ALREADY SETTLED IN THIS EXACT MODULE, AND IT IS EXIT 1, NOT 2. `specs.run_set` refuses with `aw specs set: --gate-summary must be a bounded single control-char-free line` and returns **1**, and every other usage refusal in `run_set` (`is not a spec status`, `illegal transition`, `deferred requires a valid --gate-kind`) also returns 1. `specs.run_new` by contrast returns **2** for `--title is required`, and `run_note` returns 2 for an unreadable path. So the module is internally inconsistent ALREADY and this plan preserves each function's own convention rather than unifying them (OQ-01).
- `releases.run_new` OWNS AN ENVELOPE-AWARE REFUSAL CLOSURE, `_usage(msg)`, which builds the `aw.agent/v1` `cannot-run` CommandResult under `--agent`/`--json` and falls back to `aw releases new: <msg>` on stderr, returning 2 either way. A new guard there MUST route through it; a bare stderr write would emit a non-envelope line in agent mode, which the surrounding code deliberately avoids.
- THE SIBLING TREE'S FIX IS ALREADY EXECUTED AND IS THE TEMPLATE. Plan `dtg7dz` (Set `a0s33b`, executed 2026-09-29) added `backlog._refuse_unsafe_descriptive` with the same `bound_length` parameter for the same measured reason, and its Deferred section names `aw specs new` and `aw releases new` with `Carrier: qbz8i1`, which is this plan's own backlog item. This plan is the discharge of that carrier.
- THE GOVERNING SPEC ALREADY FORBIDS THE OBVIOUS ALTERNATIVE. Spec `attention-registry-and-cross-tree-status` Section 8.8: "embedded newlines are rejected (a violation), not wrapped" and "Over-length values are a contract violation, not silently truncated". So sanitizing, wrapping or truncating at the write path is ruled out and refusal is the specified behavior. Its A14 acceptance criterion already requires hostile-string fixtures of exactly these shapes.
- A HISTORY MESSAGE IS NOT A BOUNDED FIELD IN THIS REPOSITORY, on any tree. Measured here: specs 59/146 (40.4%) over 300 at authoring and 60/148 (40.5%) re-derived at review, max 2594. `dtg7dz` F-13 measured backlog at 531/1483 and plans at 1549/3990. No checker anywhere bounds a history message, so guarding one on LENGTH would be a new policy this plan does not make.
- Cite code by SYMBOL (`module.function`) or by a quoted content string, with a line number only appended to one of those and never alone: an offset expires before this plan executes (spec `ipd-structure-and-linting` Section 10.2; advisory `IPD-C801`).
