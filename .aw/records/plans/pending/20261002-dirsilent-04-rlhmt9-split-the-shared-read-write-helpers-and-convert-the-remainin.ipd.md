## Open questions

### OQ-01: Should the split be a per-helper pair of entry points, or one helper taking a read/write parameter?

- Blocking: no
- Status: resolved
- Owner: executor
- Finding: F-01, F-02
- Resolution or deferral rationale: RESOLVED: TWO NAMED ENTRY POINTS per mixed helper, not one helper with a flag. A flag (`_repo_root(args, write=True)`) is fewer lines and is the obvious first instinct. It is worse here for a specific reason: the whole value of the split is that a READER at the call site can see which policy a verb is under, and a boolean argument defers that to whichever default was chosen - and a default is exactly how a new write verb would silently inherit a refusal, or a new read verb silently keep greenwashing. Two names make the class a property of the CALL rather than of an argument, so adding a caller forces the author to choose. It also makes E-05's negative control meaningful: a write verb calling the read entry point is a visible mistake rather than a missing keyword. The cost is one extra symbol per mixed helper, which is three symbols in total.
