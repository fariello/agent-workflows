## Goal

Make the run summary's HEADLINE agree with its own body for a stranded review. The recovery section already tells the operator their review never landed and names the branch; the outcome word above it still says `COMPLETED`, because the ladder asks only the EXECUTE-shaped question. This plan adds the REVIEW-shaped question that is already defined and already used one function away, so one screen stops stating two contradictory things.

This is the HUMAN-READABLE half of a defect whose MACHINE-READABLE half was owned by plan `entv1d` (Set `strandexit`), which makes the same shape count for the process exit code. THAT PLAN HAS NOW EXECUTED (corrected at review, PR-002; F-07 and OQ-02 describe it as approved-and-pending because that was true at authoring), and its landing SIMPLIFIES this plan rather than complicating it: the composed predicate `work_did_not_land` it added is precisely the question this ladder must ask, and its docstring names the headline as the second surface that must ask it. So the two halves now converge on one predicate instead of two independent edits, which is what E-03 calls for after PR-001.
