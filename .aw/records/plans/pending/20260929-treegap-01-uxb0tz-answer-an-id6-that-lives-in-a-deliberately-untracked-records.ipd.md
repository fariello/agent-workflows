## Goal

Stop `aw attention` telling an operator that an artifact they can see on disk does not exist. A selector that resolves into a tree the view deliberately excludes should say so, naming the tree and its recorded reason, and exit 0; only a token that resolves to nothing at all should keep the exit-2 refusal. SAYING SO IS THE DELIVERABLE, NOT THE EXIT CODE: exiting 0 in silence is a different and worse defect (F-12), so every surface must carry the explanation and every validation item demands the output text rather than the return value. Separately, settle the Phase 3 question the backlog item raises by recording the measured admission verdict for both trees in-tree, so the next author inherits a decision instead of re-deriving it.

- The zero-match exit contract is SPEC-GOVERNED, not a local convention. - `attention_contract`'s mapping purity rule is the reason this plan cannot simply show the artifact: `class_of(tree, native_status)` must be PURE and TOTAL over a tree's native enum and "NEVER infers activity or gate state from prose". An artifact with no status field has no enum to be total over. This is the identical rationale the `reviews` tree already carries in `TREE_POLICY`, measured over 231 files, and it applies unchanged here.
- `TreePolicy` already carries a `reason` string per tree, and both excluded trees have a populated one (`"narrative records; no lifecycle status in v1 (OQ8)"` and `"intent, not commitment; no lifecycle status in v1 (OQ8)"`). E-04 therefore has a real message to print and does not need to invent per-tree prose in `attention.py`.
- `_classify_tree` already normalizes the `.aw/records/<type>` layout onto the legacy `.agents/docs/<type>` policy keys via its `_DOCS_FAMILY` tuple, which lists `walkthroughs` and `roadmaps` explicitly. So policy lookup for both trees works today and E-02 adds no path mapping.
