## Goal

Stop `aw attention` telling an operator that an artifact they can see on disk does not exist. A selector that resolves into a tree the view deliberately excludes should say so, naming the tree and its recorded reason, and exit 0; only a token that resolves to nothing at all should keep the exit-2 refusal. Separately, settle the Phase 3 question the backlog item raises by recording the measured admission verdict for both trees in-tree, so the next author inherits a decision instead of re-deriving it.

## Project conventions discovered (Step 0)

- Cite code by SYMBOL (`module.function`) or by a quoted content string, with a line number only appended to one of those and never alone: an offset expires before this plan executes (spec `ipd-structure-and-linting` Section 10.2; advisory `IPD-C801`).
- The zero-match exit contract is SPEC-GOVERNED, not a local convention. Spec `25kzda` Section 2.4a: an empty result "is a success, not an error ... because `reviews` is a standing question about repository state rather than an assertion that a named item exists. A misspelled id6 still exits 2; only the status selectors are exempt." This plan adds a SECOND exemption class and must not weaken the id6 clause, which is exactly why E-06 pins the bogus-token case.
- `attention_contract`'s mapping purity rule is the reason this plan cannot simply show the artifact: `class_of(tree, native_status)` must be PURE and TOTAL over a tree's native enum and "NEVER infers activity or gate state from prose". An artifact with no status field has no enum to be total over. This is the identical rationale the `reviews` tree already carries in `TREE_POLICY`, measured over 231 files, and it applies unchanged here.
- `TreePolicy` already carries a `reason` string per tree, and both excluded trees have a populated one (`"narrative records; no lifecycle status in v1 (OQ8)"` and `"intent, not commitment; no lifecycle status in v1 (OQ8)"`). E-04 therefore has a real message to print and does not need to invent per-tree prose in `attention.py`.
- `_classify_tree` already normalizes the `.aw/records/<type>` layout onto the legacy `.agents/docs/<type>` policy keys via its `_DOCS_FAMILY` tuple, which lists `walkthroughs` and `roadmaps` explicitly. So policy lookup for both trees works today and E-02 adds no path mapping.
- `selector_match_facts` requires the UNFILTERED scan and already takes `drift` for the same class of reason this plan extends it: a token naming a real but unparseable artifact was being reported as a typo. This plan's case is the same defect class arriving by a fourth route (the artifact is real, parseable, and in an untracked tree), so it belongs in this function rather than in a new one.
- Both trees are already in `artifact_core.SCAN_ROOTS` and in `attention._TREE_TO_SCAN_ROOTS`. Neither absence is the blocker; the blocker is `TreePolicy.tracked=False`, which `attention.scan` honors with `if not pol.tracked: continue`.
