- A legacy 3-field `Drift` carries an EMPTY severity and `drift_exit_code` treats it as FAILING, which the docstring states explicitly so existing callers are unchanged. So delegating is conservative: an unenriched finding still refuses.
- `check_commit_invariants` deliberately "introduces NO new policy logic" so the hook and `aw check` "can never diverge", and it enriches every finding with registry metadata before returning. That is the reason the fix belongs at the exit-code boundary and not inside the aggregator.
- Cite code by SYMBOL (`module.function`) or by a quoted content string, with a line number only appended to one of those and never alone: an offset expires before this plan executes (spec `ipd-structure-and-linting` Section 10.2; advisory `IPD-C801`).
- The opt-in pre-commit hooks are installed by named `engine.create_*_hook` helpers that are idempotent, no-clobber and "never default-installed"; this repository wires only two of them, and the generalized scope gate is not among them.
- `AGENTS.md` records the same honest limit the hook's docstring does: the local hook is "local-only and skippable", and "the portable authority is the `aw check release-gates` rule family ... and CI, never the local hook alone". A fix to the hook is therefore an improvement to FEEDBACK QUALITY, not to an authority boundary, and must not be described as the latter.
