## Project conventions discovered (Step 0)

- TESTS ASSERT OUTCOMES, NEVER CODE STRUCTURE OR TEXT. `GUIDING_PRINCIPLES.md` P16 forbids `inspect.getsource`, `ast.parse`, `read_text()` or substring search against `agent_workflows/*.py`, forbids count and census pins "as a proxy for an invariant", and forbids docstring or banner pins outright ("Comments and docstrings are for humans and models reading the code, not test assertions"). It grants one narrow exception, where "the text or file itself is the artifact under test". THIS PLAN SITS ON BOTH SIDES OF THAT LINE AND THE DISTINCTION IS LOAD-BEARING: parsing the SPEC (a records artifact, the contract under test) is the sanctioned exception and is the shape the deleted tests used; reading `run_evidence.py`'s own comment would be the prohibited case, which is why E-03's prose is verified by `git diff` in validation and by no test at all.
- A COUNT PIN IS ITSELF A DEFECT UNLESS THE COUNT IS THE CONTRACT. P16's "no count or census pins" and the item's own suggestion pull in opposite directions, and the repository has already ruled where the line is: `validate_finding_table` hard-fails `len(RUN_FINDING_CODES) != 12` with `RC-COUNT`, and the spec says so explicitly ("THE TABLE'S CODE COUNT IS ITSELF PART OF THE CONTRACT"), so that twelve is a contract and stays. The abort partition is NOT in any contract: no spec sentence states it, so it is a derived statistic and must be derived.
- THE SPEC IS ALREADY READ AS A FILE BY TESTS, so an amendment to its table is detectable and the glob-one-match shape is established. `tests/test_runner_shared.py` globs `*-25kzda-*.spec.md` under the approved directory, asserts exactly one match, and asserts on its content.
- THE TRI-STATE IS DOCUMENTED AS AN INDEX, NOT A POLICY, which is what licenses deriving it. `RunFindingCode`'s own docstring: `abort` is a "derived tri-state over ``action``" and "this is an INDEX over the verbatim string, not a new policy". A derivation test is therefore checking the field's stated contract rather than inventing one.
- A ROW'S `action` IS TRANSCRIBED VERBATIM AND BYTE-EQUALITY IS THE ESTABLISHED ASSERTION. Spec 4.2's own note: "`run_evidence.RUN_FINDING_CODES` transcribes the `inspects` and `pass_criterion` cells VERBATIM, and `tests/test_run_evidence_completion.py` asserts byte equality, so editing a cell here is a code change." That test file is gone (F-02); the convention it names is not.
- Cite code by SYMBOL (`module.function`) or by a quoted content string, with a line number only appended to one of those and never alone: an offset expires before this plan executes (spec `ipd-structure-and-linting` Section 10.2; advisory `IPD-C801`).
