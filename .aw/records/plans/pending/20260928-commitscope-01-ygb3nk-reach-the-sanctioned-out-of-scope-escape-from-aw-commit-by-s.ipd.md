# IPD: Reach the sanctioned out-of-scope escape from aw commit by scoping its scope refusal to the staged set

- Date: 2026-09-28
- Kind: child
- Concern: Backlog `ldy1al` (and its near-duplicate `v45wb7`) report that `aw commit <plan>` becomes unusable for the REST of an execution once one out-of-scope path is legitimately committed, because the commit gate consumes `check.scope-drift`, which measures the whole execution diff since the begin receipt's frozen `base_head` rather than the staged set. VERIFIED END-TO-END at HEAD `1e522dc5`: a lane-isolated plan declaring two paths, having committed one undeclared path, is refused on a later commit naming ONLY a declared path, with the staged set literally `[]`. The sanctioned escape (`aw ipd finalize --scope-reason PATH=WHY`) is real and works, measured accepting that same path, but it is unreachable because the commit gate refuses first, pushing the agent onto `aw commit --no-plan`, which skips Scope-Paths enforcement AND plan validation for every later commit.
- Scope: Stop `aw commit`'s plan-validation gate treating `check.scope-drift` as BLOCKING, routing it to the existing non-blocking advisory channel instead, so the commit-time refusal is the one that already compares the STAGED set (`run_commit`'s own `_in_scope` branch, which measurement shows is already correctly staged-scoped) and the execution-wide reconciliation stays where it already lives, at finalize. This deliberately does NOT add a `--scope-reason` flag to `aw commit`, does NOT change `check_scope_drift`, does NOT change the rule's registered severity, and does NOT touch `aw check`, CI, or the opt-in pre-commit hook. OQ-01 records why the flag route was refused on measurement.

## Goal

Make the mandated commit verb usable for a whole execution again, including after a genuinely-required out-of-scope edit, without weakening any gate. After this plan `aw commit <plan>` still refuses an out-of-scope path that is STAGED or NAMED, which is the invariant the catalog actually states, while the execution-wide scope question is reported as an advisory at commit time and remains fail-closed at `aw ipd finalize`, where the `--scope-reason` grammar that answers it already lives. The user-visible effect is that an agent following the repository's own instruction to make and then justify a required out-of-scope edit is no longer pushed onto `aw commit --no-plan` for the remainder of its lane.
