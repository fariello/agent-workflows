## Goal

Make the lane landing question answer IDENTICALLY no matter which worktree of a checkout asks it, so `LaneState.reclaimable` cannot report `True` for work that reached nothing, and so a landing question that cannot be anchored is reported as UNANSWERABLE rather than as landed.

Concretely:

1. The symbolic integration target is resolved against the CHECKOUT (through its shared git common dir, whose `HEAD` is the main worktree's), not against the caller's worktree, so `HEAD` names the branch a merge would actually land on even when the caller is a lane.
2. When no checkout anchor can be established, the predicate returns `None` (unanswerable) rather than falling back to a cwd-relative resolution, because `None` already collapses to "not merged" in every consumer and so fails toward preservation.
3. The `--git-common-dir` resolution lives in ONE primitive that `checkout_control_root` and the landing predicate both call (REVISED AT REVIEW from "the collapse that finds the main worktree", PR-001), so this repository does not gain a FOURTH hand-rolled anchoring workaround beside `checkout_control_root`, `attention._resolve_runs_repo_root`, and the `tjags7` fix in flight.
