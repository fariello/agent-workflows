# IPD: Document the severity tier contract so warning is not mistaken for advisory, and pin the six consumers that enforce it

- Date: 2026-09-29
- Kind: child
- Concern: The check engine's severity vocabulary (`error` / `warning` / `info`) reads as a three-level scale of seriousness, but for the exit-code contract it is a TWO-level one: `artifact_core.drift_exit_code` is `1 if any(getattr(d, "severity", "") != "info" for d in drift) else 0`, so `info` is the ONLY tier that does not fail a gate. Measured at base by driving the function directly: `error` -> 1, `warning` -> 1, `warn` -> 1, `info` -> 0, `""` (empty) -> 1, `"advisory"` -> 1, `"INFO"` -> 1, `[]` -> 0. A rule author who wants "report it but do not fail the tree" reaches for the tier NAMED `warning` and gets a failing gate. This has been reasoned through wrongly repeatedly and caught only at review: backlog `1dvtiq` cites `76w6mq` E-05 (authored "register at warning so the repository does not fail its own check for documenting itself", which defeats its own stated goal; review corrected it to `info`), and authoring found two MORE independent instances the item does not mention, `k9awrq` (whose `check.ipd-lint-diagnostic` was authored "advisory" and spelled `warning`, corrected to `info` at review, recorded as DECISION 02-k9awrq-D1) and `cnzrxb` (whose E-01 expected "aw check plans exits 0" from a `warn` tier, review PR-001 measuring it unachievable). The contract is defended today ONLY by prose comments inside `check_engine.py`, which is where authors already are when they get it wrong: 9 such comments in that one file, and 32 `drift_exit_code` references across the package. NOTHING in `docs/` states the contract at all, and NO test asserts that the tier vocabulary means what the comments say.
- Scope: IN: (a) publish the contract ONCE in `docs/cli-output-contract.md` beside the exit-code semantics it governs, naming `info` as the only non-failing tier, the fail-closed treatment of an empty or unrecognized severity, and the SECOND contract (`aw commit` / `aw work begin` / `aw ipd lint`, where `warning` is genuinely non-blocking) so a reader learns both rather than half; (b) a new behavior test module pinning the `drift_exit_code` severity mapping including the fail-closed cases, the registry's conformance to the three-value enum, and the existence of at least one `info` rule, so the contract is enforced by execution rather than by comment; (c) one CHANGELOG line. OUT, and this is the load-bearing exclusion: CHANGING what any tier MEANS, i.e. backlog `1dvtiq`'s options (b) "add a fourth advisory tier" and (c) "make warning non-failing and promote today's warning rules to error". Those re-tier 12 live `warning` rules and change CI behavior tree-wide, and the item itself files them for a MAINTAINER DECISION; OQ-01 puts the question to the maintainer rather than this plan answering it. Also OUT: any edit to `artifact_core.drift_exit_code` or to any `RuleSpec` severity (no behavior changes at all; this plan is documentation plus tests); the `aw check` errors/warnings TALLY, which is a separate measured defect owned by pending plan `tzjtg4` (set `checkinfotally`) and backlog `xqm16x`; the volume of the rendered findings report (backlog `ct1n04`); and deleting or consolidating the 9 existing `check_engine.py` comments, since a reader at the registry still benefits from a local statement (E-02 adds a pointer instead).

## Project conventions discovered (Step 0)

- Cite code by SYMBOL or by a quoted content string; the line offsets in the Findings table are at authoring and are approximate by execution time (spec `ipd-structure-and-linting` Section 10.2; advisory `IPD-C801`).
- Severity has ONE authority, `check_engine.RULE_REGISTRY` read through `check_engine.rule_spec` and stamped onto a `Drift` by `check_engine.enrich_drift`. An unregistered rule id falls back to `_DEFAULT_RULESPEC`, measured `RuleSpec(severity='error', assurance='repository', determinism='deterministic', invariant='')`, so the failure direction for an unclassified rule is deliberately strict.
- There are TWO contracts, not one, and conflating them is the mistake this plan must not repeat. The EXIT-CODE contract (`artifact_core.drift_exit_code`) exempts only `info`. The LIFECYCLE-GATE contract (`work_cmd._validate_plan_via_engine`, and `ipd_lint`'s carrier merge) treats `warning` as a printed non-blocking advisory. `work_cmd._validate_plan_via_engine`'s docstring states the distinction verbatim under the heading "NOTE ON STAGED SEVERITY AND THE TWO-CONTRACTS DISTINCTION (IPD s7cu7n)".
- `warning` is also used as a STAGING tier en route to `error`: executed plan `lkexaw` records that `check.ipd-priority-required` and `check.ipd-work-kind-required` end at `error` once the pending corpus is free of sentinels. So `warning` is not a permanent exemption anywhere, which is a further reason not to redefine it casually.
- User-facing prose (which `docs/` and `CHANGELOG.md` are) must contain no em or en dashes; internal artifacts such as this plan are exempt (AGENTS.md).
- Tests must exercise behavior and assert on real outputs; a test that reads production source text or counts symbols is forbidden (AGENTS.md "TEST OUTCOMES, NOT CODE STRUCTURE"; GUIDING_PRINCIPLES P16). This is why E-04 calls the functions rather than grepping them.
- Run the suite BARE as `python3 -m pytest`; do not add `-n0`, a second `-q`, or `-p no:randomly` (AGENTS.md "HOW TO RUN THE SUITE").
- Commit through `aw commit wm40yl -- <paths>`; never `git add -A`, never `-a`, never push.
