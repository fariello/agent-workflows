## Project conventions discovered (Step 0)

- Cite code by SYMBOL (`module.function`) or by a quoted content string, with a line number only appended to one of those and never alone: an offset expires before this plan executes (spec `ipd-structure-and-linting` Section 10.2; advisory `IPD-C801`). The backlog item's own citations (`runner_shared.py:3586`, `oc_runipd.py:2727`, `agy_runipd.py:1639`) are all stale by thousands of lines at `cd0fdc03`, which is why every finding below is anchored by symbol and re-measured.
- GUIDING_PRINCIPLES P16 forbids proving this by inspecting source: no `inspect.getsource`, no `ast.parse` over `agent_workflows/*.py`, no docstring or caller-count pins in a test. The AST measurements in the Findings are AUTHORING evidence, valid in a plan and in a review; the shipped test must exercise the ladder and assert on observable outcomes. This is why E-01 asserts an injected stub's invocation count and the item's post-call state rather than asserting the parameter is gone.
- The house pattern for a both-hosts property is a shared helper parameterized on the host module (`tests/test_forkresid_shared_shells.py::DeferredRetryUnmeasuredTests._run_retry_test(host, host_label)`, called once per host), not two copied classes. `tests/test_concurrent_driver_guard.py` records the reason in a module-level comment on its `BOTH` table: "a per-host test class would let a property hold on one host and not the other while both classes stayed green."
- Both hosts' `retry_deferred_integrations` are one-statement delegations to the shared body and resolve `integrate_lane_branch`, `make_integration_validation_runner`, `run_suite_check` and `process_backlog_close` from the HOST module at call time, which is what keeps `mock.patch.object(<host>, ...)` working as a test seam (`184tn9` E-04 states this explicitly). E-01's stubs must therefore be patched on the host module, not on `runner_shared`.
- `make_integration_validation_runner` FAILS CLOSED and records WHY on the item: no injected `suite_check`, an unresolvable base/head, or an unmaterializable merge result each return False with `measured=False`, and `revalidation_was_unmeasured` is the single reader of that flag, consumed by `record_integration_refusal` to reclassify a `fail-merge` into `merge-unchecked`. A test whose fixture cannot resolve endpoints therefore passes vacuously through the fail-closed arm without ever running a suite, which is the trap E-01's fixture requirements exist to avoid.
- `resolve_lane_endpoints` reads the LATEST ATTEMPT first (`worktree_base`/`worktree_branch`) and treats `preserved_base`/`preserved_branch` as the FALLBACK. Its docstring records the measured incident behind that ordering: three items were refused `merge-conflict` with `base=False, head=False` and the suite invoked ZERO times, because the gate was reading item keys that do not exist yet. BUT `head` IS NOT AN ATTEMPT FIELD AT ALL: it resolves from `item["lane_head"]`/`item["preserved_head"]` only, and the factory recovers an empty `head` with `git rev-parse <branch>`. So an attempt-only fixture is resolvable only when `state["repo"]` and the branch are real (F-10).
- AN INJECTED `run_suite_check` STUB MUST CARRY ATTRIBUTES, NOT RETURN A TUPLE. The factory reads `result.passing`, `result.reason`, `result.failures` and `result.exit_code` by `getattr` with defaults, so a tuple is read as failing, and `exit_code=5` is read as "collected nothing" and short-circuits to a pass (F-11).
- The ladder has TWO adapters and only one takes a runner: `_integrate` passes `make_validation_runner(...)` while `_integrate_review` calls `integrate_review_lane_branch(repo, handle, id6)` with no runner at all (F-12).
- Spec `25kzda` Section 2.1 governs the re-attempt: "Every re-attempt MUST route through the same merge-and-revalidate gate as the first attempt: a clean `merge-tree` proves the absence of a textual conflict and never that the combined result still passes." That is a requirement ABOUT the gate, not about any particular injection, which is why deleting the parameter needs no spec amendment while removing the revalidation would.
