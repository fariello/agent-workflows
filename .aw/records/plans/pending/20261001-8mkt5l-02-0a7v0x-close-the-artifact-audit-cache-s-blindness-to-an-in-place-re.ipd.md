## Goal

Make an id6 lookup's answer agree with what the files on disk actually declare, in the one case the signature structurally cannot see: an in-place rewrite of a record's `- Id:` line. Concretely, close three wrong answers that are reachable today with no filename change and no race: a stale positive, a wrong path, and a phantom collision.

Do it WITHOUT widening `_dir_signature`, and the reason is measured rather than preferred: the per-file signature the backlog item names as the remedy is falsified in F-03 (it fails on a size-preserving rewrite in 149 of 200 trials and costs 4.10x), while verifying the identity claim at the point of use costs 479us per lookup, which is 1.3% of a lookup and 0.006% of the rebuild it avoids (F-07).

State plainly what this plan does NOT close, because a reader of the item will expect it: the MISS-ON-NEW half, where the record's NEW id6 is unfindable until the index is rebuilt, stays open. No verification performed at the point of a hit can close it, since there is no hit to verify (F-05).

## Project conventions discovered (Step 0)

- TESTS ASSERT OUTCOMES, NEVER CODE STRUCTURE. `GUIDING_PRINCIPLES.md` P16 and `AGENTS.md` both forbid `inspect`, `ast`, regex or substring search against production source, and forbid caller counts and symbol censuses as a proxy for correctness. E-06 is written to that rule: it drives `find_artifact` and compares its answer against a freshly built index's answer. The one count it does keep is a traversal count, which measures WORK PERFORMED (did the index rebuild) rather than code shape, and is the only available behavioral proxy for the memoization invariant the predecessor plan `dea7dr` established in `tests/test_artifact_audit_index_cache.py`.
- COMPARE AGAINST THE FRESH ANSWER, NOT A SNAPSHOT. The invariant this plan defends is "a cached answer equals what the files say", so every assertion is `cached == truth` where truth is obtained by clearing the cache. That survives a later legitimate change to what `find_artifact` returns, which a hardcoded expected path would not.
- CITE CODE BY SYMBOL OR BY A QUOTED CONTENT STRING, with a line number only appended to one of those and never alone: an offset expires before this plan executes (spec `ipd-structure-and-linting` Section 10.2; advisory `IPD-C801`). Every citation here names `artifact_audit.find_artifact`, `artifact_audit._dir_signature`, `artifact_audit.build_index`, `selectors._read_header`, `run_viewer.find_artifact_file`, or quotes the comment text being changed.
- THE CACHE IS MODULE-LEVEL SHARED STATE AND THE SUITE RUNS IN RANDOM ORDER. `AGENTS.md` forbids `-p no:randomly` precisely to keep order-dependence visible, so a test that reads `_INDEX_CACHE` without clearing it first is order-dependent by construction. The predecessor file `tests/test_artifact_audit_index_cache.py` clears it in both `setUp` and `tearDown`; E-06 follows that.
- AN id6 IS A FIXED-WIDTH TOKEN, which is why a size component cannot detect an id6 rewrite. `check_engine._ID_LINE_RE` is `(?m)^- Id:\s*([0-9a-z]{6})\s*$` and `artifact_rename._ID_LINE_RE` plus `ipd_authoring._ID_LINE_RE` are byte-identical twins of it, all pinning exactly six characters. This is the mechanical reason F-03 falsifies the item's named remedy, and it is a property of the format rather than of any one measurement.
- THE SUITE IS NOT GREEN AT THIS HEAD AND ITS FAILURE SET IS NOT STABLE, which changes how this plan's no-regression evidence must be read. See F-09; compare by NODE ID against a baseline re-derived in the execution lane, never by total.
