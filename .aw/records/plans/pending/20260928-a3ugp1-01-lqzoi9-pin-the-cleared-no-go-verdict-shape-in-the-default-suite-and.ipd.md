## Project conventions discovered (Step 0)

- A LIVE-CORPUS TEST IS A LANE-WIDE HAZARD, AND THE REPOSITORY HAS ALREADY RULED ON IT. `pyproject.toml` defines the `livecorpus` marker for tests asserting a property "over EVERY artifact in this repository's own `.aw/records/` tree, so ANY agent writing a plan can turn it red", deselects it in `addopts`, and gives one measured reason: "a runner lane merges its work only if the full test suite passes, so a red test here blocks integration for every concurrent lane, not just the one whose plan is at fault". It then cites this plan's own incident as the measurement. So E-01 applies an existing rule rather than inventing a policy.
- THE MARKER DEFINITION ALSO FORBIDS DELETING SUCH A TEST: they "are VALUABLE and are not deleted (that one caught a real parser bug a made-up-data test could not), so they still run in `make test-all`, in release-review, and wherever a failure informs a human instead of halting a queue". This is why E-01 marks rather than removes, and why E-02 adds in-memory coverage alongside rather than as a replacement.
- THE TWO GATES ACCEPT OPPOSITE RISKS ON PURPOSE, and an executor must not "unify" them. `history_verdict_approves` uses the PLAIN scan and disqualifies on ANY mention of a negative readiness token; `newest_verdict` is the approval-gate path. The call-site comment records the reason: "this rule's false negative costs ONE deferral to a human, while the approval gate's false positive is an UNOVERRIDABLE LOCKOUT, so the two accept opposite risks on purpose. Relaxing this line is a policy change about which risk we accept, not a bug fix." The fix commit `a03b4c5b`'s own message records that its author applied the predicate to BOTH and a test caught it.
- CODE IS CITED BY SYMBOL, NOT BY BARE LINE OFFSET (spec `ipd-structure-and-linting` Section 10.2, advisory `IPD-C801`). This plan cites `plan_readiness.newest_verdict`, `negative_readiness_asserted`, `is_review_history_entry`, `_CLEARED_NEGATIVE_READINESS_RE` and `_NEGATIVE_READINESS_SCAN_RE` by name throughout.
- THE SUITE RUNS BARE. `addopts` already supplies `-q -n auto --dist=worksteal -m 'not slow and not livecorpus'`. A second `-q` suppresses the `N passed` line this plan's validation requires, and `-n0` makes the run several times slower. Use `-o addopts=""` when per-test counts are genuinely needed, which for this plan includes every `-m livecorpus` command, since the default `addopts` would otherwise deselect the very test being run.
- A DELETED TEST LEAVES LIVE COMMENTS POINTING AT IT, and this module has been bitten before. `xpta5g` E-02 had to correct four stale citations to `tests/test_plan_readiness.py` and `tests/test_plan_readiness_recheck.py` after `19313eed` deleted both, its finding F-5 noting that "a comment pointing at a nonexistent guard is worse than no comment". E-04 applies the same standard to a citation this plan itself makes stale.
