## Goal

Make the plan setter fail closed on an illegal lifecycle transition, by consulting the predicate that already encodes the answer. Today `ipd_lifecycle.validate_transition` is correct, shipped, and consulted by nothing that can PREVENT a bad write: its only production caller is an advisory `aw check` rule that runs after the fact, over pending plans only. This plan closes the gap the way the repository already closed it for specs - one delegation inside `status_set.validate_transition_allowed` - while preserving every legal edge that delegation would otherwise break.

- Cite code by SYMBOL (`module.function`) or by a quoted content string, with a line number only appended to one of those and never alone: an offset expires before this plan executes (spec `ipd-structure-and-linting` Section 10.2; advisory `IPD-C801`). - THE SPECS BRANCH IS THE PRECEDENT TO FOLLOW, and it is sited in the function this plan edits. `status_set.validate_transition_allowed` already contains a `rec.record_type == "specs"` branch delegating to `attention_contract.transition_allowed` and refusing with `Illegal spec transition {old} -> {new}`. The plan-side hole is symmetrical, so the fix is shaped like an existing, reviewed, shipped gate rather than invented.
- ONE FUNCTION SERVES BOTH REAL SPELLINGS. `aw set` and `aw ipd set` both dispatch into `status_set.run_set_command`, whose pre-flight loop calls `validate_transition_allowed` per record before any write. Measured: `aw plan set` and `aw plans set` are NOT registered commands (argparse rejects them with `invalid choice`), so an apparent "refusal" from those spellings is a usage error and must not be mistaken for the gate working.
- A NEW REFUSAL GETS ITS OWN NAMED FLAG, NEVER `--force`. Stated in `status_set.py` beside the terminal-reopen guard and echoed in the `--allow-terminal-reopen` help text: `--force` already means "act on all of an ambiguous multi-match" in this same function, and overloading it would make one flag answer two unrelated risk questions. This plan adds NO flag, for the reason in E-04.
- THE OVERRIDE MUST BE RECORDED IN THE ARTIFACT, not only in a shell history. `apply_status_change` folds `--allow-terminal-reopen` into the actor string it writes, so the override is auditable in the file. Any change to how that flag is honored must preserve this.
- The repository's exit vocabulary is a THREE-STATE contract (`0` clean, `1` domain findings, `2` usage/cannot-run) per `docs/cli-output-contract.md` Section 3. The existing terminal-reopen refusal uses `2` (`cannot-run`) while the pre-flight validation loop uses `1` (`findings`); this plan does not reclassify either, which is why E-05 expects zero test edits.
- A `- Readiness:` field is an OUTPUT of `/plan-review` and is deliberately ABSENT here; writing one while authoring would forge a review that has not happened, and the auto-approve predicate reads that field first.
