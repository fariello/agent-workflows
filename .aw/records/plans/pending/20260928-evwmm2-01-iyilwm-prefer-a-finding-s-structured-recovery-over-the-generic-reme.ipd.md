THE CORE CLAIM IS VERIFIED AT HEAD `4873a82a` and is far wider than the one rule it was found on: driving all 51 registered rules through `build_remediation` puts 44 of them on the generic fallback, including every rule that populates a real `recovery`. ## Goal

Stop `aw check` and `aw doctor` throwing away the one string that tells a user how to fix a finding. A rule author who follows the documented shape and populates `recovery` should see that text reach the human, instead of watching it be replaced by a sentence that tells the reader to inspect frontmatter for findings that are frequently not about frontmatter at all.

## Project conventions discovered (Step 0)

- CODE IS CITED BY SYMBOL, NOT BY BARE LINE OFFSET (spec `ipd-structure-and-linting` Section 10.2; advisory `IPD-C801`). This matters concretely here: the backlog item locates the fallback by a bare seven-line offset range in `doctor.py` beginning at line one thousand one hundred and fifty-one (spelled in words so this plan does not itself plant an expiring anchor), and that range now lands inside the `doctor.setup-needed` branch of `doctor.build_remediation`, an unrelated valid piece of code (F-03). An executor following the item's offset would edit the wrong branch. This plan therefore cites the fallback by its surrounding content throughout.
- THE SUITE RUNS BARE. `pyproject.toml` `addopts` already supplies `-q -n auto --dist=worksteal -m 'not slow'`. Every measurement here was taken with a bare `python3 -m pytest`; the baseline at HEAD `4873a82a` is `3087 passed, 2 skipped` (F-07).
- `recovery` IS THE DOCUMENTED FIELD FOR A FIX COMMAND, which is what makes discarding it a defect rather than a design choice. `artifact_core.Drift`'s own docstring describes the trailing fields as the versioned policy-schema metadata and names `recovery` as "the exact recovery command, when one exists"; `check_engine.finding_dict`'s docstring repeats it as "the exact recovery command". So the field's contract is explicit and `doctor.py` is simply not reading it.
- THE REPOSITORY ALREADY TEACHES THIS RULE AND IS ALREADY DISAPPOINTED BY IT. `check_engine.check_live_bug_gate` carries a comment saying it uses a structured `recovery` "matching the family's shape rather than embedding the fix in the detail text: `recovery` is the field the human renderer prints as the Fix line and the machine record carries verbatim", and then records the outcome in parentheses: "(driven: the generic 'inspect ... frontmatter' fallback was printed instead)". That comment is a correct statement of the intended contract and a record of it being violated, written by the author who filed `evwmm2`.
- A SHARED CHECKOUT MEANS NO SPECULATIVE FILE MUTATION. Every measurement in this plan that required altering behavior was taken IN MEMORY (wrapping `doctor.build_remediation` or `pathlib.Path.rglob` in a scratch script outside the tree), with `git status --short` empty throughout. The same method is mandated for the mutation proofs below.
