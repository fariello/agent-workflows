## Project conventions discovered (Step 0)

- The outcome is computed from per-item STATUS ONLY (`render_stream.py:1857-1880`); nothing in it asks about integration. `substantially-complete` sits inside the success tuple, which is why a stranded run reads as complete.
- THE BLOCK HAS SEVEN BRANCHES, NOT FIVE, and one of them already handles part of this problem: a `FAILED` branch fires on `("failed-safely", "integration-blocked", "merge-conflict")` (`:1861-1866`). So the gap is narrower than the concern states: it is the item that kept a SUCCESS-TUPLE status while its `integration_signal` recorded a refusal. An `exit_reason` passthrough (`:1858-1859`) also SHORT-CIRCUITS the whole block. Both must be preserved.
- The color selection is keyed on the outcome STRING with substring tests (`:1892-1902`), and its ELSE-BRANCH IS CYAN, not an obviously-wrong color, so an unhandled word looks deliberate while being wrong. Note `"FAIL" in outcome_str` means a word containing `FAIL` is red with no edit at all; do not rely on that coincidence.
- `render_stream.py` IMPORTS ZERO IN-PACKAGE MODULES (measured by AST), and both runners plus `runner_shared` import FROM it. It is a leaf. So it cannot import `oc_runipd`'s `INTEGRATION_REFUSED_*` constants, and any design that requires it to is unbuildable as written.
- **THE RECORDED FACTS CONTAIN ABSOLUTE HOME PATHS.** `preserved_worktree` is an absolute path under the maintainer's home, and `integration_detail`'s text embeds the repository's absolute path too (measured on `run-20260908T140845Z-2489897`). The summary is the most-copied output in the product, and D92 forbids machine-identifying strings in a public artifact, so anything printed here must be a git ref or a repository-relative string, proven with `aw sanitize --agent`.
- `integration_detail` IS ON THE ATTEMPT, NOT THE ITEM. Both drivers write `attempt["integration_detail"]` (`oc_runipd.py:6676`, `agy_runipd.py:3739`); the item carries `integration_signal`, `preserved_branch`, `preserved_worktree`, `preserved_lane_id`, `preserved_base`, `preserved_disposition` but NO detail key.
- `.aw/records/runs/` IS GITIGNORED, so any test asserting against a live run record fails for everyone else and in every clean worktree. Commit a redacted fixture instead; `tests/test_run_viewer.py` is the standing example of what happens otherwise.
- The file already appends SECTIONS rather than table columns for new facts (the `Diagnostics / Blocked Items` block), and this repository has recorded that choice twice so the table's column contract stays stable.
- The needed facts are already persisted by BOTH drivers: `integration_signal`, `integration_detail`, `preserved_branch`, `preserved_worktree`, `preserved_lane_id`. `grep` finds no reporting consumer of `integration_signal`.
- A run summary must be derivable from the run's own immutable state. `xtklpd`'s review measured the alternative failing: a filesystem audit of a recovered run reports it clean, so the summary would rewrite history.
- `substantially-complete` is a DELIBERATE and correct status. It records that the agent's work and validation finished while the lifecycle transition did not, and `reconcile_disposition` downgrades a claimed `executed` to it as an anti-fabrication guard. Do NOT remove it from the success tuple; add the landing question alongside it (removing it is the larger-blast-radius option the maintainer did not choose).
