## Goal

Make the spec tell the truth about a flag whose meaning depends on which host you type it at, and make that truth executable. After this plan an operator reading `25kzda` can learn that `--no-verify` differs per host and why, a future de-duplication has a spec sentence to check itself against, and the two ways this surface can silently drift (a spelling stolen onto the wrong dest, a spelling appearing on a host that never had it) both fail a test instead of passing a green suite.

WHY THIS IS MORE THAN HOUSEKEEPING, measured at review and stated because it raises the stakes rather than lowering them: the `build_parser` de-duplication this contract constrains is not a hypothetical future change but a refactor the maintainer DIRECTED on 2026-09-16 and which was never performed, while the tests that pinned the contract it must preserve were deleted a week later (F-03). So the guard this plan restores is one a directed, currently-unperformed refactor will need, and its absence is why that refactor could today steal agy's shipped `--no-verify` and pass a green suite.

## Project conventions discovered (Step 0)

- A PLAN MAY AMEND A SPEC AND MUST DECLARE IT. AGENTS.md states a plan that changes behavior a spec describes SHOULD carry the amendment in the same change, and that every `.spec.md` file it will touch MUST be listed in `- Scope-Paths:` so both runners announce the declared spec edit before the run starts and the finalize scope gate reconciles it. This plan declares the spec file for exactly that reason. This is also why no separate approval round trip is needed: the spec-edit route is sanctioned, and `25kzda` is amended in place by repeated precedent (its own history records amendments dated 2026-09-05, 2026-09-08, 2026-09-20, 2026-09-22, 2026-09-23 and 2026-09-27, several carrying new lettered subsections exactly as E-03 does).
- THE GRAMMAR STANZA IS MACHINE-READ AND ADDING A FLAG TO IT IS A CODE CHANGE. This is the convention that decides this plan's shape. A flag named inside 2.1's `aw <host> run <selector>` stanza is a declaration that the flag is a member of the closed `runner_shared.RUN_POLICY_FLAGS` table; the repository's own history records the consequence three times (`51vw4y` OQ-04, `vddpml` F-9, `1g4i1t` E-03: "AMENDING SPEC 25kzda SECTION 2.1 IS PART OF THIS ITEM ... WITHOUT IT THE SUITE GOES RED"), and the spec's Section 2.1 history records an amendment being deliberately withheld for it. The six verification spellings are NOT policy-table members and must not be declared as though they were (F-09).
- A DATED PARAGRAPH IN THIS SPEC IS A SNAPSHOT AND MUST SAY SO. The spec's own preamble makes this normative for the whole document ("EVERY DATED PARAGRAPH BELOW IS A POINT-IN-TIME SNAPSHOT, NOT A STANDING CLAIM, AND YOU MUST RE-MEASURE BEFORE RELYING ON ANY OF IT") and records that all three of its existing snapshots have been measured stale at least once. E-03's measurement note follows that convention rather than asserting a timeless fact.

This bites here: the backlog item cites `agy_runipd.assert_verification_flags_are_distinct` by a bare offset in the two-thousand-and-thirties (spelled in words so this plan does not itself plant an expiring anchor), and the symbol is at a different offset at this HEAD, having drifted by roughly eighty lines.
