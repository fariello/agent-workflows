# IPD: Make the driver-identity contract enforced by a test and a required parameter instead of a docstring

- Date: 2026-09-28
- Kind: child
- Concern: A run's host attribution is frozen once, by `runner_shared.initialize_run_core`, from the `driver_path` each host passes as `Path(__file__)`. That parameter is OPTIONAL (`driver_path: Path | None = None`) and `__file__` is evaluated in the DEFINING module, so a refactor that relocates either host's call into shared code, or simply omits the argument, writes a wrong or null `driver.path`/`driver.sha256` into every later run's durable `state.json` with NO test objecting. Re-measured at HEAD `7f7efe87`: the producer-side test that plan `orziju` added for exactly this (`EachHostRecordsItsOwnDriverIdentity`) WAS DELETED on 2026-09-24 by commit `19313eed`, so the coverage the backlog item recorded as "now exists" no longer does, and both sabotage modes now pass the FULL suite at `2935 passed, 2 skipped`.
- Scope: Restore producer-side enforcement and generalize it, without changing any shipped value. Make `driver_path` a REQUIRED keyword parameter of `initialize_run_core` (verified to break nothing: all three call sites already pass it explicitly). Add one test that, for every `HostLabels` instance defined in `runner_shared`, asserts the run that host CREATES records that host's own module basename and that same module's digest, and that both consumers (`run_analytics_sources.driver_generation`/`generation_host` and `run_viewer.load_run_summary`) return the host's labels rather than `unknown`. Add a registry-closure test so a THIRD host cannot be added without its generation being routable. Write the invariant into spec `25kzda` Section 5.3, which enumerates the durable state contract and today says nothing about it.

## Goal

Make the sentence "the driver record names the module that CREATED the run" a thing the repository ENFORCES rather than a thing two docstrings assert. Concretely: a future author who relocates `initialize_run_core`'s caller into shared code, or who drops the `driver_path` argument, must get a red test and a `TypeError` respectively, instead of a silently wrong `driver.path` and `driver.sha256` in every run created afterwards. No shipped value changes: both hosts keep recording exactly what they record today.

## Project conventions discovered (Step 0)

- CODE IS CITED BY SYMBOL, NOT BY BARE LINE OFFSET, per spec `ipd-structure-and-linting` Section 10.2 and advisory `IPD-C801`. This matters acutely here: EVERY line number in backlog item `9zyanj` is stale. The item cites `oc_runipd.py:3745` and `agy_runipd.py:2455` for `initialize_run`, which now live at `oc_runipd.initialize_run` and `agy_runipd.initialize_run` (roughly 1896 and 2043), and the statement it quotes no longer exists in either file at all: the freeze moved into `runner_shared.initialize_run_core`. An executor following the item's offsets lands in unrelated valid code. This plan cites by symbol throughout.
- THE SUITE RUNS BARE. `pyproject.toml` `addopts` supplies `-q -n auto --dist=worksteal -m 'not slow'`; `python3 -m pytest` with no added flags is the contract. A second `-q` suppresses the `N passed` line this plan's validation requires, and `-n0` makes the run several times slower. Use `-o addopts=""` only when per-test counts from a narrowed run are genuinely needed.
- `HostLabels` IS THE SANCTIONED SEAM FOR A HOST-VARYING VALUE, AND IT HAS NO DEFAULTS BY DESIGN. Its docstring states the reason in terms this plan reuses: a value "reaches a plan's PERMANENT finalize record", so "a defaulted or empty value would misattribute in durable history", and a `NamedTuple` "raises `TypeError` on a missing field at construction ... so a field can never silently read as empty". `driver_path`'s optional default is the same hazard one layer out, in a plain keyword parameter instead of a descriptor field, which is why E-01's fix is to remove the default rather than to add a field.
- `runner_shared`'S OWN MODULE DOCSTRING ALREADY NAMES THIS HAZARD CLASS GENERICALLY: lifting a symbol from one runner into shared code "would silently give BOTH drivers that runner's behavior". `driver_path` is the instance of that warning which a test does not yet cover.
- A DESCRIPTOR-ONLY HOST LEGITIMATELY PASSES `None`. `tests/test_hostdedup_third_host.py`'s `SCRIPTED_HOST_LABELS` case calls `initialize_run_core(..., driver_path=None, ...)` and asserts `state["driver"]["path"]` and `["sha256"]` are both `None`, then asserts `driver_generation(state) == "scripted"` and the viewer label is `"scripted"`. So `None` is a SUPPORTED value and the `driver.id` field is what carries attribution for such a host. Any fix must remove the DEFAULT without forbidding the VALUE.
- THIS REPOSITORY DELETES CHANGE-DETECTOR TESTS ON PURPOSE, which constrains what the replacement may assert. Commit `d4dd6b88` ("retire change-detector tests over code text and prose") and `19313eed` ("trim test suite from 9,136 to under 2,000 tests") removed suites that froze source line counts, `SequenceMatcher` ratios and AST census tables. The test E-02 adds must therefore assert BEHAVIOR (what a real `initialize_run` writes, and what the consumers make of it) and must not pin source text, line counts, or module structure, or it will be correctly deleted again.
