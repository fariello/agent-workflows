## Project conventions discovered (Step 0)

- THERE IS NO STATIC TYPE CHECKER IN THIS REPOSITORY'S TOOLCHAIN, which decides how this plan must be validated and, after review, is the whole reason it still has work to do. `pyproject.toml` declares one runtime dependency (`filelock>=3`) and test extras of `pytest`, `pytest-xdist`, `pytest-randomly` and `PyYAML`; `.pre-commit-config.yaml` runs `ruff` and `ruff-format` and no type checker; `.github/workflows/tests.yml` has no type-check step. RE-VERIFIED AT REVIEW: searching both config files for `mypy`, `pyright` and `type-check` returns nothing. THE CONSEQUENCE IS SHARPER THAN AUTHORED. A type error here is not merely unguarded against rot; it is INVISIBLE to every gate. Review measured that rewriting the product call positionally produces a real mypy error (`Too many positional arguments for "__call__" of "_ReapCallable"`) that no gate will ever run, while the shipped `tests/test_reap_contract.py` stays green (F-09). So the Protocol `2o9osz` shipped is a correct annotation that nothing enforces, and a BEHAVIORAL test is the only enforcement available in this repository today. A `mypy` invocation is legitimate EVIDENCE (V-03 uses it for provenance) but is not a standing guard, and this plan must not pretend otherwise. `mypy` is not a declared dependency, so an executor must install it ad hoc and must NOT add it to `pyproject.toml` or `.pre-commit-config.yaml` (see the deferral).
- A PENDING PLAN CAN SHIP YOUR CHANGE BEFORE YOU DO, and the evidence pass must look for that. Learned at review the hard way (F-04, F-14): plan `2o9osz` was already sitting in `.aw/records/plans/pending/` at this plan's authoring HEAD, declaring the SAME production file for the SAME defect from a different backlog item, and it executed first. Reading the CODE proved the defect was live; it could not prove the defect was UNCLAIMED. The convention this plan should have followed, and which its successors should: before authoring, grep `pending/` for every path you intend to put in `- Scope-Paths:` and for the symbol you intend to change, and cite what you find. Two plans racing the same file is not a hazard the runner solves for you at AUTHORING time (its worktree isolation and its merge gate protect EXECUTION), because the waste here was an authored plan whose main item was already claimed.
- CODE IS CITED BY SYMBOL, NOT BY BARE LINE OFFSET, per spec `ipd-structure-and-linting` Section 10.2 and advisory `IPD-C801`. This matters unusually much for this item, because BOTH of its line numbers are now wrong. Item 1's cited offset predates the `rununify` lifts that grew the module by roughly ten thousand lines, so the `holds_work` code it names now sits far below it inside `runner_shared.reconcile_item_on_interrupt`; item 2's cited offset now lands on the `def bound_expiry_reaper(` signature block rather than on the `reaper(process, run_dir=run_dir)` call it was describing. An executor following the item's offsets lands in unrelated valid code, which is exactly how a "fix" gets applied to the wrong side of a working call. Both are therefore cited by symbol and by quoted content string throughout this plan.
- THE ONE SHARED REAPER IS A SPEC REQUIREMENT, SO ITS CALL SHAPE IS A CONTRACT AND NOT AN IMPLEMENTATION DETAIL. `runner_shutdown`'s module docstring and `clean_shutdown` both cite spec `c4gd2h` R5 as forbidding a second reaper, `bound_expiry_reaper`'s docstring states `reap` "is injectable ONLY so a test can observe the call without spawning a real process", and BOTH hosts reach it through the identical line `reap=lane_containment.bound_expiry_reaper(process, run_dir, item)` (`oc_runipd`, `agy_runipd`). A wrong annotation on the seam between a spec-mandated singleton and its only injection point is worth fixing precisely, not papering over.
- `contextlib.suppress` PLACEMENT DECIDES WHAT A TEST CAN OBSERVE in `_expire`: the event-append bookkeeping is suppressed, the reap call is not. E-01's negative assertion depends on that, so it is stated as something the executor must verify by reading the body rather than assume.
