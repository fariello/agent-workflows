## Project conventions discovered (Step 0)

- THE CANONICAL MIGRATION PATTERN IS ALREADY IN THE TREE AND MUST BE COPIED, NOT INVENTED. `cli._run_check` converts a `List[Drift]` into a `CommandResult` with one `Diagnostic` per finding, derives `status` from `artifact_core.drift_exit_code`, enriches severity through `check_engine.enrich_drift`, and emits through `renderers.get_renderer(ctx).emit(res, ctx)`. `leak_sanitizer.main` does the same for its own finding type. Three verbs are being brought onto an established path, not onto a new one.
- SEVERITY IS LOAD-BEARING AND `info` IS EXEMPT. `artifact_core.drift_exit_code` returns nonzero for anything whose `severity` is not `info`, and `check_engine.RULE_REGISTRY` registers `check.stale-index-missing` as `info`. This is why all three verbs can report findings and still exit 0, and it is the specific condition that makes a naive `status = "findings" if drift else "clean"` raise inside the schema validator.
- THE COMPACT RECORD OMITS `detail` BY DESIGN. `result_types.CommandResult.to_agent_record` emits `{"location", "rule"}` per diagnostic unless `context.verbose` is set, and `docs/cli-migration.md` recipe 3 documents exactly that ("the old free-text `detail` column is available under `--verbose`"). So the migration LOSES the third TSV column from the default machine stream, deliberately and consistently with every other migrated check verb.
- `--verbose` IS NOT REACHABLE, so the plan may not lean on it. `select_output` reads it and `to_agent_record` branches on it, but exactly one parser leaf declares the flag (`aw upgrade-test new`, where it means installer verbosity). Backlog `qm04zi` owns that gap. Any instruction in code or docs telling a reader to pass `--verbose` to one of these verbs would exit 2.
- THE THREE MANIFESTS ARE GITIGNORED, which is why a fixture is necessary and why running the verb during validation is safe. `.aw/.gitignore` ignores `records/plans/INDEX.json`, `records/plans/INDEX.md` and the prompts and research twins, so regenerating them changes no tracked file. It is also why this repository's own `index plans --check` reports `check.stale-index-missing` in a fresh worktree, which is the finding used in the measurements above.
- THE HUMAN OUTCOME WORDS ARE DELIBERATELY NOT LIFECYCLE STATUSES. `plans_index.run_index` carries a long comment recording that `wrote`, `updated` and `up to date` are generic command outcomes kept outside spec `uonrjg` R10.3, and that routing them through the lifecycle resolver would print `?` where a user reads a word. Do not touch that print path; this plan changes the `--check` machine branches only.
- MACHINE MODE FORCES COLOR OFF THROUGH THE SHARED CONTRACT. The same module records that `Term(color=not no_color)` once forced color on under `--agent`, `--json`, `NO_COLOR=1`, `TERM=dumb` and a plain pipe, and that the fix was to defer to `select_output`. A migration that hand-rolls its own color decision would reintroduce that defect; `get_renderer(ctx)` already resolves it.
- Cite code by SYMBOL (`module.function`) or by a quoted content string, with a line number only appended to one of those and never alone: an offset expires before this plan executes (spec `ipd-structure-and-linting` Section 10.2; advisory `IPD-C801`).
