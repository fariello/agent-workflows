## Project conventions discovered (Step 0)

- `status_set.run_set_command` is the ONE engine behind five routing spellings (`aw set`, `aw ipd set`, `aw spec`/`specs set`, `aw backlog set`, and a declared-but-dead `aw prompts set`). Its module docstring lists them. So the confirmation-and-commit contract is genuinely SHARED, which is what makes a single canonical statement plus four pointers correct rather than lazy.
- THE CONFIRMATION PREDICATE IS MACHINE-MODE-SCOPED. `run_set_command` reads `if (ctx.is_agent or ctx.is_json) and not is_dry_run and not yes:` and returns the `confirmation required (--yes needed to execute mutation)` refusal. The comment block immediately above it is long and describes the SUPERSEDED flagless behavior at length, which is exactly how a reader (and the backlog item) comes away with the wrong model.
- `--yes` IS OVERLOADED ON THIS SURFACE and that overload is the substance of this plan. `_offer_self_commit` computes `assume_yes` as `getattr(args, "commit", False) or (getattr(args, "yes", False) and not (agent or json or as_agent))`, so for a HUMAN caller `--yes` means "commit without asking". For a machine caller `--yes` means only "confirm the mutation", since the `and not (...)` clause switches the auto-commit half off. One flag, two meanings, split by output mode.
- THE COMMIT OFFER IS PATH-SCOPED AND DECLINES ON NON-TTY. `git_commit_helper.offer_commit`'s docstring states it stages only the caller's explicit paths, never `-A`, never pushes, and that "NON-interactive without `assume_yes` is a NO-OP (skip) ... NOT auto-yes". So the honest sentence for a scripted flagless call is "writes, commits nothing", not "may commit".
- ONE HOME PER POLICY IS THIS REPOSITORY'S OWN CONVENTION, and `.aw/records/backlog/README.md` demonstrates it in the file this plan edits: it defers the release-gate limits to `AGENTS.md` with "read it there rather than here, so the policy has one home". E-02 through E-05 follow that pattern rather than copying five clauses four times.
- `docs/artifact-lifecycles.md` IS THE LONGEST SETTER SURFACE IN THE TREE (roughly 15 setter invocations including `aw set prompts <status> <sel>` and `aw set releases shipped <id6>`, plus a per-type verb table) and is DELIBERATELY NOT IN SCOPE. It is the item's "further occurrences" hint resolved in the negative for this plan; see the deferral, which carries it.
- Exit codes must be measured UNPIPED (standing repository instruction); a piped `$?` reports the pipeline's status. Every exit code quoted in the findings below was taken with `cmd >file 2>&1; echo $?`.
- In-lane `aw` invocations re-exec to match the checkout's package and print a notice; `AW_NO_REEXEC=1` suppresses it, and `python3 -m agent_workflows` avoids it entirely. The fixture measurements used the latter.
