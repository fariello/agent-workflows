## Project conventions discovered (Step 0)

- The hoist target already hosts this family of contracts. `attention_contract` defines `is_safe_descriptive`, `MAX_DESCRIPTIVE_LEN`, `_CONTROL_CHAR_RE`, and `validate_gate_ref` under the comment `Output-safety (Section 8.8): descriptive fields are single-line, bounded, control-char-free.`, and separately hosts `actor_refusal`, a REFUSAL-returning helper with the same "return the reason or None" shape this plan moves. So a public `refuse_unsafe_descriptive` is a precedent-following addition, not a new category.
- `attention_contract` is a deliberate leaf. Its only package import is `from agent_workflows import lifecycle_dirs as _LD`, which is why it can be imported by `backlog`, `specs`, `status_set`, `releases`, `check_engine`, and ~16 other modules without a cycle. The hoist adds no import to it.
- Refusal helpers in this repo return the MESSAGE and let the caller choose the channel and exit code. All three copies return `Optional[str]`; callers write to `sys.stderr` and pick their own code. That is why the per-tree exit-code asymmetry is a call-site property and is untouched here.
- Module-private helpers are addressed by tests through `hasattr`/`getattr` on the module. `tests/test_backlog_descriptive_safety.py` and `tests/test_specs_releases_descriptive_safety.py` both assert the attribute exists before driving it, which is the convention that makes retaining the aliases the cheap option.
- The repo's own execution contract forbids code-pinning tests (AGENTS.md "TEST OUTCOMES, NOT CODE STRUCTURE", GUIDING_PRINCIPLES P16). A duplication-removal plan is exactly where a `inspect.getsource` line-count test is tempting; E-01 and E-06 are specified to forbid it.
