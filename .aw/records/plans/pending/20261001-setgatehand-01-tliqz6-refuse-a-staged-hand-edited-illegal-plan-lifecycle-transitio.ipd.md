## Goal

Close the hand-edit bypass for an ILLEGAL plan lifecycle transition by adding the one commit-scoped rule that is missing, and by adding nothing else. The repository already owns every piece of this except the join: `ipd_lifecycle.validate_transition` knows which edges are illegal, `check_engine.check_status_untooled` knows how to read a staged plan status delta, and `check_engine.check_commit_invariants` knows how to put a commit-scoped rule in front of a commit. What does not exist is a rule that asks the first question about the second's data. This plan writes that rule, composes it where the three existing commit-scoped rules already compose, and pins it by outcome against the four classes it must refuse and the seven it must not.

## Project conventions discovered (Step 0)

- Cite code by SYMBOL (`module.function`) or by a quoted content string, with a line number only appended to one of those and never alone: an offset expires before this plan executes (spec `ipd-structure-and-linting` Section 10.2; advisory `IPD-C801`). THIS PLAN CITES BY SYMBOL THROUGHOUT.
- THE COMMIT-SCOPED RULE SHAPE IS ESTABLISHED AND MUST BE COPIED, NOT INVENTED. `check_engine.check_status_untooled` is the template: it runs `git diff --cached --name-status -M` scoped to the plans prefix, returns early when that output is empty so an ordinary commit pays nothing, and compares `_blob_text(repo, ":0:", path)` against `_blob_text(repo, "HEAD", path)` through the shared `_status_meta`. Its docstring records why commit-scoping is "the key simplification": only files in the commit are examined, so historical records are never touched and no grandfathering list is needed.
- ONE PREDICATE, MANY SURFACES, NEVER A SECOND COPY. `check_engine`'s own section banner states this, and `evaluate_blocking_close` demonstrates it across a setter, a check rule and an opt-in hook. The hook modules under `agent_workflows/hooks/` are deliberately thin: `status_untooled_gate.check` and `backlog_blocking_close_gate.check` are each three lines that call a `check_engine` rule and format its drift. This plan therefore puts ALL logic in `check_engine` and adds no hook module.
- A NEW COMMIT-SCOPED INVARIANT DOES NOT NEED ITS OWN HOOK. `hooks.precommit_scope_gate` is the generalized layer whose docstring says it exists because "the earlier gates each enforce ONE commit-scoped invariant" while it delegates to the single aggregating surface `check_commit_invariants`. Composing into that aggregator is what makes a new rule enforceable at commit time with no new hook id and no `.pre-commit-config.yaml` edit.
- THE COMMIT-SCOPED / WHOLE-TREE LINE IS DELIBERATE AND DOCUMENTED. `check_engine`'s full-sweep block records that whole-tree release-gate rules are deliberately NOT added inside `check_commit_invariants`, "that function is composed by the opt-in pre-commit aggregator and must remain commit-scoped so a local hook cannot refuse a commit over an unrelated artifact in a shared checkout." That is the governing constraint for where this rule may be composed.
- THE SIBLING RULE IS `error` SEVERITY UNDER `I-03`, and so is the advisory recorded-history rule. `RULE_REGISTRY` carries `check.status-untooled` and `check.lifecycle-transition-invalid` both as `RuleSpec("error", ASSURANCE_REPOSITORY, DET_DETERMINISTIC, "I-03")`. `artifact_core.drift_exit_code` exempts only `info`, so `error` fails CI and pre-commit alike.
- THE HONEST-LIMIT PARAGRAPH IS A CONVENTION, NOT DECORATION. Every hook module here carries one, and `AGENTS.md` records the same limit for `backlog-blocking-close-gate`: git hooks are local, not cloned by default, and skippable with `--no-verify`, so the portable authority is the `aw check` rule family plus CI. The backlog item explicitly asks the plan to state this.
- A `- Readiness:` field is an OUTPUT of `/plan-review` and is deliberately ABSENT here; writing one while authoring would forge a review that has not happened, and the auto-approve predicate reads that field first.
