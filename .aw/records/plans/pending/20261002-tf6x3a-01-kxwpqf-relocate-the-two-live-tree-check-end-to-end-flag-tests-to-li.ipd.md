## Project conventions discovered (Step 0)

- The `livecorpus` marker exists for exactly this situation and its registration in `pyproject.toml` (`[tool.pytest.ini_options]`, `markers`) states the criterion as a test that "asserts a property over EVERY artifact in this repository's own .aw/records/ tree, so ANY agent writing a plan can turn it red", and records the measured cost of not using it ("Measured 2026-09-19: one such test went red on three correctly-cleared plans and cost run run-20260919T194413Z-2056285 2h 10m and $55.02 with nothing integrated").
- The marker's registration text also states the preservation rule this plan follows: such tests "are VALUABLE and are not deleted ... so they still run in `make test-all`, in release-review, and wherever a failure informs a human instead of halting a queue". The `Makefile`'s `test-all` target restores both markers by passing `-m ''`.
- `addopts` in `pyproject.toml` is `-q -n auto --dist=worksteal -m 'not slow and not livecorpus'`, so marking a test `livecorpus` removes it from the default run and from CI's main step (`.github/workflows/tests.yml` runs `python -m pytest tests/ -n auto -rfEs`, inheriting `addopts`) without any further configuration change.
- The 90s budget is NOT pytest-timeout; it is a stdlib SIGALRM hang guard in the root `conftest.py` (`_DEFAULT_TEST_TIMEOUT = 90.0`, applied in `pytest_runtest_call`, overridable per test with `@pytest.mark.timeout(<seconds>)` which that file's own rationale comment registers and documents).
- Three existing sites already use this marker and establish both spellings: method-level on `test_ipd_lint.test_the_detector_discriminates_on_the_real_corpus_with_the_gate_disabled` and on `test_review_record_classifier.test_no_pending_plan_has_verdict_class_refusal`, and class-level on `test_orchestrator_probe_payload.TestProbePayloadLiveCorpus`. This plan uses the METHOD-level spelling, because only two of the seven tests across the two files are live-tree sweeps.
- `tests/livecorpus_notice.py` is a non-gating detector that appends a `LIVE-CORPUS NOTE` to an already-failed test naming the live paths it read, and its message explicitly recommends this marker as the remedy. It is registered via `conftest.py`'s `pytest_plugins`.
- `tests.support.ready_plan_text` is the established helper for synthesizing plan text into a throwaway repository, and `tests/test_carrier_reverse_lookup.py` is the in-repo precedent for the exact pattern E-02/E-03 use: build a `tempfile.TemporaryDirectory` repo, then call `cli.main(["check", "plans", "--agent", "--dir", str(repo)])` under `redirect_stdout` and parse the `aw.agent/v1` record out of stdout.
- The production code under test is `agent_workflows.result_types.CommandResult.to_agent_record`, which branches on `is_verbose` for the `diagnostics` key set and applies `--fields` last via `_schema.filter_record_fields`. Both branches are repository-agnostic, which is the structural reason a synthetic repository can cover them.
