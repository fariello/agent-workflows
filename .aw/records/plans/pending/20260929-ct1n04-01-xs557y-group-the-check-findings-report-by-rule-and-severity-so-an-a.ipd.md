# IPD: Group the check findings report by rule and severity so an advisory is not lost in a per-finding enumeration

- Date: 2026-09-29
- Kind: child
- Concern: `aw check`'s human report enumerates ONE `Issue:` block per FINDING instead of one per rule, and prints one `Next` line per finding, so a low-volume advisory is buried in a report dominated by whatever rule is most numerous. The renderer ALREADY CONTAINS grouping code, and that code is DEFEATED BY ITS OWN KEY: `renderers.HumanRenderer.render` groups on `key = (title, fix_action)` where `fix_action = d.fix or fix` is `doctor.build_remediation(...).detailed_fix`, a string that INTERPOLATES THE FINDING'S OWN PATH (`inspect <path> frontmatter and schema conformity.`), so every finding lands in a group of exactly one. Measured at HEAD `df0e2c05`: `aw check plans` reports 19 findings and renders 19 `Issue:` blocks over 5 distinct rules, plus 19 `Next` lines carrying 1 distinct `summary_fix`; `aw check all` renders 22 blocks over 7 rules with 22 `Next` lines. ## Goal

Make the one advisory in a long `aw check` report readable. After this plan, `aw check plans` prints one block per RULE with a severity badge and a count, worst severity first, and one `Next` line per distinct remediation, so a human or agent scanning the report sees the `info` finding instead of losing it among fourteen repetitions of an unrelated error. A report that has no repetition in it renders exactly as it does today.

## Project conventions discovered (Step 0)

- COLLAPSING AN ENUMERATION IS ESTABLISHED PRACTICE HERE, WITH FOUR PRECEDENTS, and all four live in the ENGINE's `detail` string rather than in the renderer. `check_engine.evaluate_durable_carrier` shows five then `(and N more)` (DECISION 07-rnkqrc-D4, plan `cnzrxb` E-01); `_IPD_LINT_SHOWN = 5` cites that decision explicitly for the same reason ("a per-diagnostic Drift would let one badly-formed plan add dozens of lines to every `aw check plans`"); `_SCOPE_DRIFT_PATHS_NAMED = 10` names paths before tailing off, and its comment states the principle this plan inherits, that a finding reporting only a number is unactionable; and `check_spec_criteria_uncovered` caps at five under a 60-character budget. This plan adds the FIRST renderer-side collapse, and deliberately keeps every member NAMED for that reason.
- `check_scope_drift`'s docstring already states the governing rule as "ONE FINDING PER PLAN, NOT ONE PER PATH ... The collapse is UNCONDITIONAL (no threshold)". This plan's E-02 is that same rule applied one level up, at the rendered block.
- Cite code by SYMBOL (`module.function`) or by a quoted content string, with a line number only appended to one of those and never alone: an offset expires before this plan executes (spec `ipd-structure-and-linting` Section 10.2; advisory `IPD-C801`).
- `renderers.HumanRenderer` is SHARED BY EVERY COMMAND that calls `get_renderer` (45 call sites in `cli.py` alone, plus `attention`, `backlog`, `artifact_adopt`), so a change to its Findings block is not a check-only change. Two guards follow: `doctor` short-circuits to its own `render_human_report` at the top of `render` (so `aw doctor` is untouched by construction), and the E-02 grouping change is behavior-preserving for any command whose findings do not repeat a rule (E-03).
