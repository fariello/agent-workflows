## Goal

Make `check_engine.check_scope_drift` provably covered again, and make the next author who arranges a
scope-drift case get the lane for free instead of having to remember it.

Three properties, all currently absent. FIRST, breaking the rule must break the suite: today it can
return nothing for every input and nothing fails. SECOND, an arrangement that silently stops measuring
must be visible: every assertion of SILENCE is paired with an arrangement that FIRES from the same
fixture, so a rule that had stopped working entirely fails the firing row rather than passing all the
silent ones. THIRD, and this is the property the review had to ADD because the authored row set did not
carry it, A WRONG-TREE RULE MUST BE DISTINGUISHABLE FROM A SILENT ONE. The two failure modes are not the
same defect and a row set that cannot tell them apart does not cover the rule's headline claim.

WHY THE THIRD PROPERTY NEEDS ITS OWN ROW, measured at review 2026-09-30 and not inferred. Every row
this plan originally specified arranges its change INSIDE the lane, so the main checkout is clean in
all of them. Replacing the rule's lane resolution with the running tree (`exec_tree = Path(repo_root)`,
applied to real source) then fails EXACTLY ONE row, row (a), which is the same single row an
unconditional early return fails. Worse, simulating the ACTUAL historical defect (the rule measuring
the UNION of the lane and the running tree, which is what produced 350 findings of which 350 were other
agents' commits) passes ALL SEVEN of the originally specified rows, because in every one of them the
union equals the lane. One row closes all of this: MAIN dirty out of scope while the LANE is clean,
asserted SILENT. Unmutated it is silent; under the wrong-tree mutation it FIRES; under the
report-nothing mutation it stays silent, so it is not confounded with property one. That row is E-06.
