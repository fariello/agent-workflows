## Goal

Stop `aw check` and `aw doctor` printing an instruction that cannot be followed. When a finding is about a SCAN or a PROBE rather than about one artifact, the report currently tells the reader to inspect the frontmatter of `<collisions>`, `<sanitizer>` or `<git>`, none of which are files. After this plan such a finding gets a remedy line that is true of what it actually reports, and the dead tuple that the backlog item mistook for the cause is removed so the next reader is not misled by it.

WHAT THIS GOAL DOES NOT CLAIM, ADDED AT REVIEW SO IT IS NOT READ AS PROMISING MORE (F-13). This does not make the frontmatter sentence disappear from a typical run. Measured at review on `aw check plans`: of 26 findings exactly ONE is sentinel-located, so that surface goes from 26 frontmatter sentences to 25, not to 0. The remaining 25 are REAL-PATH findings for which "inspect its frontmatter" is vague but not FALSE, and improving them is the sibling plan's territory for rules that author a recovery and nobody's yet for the rest. The defect this plan closes is narrower and sharper than "the fallback is unhelpful": it is that the tool asserts a file property of something that is not a file, which is a false instruction rather than a weak one, and it is the entire population of five `doctor.probe-failed` producers that fire exactly when something has already gone wrong.

## Project conventions discovered (Step 0)

- THE SENTINEL PREDICATE ALREADY EXISTS AS AN IDIOM IN THIS MODULE and E-01/E-03 must reuse it rather than invent a constant. `doctor._extract_record_id6` opens with `if not loc or (loc.startswith("<") and loc.endswith(">")):` and repeats it at its second guard; `doctor._categorize_drift`'s first branch is `if loc.startswith("<") and loc.endswith(">"):`; and two branches inside `build_remediation` itself (`doctor.git-dirty`, `doctor.git-staged`) already suppress a location phrase with `if loc and not loc.startswith("<")`. So the module's established convention is the inline predicate, and the backlog item's suggestion to "derive the sentinel exclusion from a shared constant" would ADD a concept where four sites already agree without one. E-03 therefore reuses the predicate and does not mint a constant; OQ-03 records the reasoning.
- A NON-FILE FINDING RETURNS `file_path=None`, ESTABLISHED BY THREE SHIPPED BRANCHES. `doctor.setup-needed`, `doctor.layout-split-brain`, `doctor.pypi-update-available` and `doctor.version-*` all return `file_path=None`, and `doctor.setup-needed` carries a comment explaining that its `command` stays non-None because "a None command is dropped from raw_actions entirely". So E-01's `file_path=None` follows a convention rather than introducing one, and the single consumer of the field (`_categorize_drift`'s `loc = rem.file_path or d.location`) already handles `None` by falling back to the drift's own location.
- THE `title` EXPRESSION IS LOAD-BEARING AND IS DEPENDED ON BY A DELIBERATE WORKAROUND. `check_engine.check_collisions` carries a comment saying its detail "is kept under 60 characters deliberately" because `build_remediation`'s "generic fallback uses the detail AS THE TITLE when it is short enough", and the backlog item `cciw6g` itself records that same workaround as its own. E-01 therefore must not touch `title = detail if len(detail) < 60 else rule`, and V-02(c) pins it mechanically so the invariant is not eyeball-only.
- COMMANDS ARE GUARDED AGAINST PLACEHOLDERS, WHICH CONSTRAINS WHAT E-01 MAY PUT IN `command`. `tests/test_doctor.DoctorRemediationTests.test_remediation_family_guard` asserts of every non-None `command` that it contains neither `<` nor `>`. E-01's sentinel text necessarily contains `<...>`, so it must go in the fix strings and `command` must stay `None`; putting it in `command` would turn that shipped guard red.
- Cite code by SYMBOL (`module.function`) or by a quoted content string, with a line number only appended to one of those and never alone: an offset expires before this plan executes (spec `ipd-structure-and-linting` Section 10.2; advisory `IPD-C801`).
