## Project conventions discovered (Step 0)

- A plan may amend a spec and MUST declare it (AGENTS.md). The spec is therefore in `Scope-Paths`, which is what makes both runners announce the declared spec edit before the run starts and reconcile it at finalize.
- Spec status and history are OWNED by `aw specs`; history is appended with `aw specs note`, never hand-edited (AGENTS.md; `.aw/records/specs/README.md`). E-06 follows this and the plan changes no `- Status:`.
- Cite code by SYMBOL (`module.function`) or by a quoted content string, with a line number only appended to one of those and never alone: an offset expires before this plan executes (spec `ipd-structure-and-linting` Section 10.2; advisory `IPD-C801`). This area is a measured case study: backlog `oq05nc`, plan `4h7tt0`, and the spec's own `RUN-NO-PUSH` retirement paragraph each cite the anti-inference rule in `host_sandbox_profile` by a BARE LINE RANGE, and the three ranges disagree with each other and with the current file, so all three now misdirect a reader. The rule is durably reachable instead as `host_sandbox_profile`'s module docstring together with its `_DECLARED_UNENFORCED` rationale. Every citation here names a symbol or quotes a string, and E-03/E-04 identify their edit sites by QUOTED TEXT for the same reason.
- Tests must assert observable behavior and outcomes, never code structure: no `inspect`/`ast`/regex reads of production source, no caller counts, no pinning of docstring or comment text (AGENTS.md; GUIDING_PRINCIPLES P16). E-02 calls the shipped artifacts and asserts on returned values plus `dataclasses.fields`, the same runtime introspection the file's existing `DenyPushRemovedTests` uses. Note that `tests/test_host_capability_wiring.py` DOES parse `runner_shared` with `ast`; it is pre-existing and this plan neither extends nor imitates it.
- A capability may only be set True by code that executed a probe for it, and inferring support from a helper's PRESENCE is forbidden in writing (`host_sandbox_profile`'s module docstring and its `_DECLARED_UNENFORCED` rationale; restated in `run_evidence`'s `RUN-NO-PUSH` retirement comment). This plan adds no probe and no capability, so it cannot violate the rule; it is named because it is why the honest answer here is prose rather than code, and why E-03 must not cite `git_commit_helper` as enforcement.
- The `RUN_FINDING_CODES` table's size is itself contractual: `run_evidence.validate_finding_table` hard-fails on a count other than 12, and `tests/test_run_finding_spec_transcription.py` guards byte equality between spec 4.2 and the shipped codes. This plan adds, removes, and rebinds NO row and edits NO 4.2 cell, so both invariants are untouched; E-02 only READS the table.
- `tests/test_run_finding_abort_partition.py` parses spec `25kzda` 4.2 out of the spec FILE, under a narrow stated P16 exception because the contract text is the artifact under test. Its parser selects only lines beginning `| \`RUN-` with exactly five cells, so it cannot match a 5.2 guarantee row (which begins `| 1 |` and has four cells).
