## Project conventions discovered (Step 0)

- THE VIEW IS A PROJECTION, NOT A SOURCE OF TRUTH, and `aw attention` is READ-ONLY by spec (`attention-registry-and-cross-tree-status`, decision 1 and G3/G4: writes are owned by per-tree verbs). Synthesizing a record for display is therefore in-contract; writing a `- Status:` into the malformed file to make it parse would NOT be, and this plan does not.
- FAIL CLOSED IS THE HOUSE RULE, stated in that spec's Section 8.6: `--check` "never silently skips a malformed included artifact nor downgrades a local failure to a warning". This plan is additive to that rule and must not weaken it, which is why E-02 keeps `drift.extend` untouched and E-04(7) re-asserts the exit code.
- APPENDING AN OPTIONAL TRAILING FIELD WITH A DEFAULT IS THE ESTABLISHED WAY TO EXTEND `Item`, and the type's own comments say so twice (the `priority`/`blocks_release` note and the longer `item_dependencies` note both record "appended LAST with a default, matching the pattern"). This plan needs NO new field at all, which is strictly cheaper than that precedent.
- Cite code by SYMBOL (`module.function`) or by a quoted content string, with a line number only appended to one of those and never alone: an offset expires before this plan executes (spec `ipd-structure-and-linting` Section 10.2; advisory `IPD-C801`).
- `agent_workflows/attention.py` IS A SHARED, HIGH-TRAFFIC FILE declared by three other pending plans (`1qt1u3`, `r61br4`, `nwcf8j`), so "verify what you are actually about to commit" is not optional here.
