# IPD: Make run_cli's module docstring agree with its own module, by pointing at the constants instead of re-transcribing them

- Date: 2026-10-02
- Kind: child
- Concern: `agent_workflows/run_cli.py`'s module docstring Contract block CONTRADICTS the constant block declared about twenty lines below it in the SAME file, so the module disagrees with itself and a reader who trusts the prose gets a wrong answer about a shipped contract. Every claim in backlog `h9kgjp` reproduced EXACTLY at this HEAD by parsing the module rather than by reading it (F-01): the constants carry the eight values `0..7` (`EXIT_OK` 0, `EXIT_INCOMPLETE` 1, `EXIT_INVALID_INVOCATION` 2, `EXIT_BLOCKED` 3, `EXIT_INVALID_EVIDENCE` 4, `EXIT_CORRUPTED_LEDGER` 5, `EXIT_OPERATIONAL` 6, `EXIT_NOT_A_LEDGER` 7), while the docstring lists only `[0, 1, 2, 5, 7]` and OMITS `[3, 4, 6]`. Worse than the omission, the docstring MISASSIGNS a code it does list: its `exit 1 = incomplete / invalid evidence / unsatisfied requirements` folds invalid-evidence into 1, while `EXIT_INVALID_EVIDENCE` is 4.
  THE MISASSIGNMENT IS SUBSTANTIVE, NOT PEDANTIC, BECAUSE EXIT 4 IS REACHABLE AND WAS DRIVEN (F-02). The item rates the defect as misleading "a code reader only", which is true of the HARM but could be read as implying the folded-in code is unreachable. It is reachable: `run_cli._run_finalize` returns `EXIT_INVALID_EVIDENCE` from its `evidence.validate_ledger_evidence(records)` gate BEFORE the separate `evaluate_completion` gate that returns `EXIT_INCOMPLETE`, i.e. the two codes the docstring merges are produced by two DIFFERENT gates in one function. Measured end to end by building a real ledger and calling the real handler: a `tool_event` carrying `exit_code: 1` yields finding `EV-FAILED-EXIT` and the handler returns **4**, printing `error: captured evidence is invalid; refusing to finalize`. A caller branching on the docstring would treat an invalid-evidence refusal (a false-completion class, the thing the run ledger exists to catch) as an ordinary incompleteness, which is exactly backwards.
  THE OMITTED CODES ARE REACHABLE TOO, so the docstring is not merely abbreviating rarely-seen values (F-03). `EXIT_OPERATIONAL` (6) was produced by a driven call: `aw run record` against a step already `performed` returned **6** with `error: illegal/unauthorized transition: Illegal transition from 'performed' to 'performed'`. `EXIT_BLOCKED` (3) is returned from eight distinct sites in the module including `_run_next`'s terminal `return EXIT_OK if runnable_ids else EXIT_BLOCKED` and `_run_record`'s recorded-failure arm.
  THE FIX SHAPE IS THE QUESTION THE ITEM DELIBERATELY LEFT OPEN, AND THIS PLAN ANSWERS IT WITH A POINTER, ON REPOSITORY EVIDENCE RATHER THAN TASTE (F-05, OQ-01). The item says the right fix "may be to shorten this docstring to a pointer rather than re-transcribe a table", conditioned on `u28vqb` E-05 landing first. Duplicated normative content is a maintenance and correctness hazard") names re-transcription as the hazard, and this defect IS that hazard having already fired. A second transcription would be a new copy to drift. So this plan DELETES the transcribed list and points at the adjacent `EXIT_*` constants, whose inline comments already state each meaning.
