## Goal

Make the runner's own close predicate refuse an item whose spec carrier has not shipped, so the predicate that is strict about plans is equally strict about specs.

WHAT CHANGES, as an observable verdict. Today, on an item carrying one `executed` plan and one `approved` spec, `evaluate_backlog_close` returns `close=True, rule='ipd'` and cites the plan. After this plan it returns `close=False` naming the unimplemented spec, and the item stays open until that spec reaches `implemented`. The single-kind rules do not move: an IPD-only item still closes when every IPD carrier is executed, and a spec-only item still closes on EXISTENCE with status deliberately unread.

WHY THE MIXED CASE IS DIFFERENT FROM THE SPEC-ONLY CASE, because the fix must not collapse them. `zhr6mc` OQ-01 (maintainer-resolved) says the discriminator is whether the item's requested output INCLUDES an IPD: if it does, the item promised CODE and closes only when that code ships; if it does not, the item asked for the ARTIFACT and existence is the whole test, which is why a `draft` spec legitimately closes a spec-only item. A MIXED item is in the first class, so it promised code, and a same-gate spec sitting in that promise is part of the work. The current code agrees in its comment and disagrees in its control flow: the comment says "carriers include >= 1 IPD -> the item promised CODE", and the body then judges only the IPDs.

THE RULE THIS CONVERGES ONTO ALREADY SHIPPED, which is what makes this a convergence rather than a new policy. `2o5wka` tightened the inner gate's HANDOFF arm to require EVERY same-gate carrier executed or implemented, explicitly spanning both carrier kinds via `check_engine._carrier_is_executed`, and its E-03 case (5d) pins exactly the shape this plan is about: "executed plan + approved spec -> refused; implemented spec -> allowed". `tests/test_backlog_handoff_close.py::test_case_5_mixed_kind_carriers_plan_and_spec` asserts it today. So the mixed-kind answer is settled in this repository; only the OUTER predicate never got it.

## Project conventions discovered (Step 0)

- THE TWO CLOSE PREDICATES ARE DELIBERATELY SEPARATE MECHANISMS, and `runner_shared.evaluate_backlog_close`'s docstring says so: the outer one decides whether THIS RUN EARNED the close and filters carriers; the inner `check_engine.evaluate_blocking_close` decides whether a RELEASE GATE may be released. They have independent override mechanisms. So "the inner gate would have caught it" is not a defence for the outer one, and the fix belongs on the outer side.
- A SPEC'S TERMINAL STATE LIVES IN ITS `- Status:` FIELD, NOT IN ITS DIRECTORY, which is the opposite of a plan. `check_engine._carrier_is_executed` records this distinction and is the one place that implements it; `tests/test_backlog_handoff_close.py` case (9) pins the field winning over the directory. Any new spec-state read would be a second authority and would drift.
- THE SINGLE SHARED CARRIER LOOKUP IS LOAD-BEARING. `evaluate_backlog_close` calls `check_engine.find_from_backlog_artifacts` and its comment forbids a local scan ("a second implementation here would be the same divergence defect this repository keeps hitting"). That call is also documented SINGLE-ITEM-ONLY and is machine-checked by `tests/test_carrier_scan_single_item_contract.py`; this plan adds no new call site.
- `runner_shared` IS SHARED BY BOTH HOSTS BY IMPORT, NOT BY COPY. `oc_runipd` and `agy_runipd` each bind `evaluate_backlog_close as evaluate_backlog_close` from it, so one edit reaches both drivers and neither host file needs touching. This is the `cnwy8g` re-homing invariant.
- Cite code by SYMBOL (`module.function`) or by a quoted content string, with a line number only appended to one of those and never alone: an offset expires before this plan executes (spec `ipd-structure-and-linting` Section 10.2; advisory `IPD-C801`).
