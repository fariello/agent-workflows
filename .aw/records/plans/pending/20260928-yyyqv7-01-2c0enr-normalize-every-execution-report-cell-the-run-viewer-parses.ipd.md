## Goal

Make the run viewer's report-table reader treat all eight of its columns alike, so no future producer can silently lose a badge by writing a value in backticks, and so the "keep this column BARE" instruction that two shipped comments give a future author stops being load-bearing. No rendered byte changes for any report a shipped host actually writes: both hosts already emit the verify cell bare, and this plan proves that by measurement rather than assuming it.

## Project conventions discovered (Step 0)

- CODE IS CITED BY SYMBOL, NOT BY BARE OFFSET (spec `ipd-structure-and-linting` Section 10.2, advisory `IPD-C801`). This plan is an unusually direct illustration: every offset in backlog item `yyyqv7` and all four offsets in the two shipped comments about this defect are now stale, and one of them (`run_viewer.py:1370`) points at a `return set()` inside an unrelated Set-id reader. E-04 exists because of it.
- THE REPOSITORY ALREADY TREATS BACKTICK MARKUP AS SOMETHING TO NORMALIZE AT A PARSE BOUNDARY, in two independent places, so E-01 adopts an established shape rather than inventing one. `check_engine._identity_declared_values` compares declared `- Id:`/`- Set:` values "STRIPPED of backticks and quotes" and records the live case that forced it (one tracked record declares `` - Set: `awoptimize` ``). `selectors._normalize_yaml_scalar` does the same for the YAML dialect and is explicit that it is a guard rather than a live fix. Both normalize ONCE, at the read, not at each comparison.
- A NORMALIZATION MAY LEGITIMATELY BE SCOPED TO ONE DIALECT, and that is a decision to record rather than a gap. `selectors._normalize_yaml_scalar`'s docstring states that the BULLET reader deliberately returns a backticked value VERBATIM because normalizing there flips a real query's winning kind, pinned by `tests/test_cli_find.py::BacktickSetValueIsPinnedTests`. So "strip backticks everywhere" is NOT this repository's rule; "strip them where a value is COMPARED to a closed enum" is. The verify column is compared to `runner_shared.VERIFY_DISP_VERIFIED`, a closed three-value enum, which is why it qualifies.
- THE SUITE RUNS BARE: `pyproject.toml` `addopts` already supplies `-q -n auto --dist=worksteal -m 'not slow'`. Run `python3 -m pytest` with no added flags; a second `-q` suppresses the `N passed` line this plan's validation requires, and `-n0` makes the run several times slower.
- THE SUITE IS GREEN. An earlier reading of this plan recorded one pre-existing failure; it was repaired by `f1b5b9ff` after authoring, and a bare run at review reports `3109 passed, 2 skipped` with zero failures (F-08). So there is no failure to excuse, and any failure the executor sees is theirs to explain.
- A SINGLE NORMALIZING HELPER IS NOT AUTOMATICALLY SAFE FOR EVERY COLUMN: two of this table's columns want opposite empty-cell answers, measured in F-12. The repository's precedents normalize at the read, which this plan follows, but they normalize ONE field's dialect rather than eight heterogeneous cells, so the empty-cell policy has to stay per-column at the call site.
