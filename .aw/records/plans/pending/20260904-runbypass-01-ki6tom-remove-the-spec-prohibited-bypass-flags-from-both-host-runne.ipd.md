## Project conventions discovered (Step 0)

- THE PROHIBITION IS BY NAME, NOT BY CAPABILITY. Spec 2.1 `:140` forbids four specific spellings on `run`. It does not say verification cannot be disabled; it says these flags do not exist. That distinction is what makes E-04 a design question rather than a deletion, and it is also what makes E-02 an alias-only edit: `--dangerous` is a forbidden NAME for a capability that is operationally REQUIRED.
- A PROHIBITED FLAG NAME AND A PROTECTED FLAG BEHAVIOR CAN COEXIST ON THE SAME ARGUMENT, and this repo has exactly that case. `--dangerously-skip-permissions` carries a prohibited alias (`25kzda:140`) AND a normatively protected default (`7ckptx` R4.1c). Conformance work must therefore separate NAME edits from DEFAULT edits with care; conflating them is what made the original E-02 unexecutable (F-9).
- WHEN AN APPROVED SPEC FORBIDS A CHANGE, A TEST MAY EXIST THAT FAILS IN THE OPPOSITE DIRECTION FROM NORMAL. `tests/test_lane_permission_posture.py:315` is documented as "A REGRESSION GUARD IN THE OPPOSITE DIRECTION FROM EVERY OTHER CHECK HERE" and asserts literal SOURCE STRINGS, so a plan that edits those lines fails a test whose message explains why the edit is forbidden. Before proposing a safety "hardening", grep the specs and the tests for an existing ruling.
- `BooleanOptionalAction` SILENTLY DOUBLES A FLAG'S SURFACE. Every `--x` declared with it also accepts `--no-x`, for every alias. This is how the opencode host violates a prohibition that appears nowhere in its source, and it is why E-01 must assert by PARSING rather than by grep. IT ALSO APPEARS ON MORE THAN ONE SUBPARSER: `start` and `resume` register it separately with different defaults (`False` versus `None`), so an audit must enumerate subparsers, not modules.
- THE RUN-STATE OPTION KEY AND THE CLI FLAG ARE SEPARATE SURFACES, and both hosts already rely on the distinction: opencode reads legacy `no_verify`/`no_audit` keys at `:6034` purely so a run frozen under an older CLI still resolves. Removing a flag must not rename a state key.
- THE TWO HOSTS' VERIFICATION DEFAULTS DIVERGE DELIBERATELY and a code comment documents it (`agy_runipd.py:3463-3468`). Unlike the `--full-auto` divergence that `uyeko5` E-07 normalized by maintainer ruling, this one has NOT been ruled on, so this plan preserves it and asks.
- THE FLAG SURFACE IS NOW DECLARED AS DATA IN A SHARED MODULE (`runner_shared.RUN_POLICY_FLAGS`, landed by the now-executed `uyeko5`), which is the canonical mechanism this repo's no-duplicate-paths convention would prefer for anything describing the run flag surface. E-06 must decide explicitly whether the prohibition belongs there (F-11).
