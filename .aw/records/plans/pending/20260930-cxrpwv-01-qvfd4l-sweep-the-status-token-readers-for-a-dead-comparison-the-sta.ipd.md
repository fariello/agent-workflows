- Date: 2026-09-30
- Kind: child
- Concern: The `statusvocab` (`cyamvi`) rename made the runners write canonical terminal tokens (`fail-depend`, `fail-verify`, `not-run`, ...) while leaving hardcoded LEGACY-ONLY token collections behind in readers that were never updated. A measured sweep of every legacy key of `runner_shared.TERMINAL_STATUS_ALIASES` across `agent_workflows/` finds THREE surfaces whose behavior an operator can see is WRONG for a live post-rename run and RIGHT for a pre-rename one: `render_stream.render_run_summary_table` counts a frozen `skip` item (`not-run`) as COMPLETED WORK and renders `Progress: 2/3` where the same queue spelled `not-attempted` renders `0/3`; `run_viewer`'s `aw runs --failed` filter matches NONE of the six canonical `fail-*` tokens, so a run whose only item is `fail-verify` is HIDDEN from the failure filter while the same table PRINTS `fail-verify` for a `partial` item it does show; and `run_dashboard._outcome` classifies the runner-written dispositions `fail-lane` and `fail-begin` as `unknown` rather than `failed`.   OUT: the two sites plan `5o1jye` already fixed (`render_run_summary_table`'s diagnostics arm and `write_report`'s `## Dependency blocks (why)` gate, both now canonicalized and shipped); every site the sweep measured as CORRECT BY CONSTRUCTION because it accepts both spellings deliberately (`runner_shutdown.KNOWN_ITEM_STATUSES`, `lifecycle_style._RUNNER_ITEM_PAIRS`, `attention.get_active_runs_map`, `runner_shared.DISPATCH_PROVING_STATUSES`, `artifact_audit._status_disagrees`); every `blocked`/`partial` literal that is a DIFFERENT VOCABULARY's member and not a runner terminal status at all (backlog gates, IPD exec-states, release statuses, verify verdicts, research pipeline positions); and the two surfaces another pending plan already owns (`attention`'s Run column, owned by `r61br4`; `render_stream`'s zero-dispatch denominator collapse, owned by `35mjqc`).

## Project conventions discovered (Step 0)

- Cite code by SYMBOL (`module.function`) or by a quoted content string, with a line number only appended to one of those and never alone: an offset expires before this plan executes (spec `ipd-structure-and-linting` Section 10.2; advisory `IPD-C801`).
- THE CANONICALIZE-AT-THE-READER PATTERN IS ALREADY ESTABLISHED IN THESE VERY FILES, so this plan applies a convention rather than inventing one. `run_viewer` already imports `canonical_terminal_status` at module level and already calls it at four DISPLAY sites (`status_word = canonical_terminal_status(step.status)` and three `st_disp`/`st_display` assignments); the defect is precisely that its FILTER sites were not given the same treatment. `artifact_audit` canonicalizes at the top of `_status_disagrees`, `expected_dir_for_status` and `audit_artifact`. `runner_shared.write_report`'s dependency-block gate was converted to `canonical_terminal_status(item.get("status")) == "fail-depend"` by plan `5o1jye`.
- LEGACY TOKENS REMAIN READABLE FOREVER, which decides the SHAPE of every fix here: spec `25kzda`'s 2026-09-25 amendment keeps the legacy spelling readable (the spec itself now writes them as "`fail-depend` (legacy `dependency-blocked`)"), because these surfaces read FROZEN run directories written by an older driver. So the correct fix at a reader is to ACCEPT BOTH by canonicalizing, never to swap one hardcoded token for another.
- Test-outcome discipline: `AGENTS.md` forbids code-pinning tests (no `inspect`, no `ast`, no source regex, no symbol censuses, no line counts). Every test this plan adds therefore CALLS the entry point and asserts rendered output or returned values.
- Suite invocation: run `python3 -m pytest` BARE. `pyproject.toml` `addopts` already supplies `-q -n auto --dist=worksteal -m 'not slow'`; do not add `-n0`, a second `-q`, or `-p no:randomly`.
- Run records are NOT tracked in git (`git ls-files | grep -c "records/runs/"` returns 0, and `discover_run_dirs` finds 0 run dirs in a fresh worktree), so every measurement and every test in this plan must SYNTHESIZE a run directory in a temporary path rather than read a corpus. This is why the findings below cite constructed probes and not a corpus census.
