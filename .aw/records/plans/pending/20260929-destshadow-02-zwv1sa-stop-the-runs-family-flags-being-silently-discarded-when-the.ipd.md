# IPD: Stop the runs family flags being silently discarded when they precede the leaf name

- Date: 2026-09-29
- Kind: child
- Concern: `aw runs --dir <path> list` SILENTLY DISCARDS `--dir` and inspects the current directory's repository instead, because `runs list` re-declares `--dir` with `default=None` and `argparse._SubParsersAction.__call__` copies the child's whole sub-namespace over the parent (`for key, value in vars(subnamespace).items(): setattr(namespace, key, value)`), so the child's DEFAULT overwrites the value the operator supplied. Demonstrated end to end on a temporary repository holding one run: `aw runs --dir <tmp> list` prints `no matching runs found` while `aw runs list --dir <tmp>` prints the run. This is not one flag: ALL FIFTEEN viewer flags (`--dir --last --set --ipd --status --since --active --failed --detail --short --summary-only --latest-only --issues --all-classes` and the `targets` positional) lose their value when placed before the leaf, and twelve further `runs` leaves lose `--dir` the same way (`show evidence verify-ledger next resume status decisions questions analyze query export submit`), for 29 measured flag-and-leaf pairs. The failure is SILENT and its answer is PLAUSIBLE, which is what makes it worse than a crash: the operator gets exit 0 and a well-formed empty table, so they conclude the repository has no runs rather than that their argument was thrown away.
- Scope: Make a `runs` leaf's own flag default STOP overwriting the family value, by the mechanism the sibling `releases` family already uses correctly, and guard the property. IN: `default=argparse.SUPPRESS` on the colliding flag declarations under the `runs` family in `agent_workflows/cli.py` so an ABSENT leaf flag leaves the family's parsed value alone; a new `tests/test_runs_flag_position_parity.py` asserting POSITION PARITY (each flag resolves to the same value before and after the leaf token) across every affected leaf, driven through the CLI rather than by inspecting the parser; and an end-to-end case on a temporary repository proving `aw runs --dir X list` now finds the run it previously missed. OUT: any change to what a flag MEANS, any rename, any new flag, any change to the `runs`/`run` split or to `_ViewerOrLeafSubParsersAction`'s routing, the `releases new --version` case (F-09: benign, different mechanism), and the SUBCOMMAND-shadowing shape of the same argparse mechanism, which is Order 01's (`8kd4eo`).

## Project conventions discovered (Step 0)

- THE `releases` FAMILY ALREADY SOLVED THIS, IN THIS FILE, WITH THE REASONING WRITTEN DOWN. Its subparsers declare `--dir` with `default=argparse.SUPPRESS` and the comment states why: "Unlike the other record families (whose bare form prints help), a bare `aw releases` IS a real leaf that lists, so `--dir` must be accepted BEFORE the subcommand too. The subparsers therefore default their own `--dir` to argparse.SUPPRESS: absent means 'leave the parent's value alone'". `aw runs` has the identical shape (a bare form that is a real leaf) and was missed.
- THE SAME MECHANISM IS ALREADY USED FOR `--json`/`--agent` ON ANOTHER FAMILY, so `SUPPRESS` is this file's established idiom rather than a novelty: `common_upgrade` declares both with `default=argparse.SUPPRESS` and its comment records the measured reason ("so that a --json supplied BEFORE the subcommand is not clobbered by the subparser's own default (F-5 / CliTests regression)"). That is this defect, in a different family, already fixed once.
- TESTS ASSERT OUTCOMES, NEVER CODE STRUCTURE. `GUIDING_PRINCIPLES.md` P16 forbids `inspect.getsource`, `ast.parse`, `read_text()` or substring search against `agent_workflows/*.py`, and forbids count or census pins as a proxy for an invariant. Hence E-04 parses argv and compares resolved values instead of asserting that a declaration says `SUPPRESS`; asserting the latter would pass even if the value were still lost.
- COUNT PARSER OBJECTS BY `id()` AND COMPARE ACTIONS BY IDENTITY, NOT BY NAME. Aliases share one parser object (`discover_parser_leaves` records the measured 63-spurious-leaf cost of the name walk), and `parents=[...]` makes ONE action object appear on several parsers, which is the trap E-02 must handle.

## Open questions

### OQ-01: Should a pre-leaf flag instead be made a USAGE ERROR rather than being honored?

- Blocking: no
- Status: resolved
- Owner: none
- Resolution or deferral rationale: RESOLVED, HONOR IT. Refusing `aw runs --dir X list` as a usage error would be defensible in a vacuum (one canonical position per flag) but it is wrong for this tree on two counts of measured evidence. First, the bare form is a REAL LEAF: `aw runs --dir X` with no subcommand is the documented primary spelling and must keep accepting the flag, so the flag genuinely belongs at the family level and a leaf cannot claim exclusive ownership of it. Second, the sibling `releases` family already resolved the identical question the other way, in code and with its reasoning written down ("`aw releases --dir X` and `aw releases list --dir X` both resolve the same repo root"), so refusing here would make two families with one shape disagree, which is the very inconsistency this plan exists to remove. A refusal would also break the ten `--dir`-before-leaf invocations that exist in the suite today.

### OQ-02: Should the `run` (writing noun) leaves receive the same treatment for symmetry?

- Blocking: no
- Status: resolved
- Owner: none
- Resolution or deferral rationale: RESOLVED, NO. `aw run` has no family-level `--dir` above its leaves, so a `run` leaf's `--dir` default overwrites nothing and there is no collision to fix. Changing those defaults to `SUPPRESS` anyway would alter the namespace shape for a command with no defect, purely for a symmetry a reader would then have to explain. The shared `_register_run_leaf` helper registers leaves for BOTH nouns, so E-02 must scope its edit by the subparsers group rather than by the helper, and that is stated as an explicit prohibition in the execution gate.
