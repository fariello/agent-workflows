# IPD: Decide whether any backlog status transition needs an authority attestation, and record the ruling as the backlog counterpart of TRANSITION_AUTHORITY

- Date: 2026-10-02
- Kind: child
- Concern: Specs answer two independent questions in two separate structures: `attention_contract.SPEC_TRANSITIONS` answers "is this edge legal" and `attention_contract.TRANSITION_AUTHORITY` answers "may THIS actor perform it". Backlog has NEITHER today. Sibling plan `cc2m29` adds only the legality half and explicitly carries the authority half to this plan. The deliverable is the decision plus the fence, NOT a new table.

THE ITEM ASKS FOR A DESIGN DECISION AND THIS PLAN ANSWERS IT WITH A MEASUREMENT RATHER THAN A PREFERENCE. The decisive finding is F-04: automation PERFORMS three of the five backlog targets (`->graduated` and `->open` in the runner's graduate and containment-rollback paths, `->done` in `close_backlog_item`), so a `by_human` requirement on any of those three would refuse the runner's own prescribed path, and a flag the runner must pass attests nothing, which is the critique this repository already levels at `TRANSITION_AUTHORITY`'s `human_token` field (F-03). The two remaining targets are measured out of the running too: `->blocked` is reached by CREATION and not by transition, and `->parked` by no automation at all but also by nothing high-stakes (F-05). THE ONE HIGH-STAKES TARGET IS ALREADY POLICED AND BY A STRONGER MECHANISM: `->done` carries `check_engine.evaluate_blocking_close`, an evidence-kind fail-closed predicate that demands a resolvable citation, which is strictly more than a flag (F-06). The plan therefore recommends NO authority table. It records ONE honest alternative with its measured cost rather than hiding it (F-07, F-09, OQ-01): backlog terminal reopen is unguarded on both spellings while plans get `--allow-terminal-reopen`, and that flag is DECLARED on `aw backlog set` but inert, so activating it is the viable other option and would redden two shipped tests that deliberately pin `done -> open`. Per the `llbr2b` precedent (F-10), the maintainer's APPROVAL of this plan is the attestation of the ruling, so no attestation field is hand-written here.

## Goal

Replace an unrecorded design question with a recorded ruling, so that "does a backlog transition need an attestation" is answered once, in `DECISIONS.md`, with its evidence, instead of being re-derived by each agent that reaches the question. The expected answer is NO, and the plan's value is that the NO is measured, written down, and fenced by a test, rather than assumed.

## Project conventions discovered (Step 0)

- Cite code by SYMBOL (`module.function`) or by a quoted content string, with a line number only appended to one of those and never alone: an offset expires before this plan executes (spec `ipd-structure-and-linting` Section 10.2; advisory `IPD-C801`). THIS PLAN CITES BY SYMBOL THROUGHOUT for that reason.
- A `- Readiness:` field is an OUTPUT of `/plan-review` and is deliberately ABSENT here; writing one while authoring would forge a review that has not happened, and the auto-approve predicate reads that field FIRST.
- NEVER WRITE ANOTHER ROLE'S ATTESTATION FIELD, which for this plan is not a background rule but the central hazard: the deliverable IS an attested ruling, so the one way to fail this plan badly is to write an approval nobody gave. E-04 therefore carries an explicit refusal branch, and the plan relies on the `llbr2b` precedent (F-10) where approving the artifact IS the attestation.
- A MAINTAINER RULING IS CITED AS `Gate-Kind: decision` WITH A `D<n>` REF into `DECISIONS.md` (`.aw/records/backlog/README.md`), which is why E-04 writes a numbered entry rather than recording the ruling only in this plan's history: a plan is a record of work, and the durable home for a policy is the decision log.
- THE REPOSITORY ALREADY CRITIQUES ITS OWN AUTHORITY TABLE, and that critique is load-bearing here rather than incidental. `TRANSITION_AUTHORITY`'s `human_token` is a historical duplicate of `by_human` that both consumers test with `or`, so the two are indistinguishable; `who` is read by no production code; and `requires_gate` is dead, with the `->deferred` gate enforced by a hardcoded branch instead. Three of its six fields are real. Copying that shape to backlog would import the dead weight along with it.
- `aw backlog set` FORKS ON WHETHER `--status` WAS PASSED, and the mapping is counterintuitive: `--status` ABSENT (the positional spelling) routes to the SHARED `status_set.run_set_command`, while `--status` PRESENT routes to the FORKED `backlog.run_set`. Every measurement and every test case in this plan must cover BOTH, because a property that holds on one spelling and not the other is the defect shape this area has already produced repeatedly.
