### Task group 2: make an unreadable prompt fail before it is asked

- [x] E-02 GIVE THE ANTI-JARGON RULE ITS MISSING POSITIVE HALF, so it cannot be satisfied by deleting nouns.
  THE EXACT DEFECT: kernel item 3 (`askme.md:42-43`) forbids an id6, a symbol name, a finding code, or internal vocabulary as a subject, and its only positive guidance is "Name the THING and what it does" with one good example. Measured: complying by SUBSTITUTION produced "a shipped pair of helpers" and "a 900-line run-state model", which passed the gate item (`askme.md:172`) and left the maintainer with nothing to picture. The rule removed the handle and left a void.
  THE OBLIGATION TO STATE: when you drop an internal name, replace it with what the thing DOES in the reader's terms, not with a placeholder. `t156g1`'s own contrast is the model to encode: "the retry code built for another part of the system" is compliance; "a shipped pair of helpers" is not. NAME THE ANTI-PATTERN EXPLICITLY so it is checkable: a noun phrase whose head is a generic container word (`a pair of helpers`, `a module`, `a mechanism`, `a component`) carrying no information about function is a VIOLATION, not compliance.
  ADD THE HONEST ESCAPE, because the rule as written can be impossible to satisfy: if a thing genuinely cannot be described functionally without its internal name, NAME IT AND EXPLAIN IT IN ONE CLAUSE. A named-and-explained thing is decidable; an anonymous one is not. Without this, the rule sometimes has no compliant option, which is how the void got produced.
  - Depends on: E-01
  - Expected outcome: kernel item 3 states the positive obligation, names the generic-container-word anti-pattern as a violation, and permits naming-plus-one-clause-explanation when functional description alone is impossible; the existing prohibition is not weakened.

  - Depends on: E-02

- [x] E-04 NAME THE INCOMPREHENSION CASE EXPLICITLY AS DISCARD-AND-RE-ASK, including when it arrives through the free-text option.
  THE FRAMING DEFECT: Step 3's rule (`askme.md:124-126`) lists "I have zero context here" and "what is X?" and correctly says the PROMPT was defective, but its subject is the human's missing context. `t156g1` finding 4 is that this is subtly wrong and probably why it was not reached for: the maintainer used the tool's WRITE-YOUR-OWN-ANSWER option to report incomprehension, which is not obviously covered by a rule about the human lacking context.
  THE RULE TO ADD: any answer REPORTING INCOMPREHENSION is a defective prompt, whatever channel it arrives on, INCLUDING a free-text answer. Note the distinction that makes this safe: a human who ANSWERS and separately complains has still answered; a human who reports not understanding has NOT answered, and recording their reply as a decision would be recording a non-answer as consent.
  DO NOT RECORD A DISCARDED ANSWER IN THE ARTIFACT, since Step 4 (`askme.md:128-137`) would otherwise write it as a resolution with the human named as the decider. That is the concrete harm: a rationale claiming the human decided something they said they could not understand.
  - Depends on: E-03
  - Expected outcome: Step 3 names incomprehension-through-any-channel (free-text included) as a defective prompt requiring discard-and-re-ask; states that a discarded answer is never recorded as a resolution; distinguishes an answer-plus-complaint from a non-answer.
