## Project conventions discovered (Step 0)

- Cite code by SYMBOL or by a quoted content string; a bare line offset expires before execution (spec `ipd-structure-and-linting` Section 10.2; advisory `IPD-C801`). Every citation in this plan names a symbol or quotes a string for that reason.
- SEVERITY HAS TWO CONTRACTS in this repository and conflating them is the mistake this plan exists to correct in one rule. The EXIT-CODE contract is `artifact_core.drift_exit_code`, whose body is "return 1 if any(getattr(d, "severity", "") != "info" for d in drift) else 0", so `info` is the ONLY non-failing tier. The LIFECYCLE-GATE contract is `work_cmd._validate_plan_via_engine`, which treats `warning` as a printed non-blocking advisory and whose docstring states the distinction under the heading "NOTE ON STAGED SEVERITY AND THE TWO-CONTRACTS DISTINCTION (IPD s7cu7n)". Pending plan `wm40yl` (Set `warnadvisory`, from backlog `1dvtiq`) is publishing this contract in `docs/cli-output-contract.md`; this plan does not duplicate that work and does not depend on it.
- SEVERITY IS STAMPED PER FINDING WHEN A RULE NEEDS A TIER ITS REGISTRY ENTRY CANNOT EXPRESS, and the established shape is `_core.Drift(..., severity=<tier>)`, preserved by `check_engine.enrich_drift` because it reads `severity=drift.severity or spec.severity`. In-tree users: `check_durable_carrier` (per-plan tier from `carrier_severity_for_plan`), the `check.collisions-not-checked` notice, and the `check.spec-criteria-uncovered` emitter. This plan follows that shape rather than adding a second registry entry or a second rule id.
- AN UNREGISTERED RULE ID FALLS BACK TO `_DEFAULT_RULESPEC`, measured severity `error`, so the failure direction for anything unclassified is deliberately strict. That is why E-02 leaves the registry entry at `error` and downgrades only in the evaluator.
- `aw check <type>` and `aw check all` DO NOT RUN THE SAME RULES. `check_types` runs the cross-tree full-sweep seam only in the `types == ["all"]` branch, and `check.scope-path-target-stale` rides that seam beside `check.from-spec-dangling` and `check.graduated-to-*`. A per-type run emits an `info`-severity `check.collisions-not-checked` notice naming the limit.
- A plan that changes behavior a spec describes SHOULD carry the spec amendment in the same change and MUST declare the `.spec.md` file in `- Scope-Paths:` (AGENTS.md). E-05 does both.
- Tests must exercise behavior and assert on real outputs; a test that reads production source text or counts symbols is forbidden (AGENTS.md "TEST OUTCOMES, NOT CODE STRUCTURE"; GUIDING_PRINCIPLES P16).
- Run the suite BARE as `python3 -m pytest`; do not add `-n0`, a second `-q`, or `-p no:randomly` (AGENTS.md "HOW TO RUN THE SUITE").
- This is a SHARED CHECKOUT. Whatever live findings E-01 re-derives will sit in OTHER AGENTS' pending plans; repairing them is not this plan's work and editing them would sweep another party's files into this plan's commit. Do not expect the plans authoring named: the population turned over completely in one day (F-01).
- A DASH CHECK MUST NOT BE WRITTEN AS `grep -P '[\x{2013}\x{2014}]'`. Added at review (F-14): that idiom is locale-dependent and under `LC_ALL=C` it exits 2 with a diagnostic on stderr and nothing on stdout, so "no output" reads as a pass over prose that does contain a dash. Use a decode-in-source probe (`python3 -c` matching `'\u2013'`/`'\u2014'`) and report its exit status.
