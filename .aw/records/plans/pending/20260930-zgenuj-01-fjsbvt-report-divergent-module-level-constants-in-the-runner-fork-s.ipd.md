## Goal

Make the runner fork scanner able to ENUMERATE the defect class its own docstring teaches, instead of
only explaining it. After this plan, a human doing a lift can ask the scanner "which module-level
constants disagree between the hosts?" and get a complete answer that does not depend on how much
`def`-level unification happens to remain, and the answer is computed by resolving values through the
trees the scanner already parsed, so it stays a pure static instrument that measures the tree it was
pointed at.

## Project conventions discovered (Step 0)

- Cite code by SYMBOL (`module.function`) or by a quoted content string, with a line number only appended to one of those and never alone: an offset expires before this plan executes (spec `ipd-structure-and-linting` Section 10.2; advisory `IPD-C801`).
- THE SCANNER IS A MEASURING INSTRUMENT, NOT A GATE, and its docstring states this as a contract: "Exit status is 0 whenever the scan completed; this is a MEASURING instrument and not a gate, so it does not fail on a count it dislikes. The gates that consume it live in the test suite." So this plan adds a REPORT and must not add a nonzero exit, and the enforcing guard for this defect class correctly lives in `tests/test_runner_shared.py` where `gjni4c` put it.
- THE SCANNER'S HEADLINE CONTRACT IS REPRODUCIBILITY ACROSS MACHINES AND TREES. Its docstring opens with it: the contract "is not 'a number' but 'the SAME number, next week, from a different machine, by a different agent'", and `package_dir` is deliberately "resolved rather than taken from the cwd so the scanner produces the same census whether it is run from the repository root, from a lane worktree, or by absolute path from elsewhere". That sentence is what rules out the `getattr` mechanism the backlog item prescribes (F-05).
- A NEW SECTION FOLLOWS AN ESTABLISHED SHAPE. `--triples` and `--repo-wide` are each an `action="store_true"` flag, each OR-ed with `args.all` at the `render` call, each a key on the `census` dict rather than a separate code path, and each carrying its own test string in the output. `census`' docstring states the reason: returned "as a plain dict so `--json` and the human report are provably the same numbers rather than two code paths that can drift".
- A SECTION THAT REPORTS A HAZARD MUST SAY IT IS NOT A VERDICT. `render_repo_wide` prints "READ, DO NOT COUNT: a NAME collision is not a re-fork", and the docstring records `tvnq50` as an executor who made exactly that error. The constants section needs the same caveat for the same reason: a host-varying constant is usually correct by design.
- TESTS EXERCISE BEHAVIOR AND NEVER PIN PRODUCTION SOURCE (`GUIDING_PRINCIPLES.md` P16, which names `ast.parse` and `read_text()` against `agent_workflows/*.py` explicitly). That is satisfiable here WITHOUT tension: the scanner is the code UNDER test, driven over fixture inputs, so the AST parsing is the behavior being exercised rather than an assertion about production source. Fixture modules are also the form the repository already carves out, since `76ic0k`'s guard excludes `tests/fixtures/` as "synthetic sample code, not this suite's assertions".
- THE SUITE RUNS BARE. `pyproject.toml` `addopts` already supplies `-q -n auto --dist=worksteal -m 'not slow and not livecorpus'`; `python3 -m pytest` with no added flags is the contract, and a second `-q` would suppress the `N passed` line this plan's validation requires.
