# Check R6: Decomposition and Splitting

Decide whether the plan is too large, multi-faceted, or broad for a single plan and should become a plan Set.

Guidelines:
- If the plan spans multiple distinct features, modules, or distinct deliverables that can be sequenced, evaluate decomposition into an Order 00 orchestrator and numbered child plans.
- A recommended split must record a proposed breakdown in the review record (proposed Set id, orchestrator scope, and child plan boundaries).
- A recommended split is an in-scope finding that forces review readiness to `no-go`.
- Until the automated split step exists (Order 06, Stage 2), the split is left for a human maintainer to execute (as spec `k3yx72` Section 10 item 1 already provides for approved plans).

Record notes in the review record's `### Step R6` subsection starting with `- Checked: <what was examined>`.
Record findings per `_findings.md` in the current round's single `### Findings` table.
