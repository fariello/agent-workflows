# Host adapters

An adapter maps a host's native features to the canonical roles and advertises a feature as
supported only where the capability registry promoted it. The modules are
`agent_workflows/host_adapters.py` and `host_capability_registry.py`.

## Roles a host must serve

- `router`: on-demand discovery and dispatch.
- `isolated_executor`: a subagent or fresh session.
- `noninteractive_runtime`: headless execution.
- `permission_gate`: consent and permission control.

`resolve_role_target` returns the host's native feature for a role, or the external
runtime-coordination fallback when the host has none (never silently absent).

## The support table (generated from the capability registry)

The support table is generated by `host_adapters.build_support_table`, wrapped with a
provenance line by `docs_render.render_support_table`. A feature shows `supported` only when a
live probe promoted it in the capability registry; every other cell shows `unverified`. The
table is deliberately not embedded as a static snapshot here, because a support claim is only
as fresh as its evidence record. Render the current table with:

```
python3 -c "from agent_workflows import host_adapters as h, host_capability_registry as r, docs_render as d; \
reg = r.HostCapabilityRegistry(); \
print(d.render_support_table({h_id: h.build_host_adapter(h_id, reg) for h_id in h.ALL_ADAPTER_HOSTS}))"
```

## Capability evidence and freshness

A capability is `supported` only with a proven positive probe (resolved, followed, side effect
verified) plus every required fail-closed negative probe. A record expires after its TTL
(default 90 days); an expired record renders as `unverified`, not `supported`. The nine negative
probe classes (missing skill, denied permission, no user input, path precedence, stale adapter,
malformed frontmatter, external path refusal, server auth, background result loss) each prove a
fail-closed behavior.

## Running a host probe

See the walkthrough [walkthroughs/host-probe.md](walkthroughs/host-probe.md). A probe runs in an
isolated fixture with an isolated HOME; it never touches the operator's real home directory.

## Responsibility boundary

The registry owns truth about support. The adapter reflects it. Documentation renders it. No
layer can assert support the registry did not prove.

## Limitations

- Support is per host and per exact version. A newer host version is not covered by an older
  version's evidence.
