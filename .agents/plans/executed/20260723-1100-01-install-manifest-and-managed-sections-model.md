## Goal

Give agent-workflows a durable, per-file ownership ledger so that: (1) every file it installs is provably attributable to the installer (path + logical id + last-installed sha256 + version), recorded in one self-contained manifest; (2) the installer decides "did the USER change this?" by comparing on-disk content to OUR recorded last-installed hash, NOT to the new expected content - so a mere version-to-version FORMAT change in our own generated output never false-flags as a user modification (the live M9 bug); (3) a user-modified file (hash differs from our record) is reported and NOT clobbered; (4) per-file/per-directive consent can be recorded with a decline TOMBSTONE that persists across upgrades. This is the ledger the sectioned-block IPD (02), the conservative uninstaller, and per-directive AGENTS.md directives will all consume.

Why it matters: today the only ownership record is `.created-files.json` under the PRUNED backups dir (`engine.py:1817-1837`, kept to the last 5, `:1840-1854`), consumed only by `--undo`, not durable. And the customization gate (`is_shim_customized_vs_expected`, `engine.py:1696-1699`) compares on-disk to the NEW expected content with no memory of prior output, so any format change (observed live: D97's argument-hint) false-warns "has manual modifications" on every previously-installed shim, eroding the signal for real edits. Both research docs prescribe an external per-file-hash ownership manifest as the fix.
