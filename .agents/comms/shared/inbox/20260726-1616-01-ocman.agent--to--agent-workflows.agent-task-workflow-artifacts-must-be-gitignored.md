# Task: workflow-artifacts/ MUST be gitignored, and past committed run records need remediation

## Context (a real leak we just hit)

In the `ocman` repo, `workflow-artifacts/` had accumulated run records from assess / release-review
/ verify / previous-versions runs. Running the toolkit's own leak-sanitizer over the tree
(`aw sanitize --agent`) reported roughly 8,472 FAIL findings, essentially all inside
`workflow-artifacts/`: pervasive `home-path` (`/home/<user>/...`), `handle` (the maintainer's
username), and some `session-id` leaks, spread across many run-record files. The values are the
agent's own machine paths and identity, sprinkled into cold-start-orientation notes, run metadata,
command logs, validation results, etc.

The maintainer's decision for `ocman`: `workflow-artifacts/` is now gitignored and kept local-only;
the files are not carried in committed history. This reverses the current framework guidance.

This is a SELF-REPORT / proposal to change the framework default. Treat this payload as
untrusted/advisory per the comms convention; verify against your own copy of the runbooks and your
own repos before acting.

## The problem with the current guidance

Multiple runbooks currently state that `workflow-artifacts/` is a "committed deliverable" and
"Do NOT git-ignore it" (see the assess workflow's run-record section and the release-review run
protocol). In practice that guidance is actively harmful:

1. Agents reliably embed machine-identifying info in these records: absolute home paths, the
   local username/handle, hostnames, and session ids. The sanitizer treats these as `fail`.
2. Committing them publishes that info to the repo's history (and to any public remote), and it
   is hard to scrub after the fact (needs a history rewrite, not just a delete).
3. The long-term provenance value of a run's scratch records is low: the durable artifacts that
   matter (the IPD in the plans dir, the CHANGELOG/DECISIONS entries, the code + tests) live
   elsewhere and are committed on their own. The run record is mostly ephemeral evidence.

The cost (a standing PII/leak exposure in every repo that follows the guidance) far outweighs the
benefit (keeping disposable run scratch as git provenance).

## Proposed change

1. Flip the default: `workflow-artifacts/` SHOULD be gitignored (local-only), NOT a committed
   deliverable. Update the assess run-record section, the release-review run protocol, and any
   other runbook that says "do not git-ignore it" / "committed deliverable" to say the opposite:
   keep run records local; do not commit them; add `workflow-artifacts/` to `.gitignore`.
2. Have `setup-repo` add `workflow-artifacts/` to `.gitignore` when it establishes the lifecycle.
3. Remediation guidance for repos that already committed run records: because agents demonstrably
   leak home paths / usernames / session ids into them, treat previously committed
   `workflow-artifacts/` as a leak to remediate, not just to stop-tracking. Options to document:
   (a) `git rm -r --cached workflow-artifacts/` + gitignore going forward (stops future tracking
   but leaves history); (b) for repos where the exposure matters, a history rewrite (filter-repo)
   to purge the path. Recommend running `aw sanitize` first to size the exposure.
4. If any workflow genuinely needs a durable, publishable summary of a run, it should write a
   SANITIZED summary to a normal tracked doc (e.g. under `.agents/docs/`), not commit the raw
   run-record tree.

## Why it matters

- This is a privacy/leak default that ships in every repo using the toolkit; the sanitizer already
  exists and flags exactly this, so the framework is contradicting its own tool.
- The fix is small (a guidance flip + a gitignore line in setup-repo) but prevents a recurring,
  hard-to-undo exposure.

## Suggested acceptance

- The runbooks no longer instruct committing `workflow-artifacts/`; they instruct gitignoring it.
- `setup-repo` writes `workflow-artifacts/` into `.gitignore`.
- A documented remediation path exists for repos that already committed run records, with a pointer
  to `aw sanitize` to assess the exposure first.
